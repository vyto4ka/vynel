## 0. Веб-панель

### Как открыть

Адрес, логин и пароль установщик печатает в итоговой таблице. Забыли — на сервере:

```bash
vynel admin web             # адрес панели и логин
vynel admin web password    # новый пароль (старые сессии разлогинятся)
vynel admin web password --login boss   # заодно сменить логин
```

Адрес выглядит как `https://nl.example.com/k9Qm2xT7aB3c/`. Последняя часть — **секретный путь**: панель отвечает только по нему, на всех остальных адресах домена открывается сайт-заглушка — один из пяти встроенных многостраничных сайтов (§11, `sub.decoy`). Поэтому адрес стоит хранить так же, как пароль. Сменить путь можно в «Настройки → Веб-панель» (или `vynel admin setting web.path /новый-путь/`).

> Если домена нет (например, тестовая установка), панель доступна только с самого сервера: `ssh -L 2097:127.0.0.1:2097 root@сервер`, затем `http://127.0.0.1:2097/<секретный путь>/` у себя в браузере.

### Разделы

Меню слева (его можно свернуть кнопкой «Свернуть»; на телефоне оно открывается кнопкой ☰):

| Раздел | Что там |
|--------|---------|
| **Дашборд** | Три вкладки (§7). «Сводка»: пользователи, онлайн, трафик за сегодня и 30 дней, график по дням, состояние нод, топ по трафику. «Подключения»: графики трафика, онлайна, нод, пользователей и приложений за период. «Серверы»: нагрузка каждой ноды — процессор, steal, память в гигабайтах, канал |
| **Аналитика** | Трафик по профилям и каскадам — всего и у каждого пользователя, все устройства (HWID) всех пользователей, все IP-адреса, с которых подключались (§7.1) |
| **Пользователи** | Список с фильтрами и поиском. «+ Пользователь» — создать (достаточно имени). Клик по строке — карточка: ссылка подписки с QR, продление в один клик (+1/3/6/12 мес), отключение, сброс трафика, новая ссылка, устройства, график, ссылки по серверам. «Изменить» — срок, лимиты, группы, заметка |
| **Группы** | Какие серверы видят участники группы. «+ дать доступ…» — профиль (на всех нодах), нода целиком или один инбаунд |
| **Подписка** | Как подписка выглядит в приложениях и в браузере: название, объявление, страница, кнопки приложений, HTTP-заголовки, проверка ответа (§5) |
| **Шаблоны** | Наборы настроек для новых пользователей: срок, лимит трафика, устройства, группы. Один из них — по умолчанию |
| **Ноды** | Серверы: состояние, CPU/RAM, онлайн, трафик, проблемы. «+ Нода» выдаёт токен и команду для нового сервера. У инбаундов — включение, точка подключения (как сервер выглядит в приложении), конфиг, новые ключи Reality |
| **Профили** | Общие настройки VLESS (Reality self-steal или XHTTP через VK CDN). Изменение профиля применяется на всех нодах |
| **Биллинг** | Провайдеры серверов (сайт, вход в кабинет, иконка), стоимость нод, даты оплаты с напоминанием в Telegram, лимит трафика провайдера с автовыключением ноды (§9.1) |
| **Настройки** | Скрытие, адреса и роли IP с проверкой DNS, доступ к панели (путь, домен, порт, IP, заглушка), подписки, устройства (HWID), сертификаты, адрес для нод (§11) |
| **Telegram** | Бот: токен, привязка админов, расписание бэкапов, уведомления о нодах, «Скачать бэкап» (§13, §14) |
| **Журнал** | Кто, что и когда менял — из веба, терминала или сама система |
| **Аккаунт** | Сменить логин и пароль, сессии (где выполнен вход, завершить), как входить в панель (ниже) |

Изменения применяются на нодах за секунды, перезапускать ничего не нужно.

### Безопасность входа

- Пароль генерируется при установке (16 символов) и хранится в виде bcrypt-хэша.
- Сессия живёт 14 дней. Cookie привязана к секретному пути, с флагами `Secure`, `HttpOnly`, `SameSite=Strict`.
- **Сессии хранятся на сервере.** «Аккаунт» → «Сессии» (или `/sessions` в боте) показывает, где выполнен вход: браузер, IP, способ входа, последняя активность. Любую можно завершить, «Завершить остальные» оставит только этот браузер.
- **Сессия заканчивается сама:**
  - через 5 минут без действий (клики, клавиши, прокрутка). Открытая страница, которая сама обновляет данные, действием не считается. Настройка «Выход после бездействия, мин» (`web.idle_minutes`), 0 — не завершать;
  - сразу, если запрос пришёл с другого IP: украденная cookie не сработает. Если IP меняется сам (мобильный интернет, IPv4/IPv6), выключите «Завершать сессию при смене IP» (`web.bind_ip`);
  - когда вкладку закрыли. Обновление страницы сессию не завершает.

  На экране входа написано, почему пришлось войти заново.
- **О каждом входе пишет бот** — с кнопкой «Завершить эту сессию». Когда сессия заканчивается (выход, бездействие, другой IP, закрытая вкладка), бот удаляет это сообщение.
- Смена пароля или логина завершает все остальные сессии.
- **Подбор пароля закрывается по адресу.** После 5 неудачных попыток за 15 минут (пароль, ссылка из бота или Mini App) вход с этого IP закрыт на минуту, при повторе — на 2, 4… до часа. Успешный вход снимает счёт. Бот сообщает о каждом закрытом адресе, событие пишется в «Журнал» (`web.login_blocked`). Другие адреса, в том числе ваш, входят как обычно: поток мусорных попыток не задерживает правильный вход.
- Неудачные входы пишутся в лог: `journalctl -u vynel | grep "login failed"`.

### Как входить: режимы входа

Режим выбирается в «Аккаунт» → «Как входить в панель», на сервере — `vynel admin web mode РЕЖИМ`, при установке — вопрос установщика (флаги `--login-mode`, `--session-paths`). Настройка `web.login_mode`.

| Режим | Как войти |
|-------|-----------|
| **Логин и пароль** (`password`, по умолчанию) | Форма логина. Ссылки из бота и Telegram Mini App тоже работают |
| **Только по ссылке** (`link`) | Пароля нет, подбирать нечего. Одноразовая ссылка на минуту: `/login` в боте или `vynel admin login-link` на сервере, а также кнопка «Панель» в боте (Mini App) |
| **Только Telegram** (`miniapp`) | Только кнопка «Панель» в боте. Вход из браузера и по ссылкам выключен. Нужен подключённый бот |

**Случайный адрес на каждую сессию** (только в режиме «по ссылке», `web.session_paths`, `vynel admin web mode link --session-paths`). У панели нет постоянного адреса: каждая ссылка входа открывает свой случайный путь, и сессия работает только на нём. Всё остальное на домене панели — сайт-заглушка.

Вернуть пароль с сервера: `vynel admin web mode password`.

## 1. Понятия

```
Шаблон (встроен)  ──►  Профиль (общие настройки)  ──►  Инбаунд ноды (VLESS_NL, VLESS_DE…)
                                                              ▲
Пользователь ──► Группы ──── правила доступа ─────────────────┘
       │
       └─► Подписка: одна ссылка → все серверы, доступные через группы
```

| Понятие | Что это | Пример |
|---------|---------|--------|
| **Нода** | Сервер, на котором работает VPN (Xray + nginx). У all-in-one нода живёт на сервере панели | `NL` — Нидерланды, `nl.example.com` |
| **Шаблон профиля** | Готовая схема подключения: встроенная или своя, добавленная в веб-панели | `vless-reality-selfsteal`, `vless-xhttp-reality` |
| **Профиль** | Твои общие настройки на основе шаблона: порт, параметры, шаблон имени | «Reality» |
| **Инбаунд ноды** | Профиль, применённый к конкретной ноде, со своими ключами и тегом. Создаётся командой `inbound attach` | `VLESS_NL`, `VLESS_DE` |
| **Группа** | Набор правил «к чему есть доступ»: весь профиль, вся нода или конкретный инбаунд | «Основная» → весь профиль «Reality» |
| **Шаблон пользователя** | Что получает новый пользователь: срок, группы, лимиты | «Стандарт»: +3 месяца, «Основная» |
| **Пользователь** | Человек с одной ссылкой подписки | `vasya` |
| **Точка подключения** | Как сервер выглядит в приложении: название, адрес, SNI. Вычисляется сама | «🇳🇱 Нидерланды» |

Связь с Remnawave: профиль + инбаунд ноды ≈ Config Profile, группа ≈ Internal Squad, точка подключения ≈ Host.

## 2. Пользователи

```bash
vynel admin user add vasya                      # срок, группы и лимиты берутся из шаблона по умолчанию
vynel admin user add petya --template Пробный   # из другого шаблона
vynel admin user add katya --group Основная --group Тест   # свои группы вместо групп шаблона
vynel admin user add vasya --link vasya-phone-2026   # своя ссылка: https://домен/s/vasya-phone-2026
vynel admin user link vasya vasya-laptop-01     # сменить ссылку (старая перестанет работать)

vynel admin user list                           # все; --status active|limited|expired|disabled, --search вас
vynel admin user show vasya                     # статус, срок, трафик по нодам, ссылка подписки

vynel admin user extend vasya --months 1        # продлить; считается от даты окончания, если она ещё не прошла
vynel admin user extend vasya --days 7
vynel admin user disable vasya                  # отключить (сразу пропадает со всех нод)
vynel admin user enable vasya
vynel admin user reset vasya                    # обнулить трафик за период
vynel admin user groups vasya --group Основная  # заменить группы
vynel admin user reissue vasya                  # новая ссылка подписки (старая перестаёт работать)
vynel admin user reissue vasya --uuid           # новый ключ VLESS (если ключ утёк)
vynel admin user rm vasya                       # удалить
```

**Статусы:** `active` — работает; `expired` — истёк срок; `limited` — кончился трафик; `disabled` — отключён вручную. Неактивный пользователь удаляется со всех нод за секунды. Вместо серверов он получает в приложении «⛔ причину».

**Сброс трафика** — по шаблону: `month` (1-го числа), `week` (в понедельник), `day` или `no`.

**Своя ссылка подписки.** По умолчанию конец ссылки случайный, 43 символа, и подобрать его нельзя. Свой задаётся при создании пользователя (поле «Ссылка подписки») или позже в карточке («Своя ссылка»). Требования: 8–64 символа, латиница, цифры, `_` и `-`. Короткие слова легко угадать: перебор банится, но длиннее — надёжнее. Начало ссылки (`/s/`) меняется в «Настройки» → «Подписки» → «Путь подписок» или при установке.

## 3. Группы

Группа решает, **к каким серверам** у пользователя есть доступ. При установке создаётся группа «Основная» с доступом «всё»: все серверы и все каскады, в том числе добавленные потом. Новая нода, новый профиль или каскад сразу становятся доступны всем в группе. Обновление панели даёт этот доступ существующей группе «Основная»; чтобы ограничить её, уберите «всё» и дайте доступ к нужным профилям.

```bash
vynel admin group list                               # группы и их правила
vynel admin group add Тест
vynel admin group grant Тест inbound VLESS_DE        # доступ к одному инбаунду
vynel admin group grant Тест node DE                 # ко всем инбаундам ноды DE
vynel admin group grant Тест profile Reality         # ко всему профилю на всех нодах, включая будущие
vynel admin group grant Тест all -                   # ко всему: все серверы и каскады, и будущие тоже
vynel admin group revoke Тест node DE
```

У пользователя может быть несколько групп. Его доступ — объединение доступов всех его групп.

## 4. Шаблоны пользователей

Шаблон — это то, что получает новый пользователь, если указать только имя.

```bash
vynel admin template list
vynel admin template add Пробный --days 3 --limit-gb 5 --reset no --group Основная
vynel admin template add Год --months 12 --group Основная --default   # сделать шаблоном по умолчанию
```

Изменение шаблона не затрагивает уже созданных пользователей: значения копируются в момент создания.

## 5. Подписки и приложения

Ссылка подписки выглядит как `https://<домен>/s/<токен>`. Её показывают карточка пользователя в панели и `vynel admin user show`. Формат ответа выбирается сам:

| Кто запрашивает | Что получает |
|-----------------|--------------|
| **KeqDroid** | Xray JSON: полный конфиг на каждый сервер, с маршрутами и DNS (§5.1) |
| Другие приложения на ядре Xray | Список ссылок `vless://`, `hysteria2://` (base64) |
| Приложения на ядре Mihomo (Clash Meta) | Профиль Mihomo (YAML) |
| Приложения на ядре sing-box | Профиль sing-box (JSON) |
| Браузер | Страница: срок, трафик, QR-код, кнопки «добавить в приложение» |

Формат можно указать явно, добавив его в конец ссылки: `…/s/<токен>/clash`, `/singbox`, `/json` (Xray JSON), `/base64`. Или выбрать у пользователя («Изменить» → «Формат подписки»).

- **Безопасность.** Неверный токен или любой другой путь открывает 404 сайта-заглушки. IP, который перебирает токены, банится на час: с него перестают открываться короткие свои ссылки (до 32 символов). Длинные ссылки, в том числе случайные, работают и с такого IP: подобрать их нельзя, а за одним адресом бывает много людей (NAT оператора). Адреса своих нод не банятся никогда: через туннель все приложения обновляют подписку с них.
- **Утечка ссылки.** Кнопка «Новая ссылка» в карточке (или `vynel admin user reissue vasya`) выдаст новую, старая перестанет работать.
- **Ссылки без подписки.** Внизу карточки пользователя — `vless://` по каждому серверу; в терминале `vynel admin user links vasya`.

### KeqDroid

[KeqDroid](https://github.com/Lemonochka/keqdroid) — клиент для Android, Windows и Linux на Xray/sing-box/Mihomo. По User-Agent `keqdroid/…` он получает Xray JSON — полный конфиг каждого сервера вместе с маршрутами и DNS (§5.1); такие серверы KeqDroid показывает как обычные, а не «кастомные». Правило из старой версии, где KeqDroid получал ссылки, переключается само, если его не меняли. Он передаёт HWID (`x-hwid`, модель и ОС устройства), так что лимит устройств работает. Ещё он читает название, трафик, объявление, ссылку поддержки и «открыть в браузере». На странице подписки KeqDroid стоит первым с пометкой «рекомендуем»; кнопка открывает `keqdroid://install-config?url=<ссылка>`.

### Как выглядит подписка: раздел «Подписка» в панели

Все правки видны в предпросмотре справа ещё до сохранения. Приложения получают изменения при следующем обновлении подписки.

| Вкладка | Что настраивается |
|---------|-------------------|
| **Основное** | Название подписки в приложениях, как часто обновлять, ссылка на поддержку, **объявление** (строка вверху KeqDroid и плашка на странице) и его ссылка, страница «открыть в браузере» |
| **Страница** | Заголовок, описание, тема (тёмная, светлая, как в системе), акцентный цвет, QR-код, блок со статусом и трафиком, инструкция, подвал. В тексте можно использовать переменные: `{username}`, `{expire_date}`, `{days_left}`… |
| **Приложения** | Кнопки «Добавить в …»: включить или выключить, порядок (первая — «рекомендуем»), своя ссылка, где скачать, платформы. Телефон сначала видит приложения для своей системы. Готовые кнопки для популярных приложений (первая — KeqDroid) и свои |
| **Заголовки** | HTTP-заголовки ответа, которые читают приложения (ниже) |
| **Маршруты** | Что идёт мимо туннеля и через какой DNS (§5.1) |
| **Клиенты** | Какое приложение что получает. Приложение узнаётся по User-Agent (сверху вниз, первое совпадение); у каждого — переключатель «что отдавать»: ссылки, Xray JSON, Mihomo, sing-box или страница (например, KeqDroid можно переключить с Xray JSON на ссылки). Для Mihomo, sing-box и Xray JSON можно вставить свой шаблон конфига — §5.5. Формат в конце ссылки и выбранный у пользователя важнее этого списка |
| **Проверка** | Что получит конкретное приложение (User-Agent) для конкретного пользователя: формат и все заголовки. Устройство при этом не регистрируется |

### 5.1 Маршруты в приложениях

Вкладка «Подписка» → «Маршруты». Маршруты уходят вместе с серверами в форматах, где они есть: Xray JSON (KeqDroid, Happ, v2RayTun), Clash / Mihomo и sing-box. В ссылках `vless://` маршрутов нет.

| Настройка | По умолчанию | Что делает |
|-----------|--------------|------------|
| **RU напрямую** | вкл. | Российские сайты (`geosite:category-ru`, `.ru`, `.su`, `.рф`) и адреса (`geoip:ru`) идут с устройства сразу, мимо туннеля |
| **DNS для прямых сайтов** | `localhost`, `77.88.8.8` | Чем разрешать имена, которые идут напрямую: DNS устройства и Яндекс |
| **DNS через туннель** | DoH `1.1.1.1`, `8.8.8.8` | Чем разрешать всё остальное; запросы идут через сервер |
| **Торренты** | напрямую | Напрямую, блок или через туннель (Mihomo торренты не распознаёт) |
| **Реклама** | выкл. | `geosite:category-ads-all` в блок |
| **Свои списки** | пусто | «Всегда напрямую», «Всегда через туннель» (важнее RU), «Блокировать»: `domain:`, `full:`, `keyword:`, `regexp:`, `geosite:`, `geoip:`, `process:`, IP или подсеть |

Локальные адреса (`geoip:private`) всегда идут напрямую. Последнее правило отправляет всё остальное в туннель.

**Приложения целиком (`process:`).** Запись `process:имя` направляет весь трафик приложения, в том числе соединения без имени сайта: например, матчи онлайн-игр идут прямо на IP серверов, и правила по доменам их не ловят. Имя — файл программы на ПК (`process:FortniteClient-Win64-Shipping.exe`) или пакет на Android (`process:com.example.app`), без пути; регистр как в диспетчере задач. В подписке это `PROCESS-NAME` в Mihomo, `process_name` в sing-box и `process` в Xray JSON. Приложение должно работать в режиме TUN (системный прокси видит не все программы). Xray понимает `process` с версии 26.1.23: более старое ядро не примет конфиг целиком, поэтому проверьте версию ядра в KeqDroid. В ссылках (base64) маршрутов нет.

Пример: Epic Games и Fortnite напрямую, на ПК.
```
geosite:epicgames
process:FortniteClient-Win64-Shipping.exe
process:FortniteClient-Win64-Shipping_EAC.exe
process:FortniteClient-Win64-Shipping_BE.exe
process:FortniteLauncher.exe
process:EasyAntiCheat_EOS.exe
process:EpicGamesLauncher.exe
process:EpicWebHelper.exe
process:UnrealCEFSubProcess.exe
process:EOSOverlayRenderer-Win64-Shipping.exe
```

**Кастомный профиль клиента.** У профиля («Профили» → «Изменить» → вкладка «Клиент») можно включить свой клиентский конфиг для его серверов:
- **Настройки** — те же поля, что во вкладке «Маршруты», но только для этого профиля;
- **Конфиг JSON** — целый конфиг клиента Xray. Outbound с тегом `proxy` заменяется сервером (если его нет — сервер встаёт первым), `remarks` — названием сервера.

Это действует в Xray JSON, где у каждого сервера свой конфиг. Mihomo и sing-box получают один файл на все серверы и берут маршруты из вкладки «Маршруты».

**Фрагментация ClientHello.** Некоторые операторы обрывают соединения на TCP 443 по началу TLS-рукопожатия (ClientHello). Переключатель «Фрагментация ClientHello» внизу вкладки «Маршруты» заставляет приложение отправлять ClientHello маленькими кусками с паузами (`streamSettings.finalmask`, тип `fragment` в Xray 26):
- **Пакеты** — `tlshello` (только ClientHello) или диапазон первых пакетов, например `1-3`;
- **Длина куска** — байты на кусок, число или диапазон (`10-20`);
- **Пауза** — миллисекунды между кусками (`10-20`, `0` — без пауз).

Настройка уходит только в Xray JSON (KeqDroid, Happ, v2RayTun) и ко всем серверам, кроме Hysteria2: он работает по UDP, и его это не касается. Ссылки vless://, Mihomo и sing-box такую настройку передать не могут. Приложению нужно ядро Xray 26; старое настройку просто пропустит.

Для отдельного сервера свою маску задают в «Ноды» → инбаунд → «Точка подключения» → **Final Mask**: JSON-объект с `tcp`, `udp` и `quicParams`, как в Xray. Кнопка «Вставить фрагментацию ClientHello» подставляет готовый вариант. Своя маска заменяет переключатель для этого сервера. В примерах из интернета пауза иногда называется `interval`; в Xray она называется `delay`, и панель подскажет об этом.

### 5.2 Каскады

Каскад — сервер, где приложение подключается к одной ноде (вход), а трафик выходит в интернет через другую (выход). Например, вход в Финляндии, выход в Германии: для пользователя это отдельный сервер «🇫🇮 Финляндия → 🇩🇪 Германия» в подписке.

Создать: «Профили» → «Каскады» → «Каскад»: инбаунд входа (нода 1), инбаунд выхода (нода 2); название в панели (пусто — «Нода входа → Нода выхода») и название в приложениях (пусто — «флаг вход → флаг выход»). Новых портов не нужно:
- на инбаунде входа у пользователя появляется свой ключ (UUID, выведенный из его UUID — после «Сменить UUID» меняется и он);
- по этому ключу нода входа отправляет трафик на выход: исходящее подключение к точке подключения выхода со служебным ключом, правило стоит первым в маршрутизации ноды;
- на выходе служебный ключ ноды входа добавляется как обычный пользователь.

Трафик и адреса каскада засчитываются пользователю (лимит трафика и лимит IP работают как обычно). Кому выдать — §5.4.

Каскад попадает в подписку, только если включены он сам, оба инбаунда и обе ноды и у обоих инбаундов есть точка подключения. Иначе его нет ни в подписках, ни на нодах, а в списке каскадов и в карточке пользователя написано почему. Вход по XHTTP не получают приложения на sing-box, а Mihomo — только если профиль это разрешает.

### 5.3 Внешние подписки

Чужая подписка — подписка друга, другой панели или вашей же на другом пользователе. Её серверы встают в подписку под основными у тех, кому она выдана (§5.4). Источник — ссылка на подписку (`https://…`, как её добавляют в приложение) или сами ссылки серверов (`vless://`, `hysteria2://`…, по одной в строке).

Где добавить:
- в карточке пользователя: «Каскады и подписки» → «Вставить подписку или ссылки» — сразу выдаётся ему, можно со сроком;
- в шаблоне пользователя: «Каскады и подписки» — её получает каждый новый пользователь из шаблона;
- «Подписка» → «Внешние» → «Подписка» — общий список; выдать оттуда — группе или пользователю.

Название можно не писать: оно берётся из адреса подписки или из имени первого сервера.

- Панель скачивает подписку как приложение (ссылки в base64 или текстом): сразу при добавлении, затем раз в 30 минут, а ещё когда приложение пользователя обновляет подписку и копии больше минуты (ждёт до 6 секунд, иначе отдаёт прежнюю копию). Кнопка ↻ — сейчас. Если источник недоступен, остаётся последняя удачная копия, а ошибка видна в списке.
- VLESS (raw/XHTTP) и Hysteria2 уходят во все форматы, включая Xray JSON с маршрутами и Mihomo. Остальное (vmess, trojan, ss, ws, grpc…) передаётся как есть и только в формате ссылок.
- Ссылка на подписку этой же панели читается напрямую, без HTTP, вместе с тем, что подписано у того пользователя.
- Подписка в подписке: панель, которая подтягивает чужую подписку, пишет в запросе глубину (`X-Vynel-Depth`). Другая vynel на такой запрос отдаёт и свои внешние подписки, пока глубина меньше трёх; дальше — только свои серверы. Две панели, подписанные друг на друга, останавливаются, а повторяющиеся серверы в подписке встречаются один раз.

### 5.4 Кому выдать: группа или пользователь со своим сроком

Каскады и внешние подписки выдаются:
- **группе** — «Группы» → «+ каскад или подписка…»: есть у всех в группе, пока они в ней;
- **пользователю** — в его карточке, блок «Каскады и подписки»: выбрать, при желании поставить дату «до» и «Выдать». После этой даты пропадает из подписки и с нод (пусто — пока действует подписка пользователя). Повторная выдача меняет дату.

Если одно и то же пришло и от группы, и лично, в подписке оно один раз; действует более поздний срок. Один и тот же сервер из разных источников тоже попадает в подписку один раз.

### Заголовки

По умолчанию отправляются:

| Заголовок | Значение | Что делает | Кто читает |
|-----------|----------|------------|------------|
| `Subscription-Userinfo` | `upload={upload}; download={download}; total={total}; expire={expire}` | Трафик и срок в приложении | все |
| `Profile-Title` | `{title}`, base64 | Название подписки | KeqDroid и большинство приложений |
| `Profile-Update-Interval` | `{update_hours}` | Автообновление, часов | все |
| `Support-Url` | `{support_url}` | Кнопка «поддержка» | KeqDroid и большинство приложений |
| `Profile-Web-Page-Url` | `{page_url}` | «Открыть в браузере» | KeqDroid и большинство приложений |
| `Announce` | `{announce}`, base64 | Объявление | KeqDroid и большинство приложений |
| `Announce-Url` | `{announce_url}` | Ссылка объявления | часть приложений |
| `Content-Disposition` | `attachment; filename*=UTF-8''{title_url}` | Имя профиля | только Clash-клиенты |

Правила:

- **Пустое значение.** Если значение после подстановки пустое (например, поддержка не задана), заголовок не отправляется.
- **base64.** Включайте для русского текста и эмодзи: так значение уходит как `base64:…`, как требует KeqDroid.
- **«Каким приложениям».** Это регулярное выражение по User-Agent, например `(?i)keqdroid`. Пусто — всем.

**Каталог** («Из каталога») — заголовки отдельных приложений, которые включаются по необходимости:
- `Hide-Settings` — скрыть настройки серверов;
- `Routing` и `Routing-Enable` — маршрутизация;
- `Notification-Subs-Expire`, `Sub-Expire` и `Sub-Expire-Button-Link` — напоминания об окончании;
- `Sub-Info-*` — информационная плашка;
- `Subscription-Always-Hwid-Enable`;
- `Ping-Type`;
- `Subscription-Autoconnect`;
- `Color-Profile`;
- `Fallback-Url` и `New-Url` — переезд подписки;
- `Socks-Auth-Mode`;
- `Per-App-Proxy-*` — раздельное туннелирование;
- `ProviderID`;
- `Update-Always` — обновлять подписку при каждом открытии приложения.

Часть заголовков работает только с ProviderID из кабинета разработчика приложения. Точные значения — в документации приложения. Можно добавить и любой свой заголовок. «Вернуть по умолчанию» сбрасывает список.

**Переменные** в значениях и ссылках приложений (полный список с примерами — во вкладке «Заголовки»):
- `{title}`, `{username}`, `{status}`;
- `{upload}`, `{download}`, `{total}`, `{used}`, `{limit}`;
- `{expire}`, `{expire_date}`, `{days_left}`;
- `{update_hours}`, `{support_url}`, `{announce}`, `{announce_url}`;
- `{sub_url}`, `{page_url}`, `{url}`, `{url_enc}`, `{url_b64}`, `{title_url}`.


### 5.5 Свой шаблон для приложения

«Подписка» → «Клиенты» → приложение → «Свой шаблон». Сюда вставляется готовый конфиг для формата приложения: Mihomo YAML, sing-box JSON или Xray JSON — например, шаблон из Remnawave, он понимается как есть. Панель вставляет в него серверы подписки:
- **Mihomo** — серверы встают в `proxies` после своих, а их имена — во все `proxy-groups` после своих элементов. Группа с `remnawave: {include-proxies: false}` их не получает, с `select-random-proxy: true` — один случайный, с `shuffle-proxies-order: true` — в случайном порядке. `proxy-providers` с `remnawave: {include-proxies: true}` получают их в `payload`;
- **sing-box** — серверы встают в `outbounds`, их получают все `selector` и `urltest` (кроме тех, где `remnawave: {includeProxies: false}`);
- **Xray JSON** — на каждый сервер свой конфиг: сервер встаёт вместо outbound с тегом `proxy` (или первым).

Ключи `remnawave` из ответа убираются. Шаблон проверяется при сохранении: ошибка YAML или JSON называет строку. «Разобрать шаблон» показывает, что в нём, а «Перенести во вкладку „Маршруты“» переносит правила, у которых есть поле (домены, geosite/geoip, IP, `process:`, RU, реклама, DNS), — их получат остальные приложения. Шаблон отдаётся, только когда формат ответа совпадает с выбранным у клиента: ссылка `/s/токен/json` для FlClashX получит обычный Xray JSON.

## 6. Устройства (HWID)

Приложения вроде KeqDroid передают идентификатор устройства. vynel запоминает устройства и может ограничить их число. По умолчанию лимита устройств нет: одновременные подключения ограничивает лимит IP (§6.1).

```bash
vynel admin user devices vasya          # список: модель, ОС, когда последний раз обновлял подписку
vynel admin user devices vasya --rm 3   # освободить место
vynel admin setting hwid.default_limit 5      # лимит по умолчанию (0 = без лимита, так и стоит)
vynel admin setting hwid.allow_missing true   # пускать приложения без HWID
vynel admin setting hwid.enabled false        # выключить HWID совсем
```

**Приложения без HWID.** Если лимита устройств нет (0 — общий или у пользователя), приложение без HWID пускается без учёта устройства и получает серверы ссылками (`vless://`, `hysteria2://`) — их понимает любое приложение — с обычными заголовками подписки: название, трафик, срок, объявление. Формат, заданный в ссылке (`/s/токен/mihomo`) или у пользователя, по-прежнему важнее. Приложения с HWID получают свой формат как раньше. Если лимит задан, приложение без HWID получает сервер-заглушку с объяснением, пока не включена галочка `hwid.allow_missing`.

**Отключить HWID одному пользователю.** В его карточке, в блоке «Устройства (HWID)», выключите «Проверять HWID». Подписка будет выдаваться любому приложению без учёта устройств. Остальные пользователи остаются под общими правилами.

**Приложения на ядре sing-box.** Некоторые из них передают HWID, только если в настройках профиля подписки включить **X-HWID**; после этого обновите подписку. Такие приложения получают подписку без XHTTP-серверов: в sing-box XHTTP нет, а Reality и Hysteria2 работают.

В ответе подписки, как у Remnawave, есть заголовки `x-hwid-active`, `x-hwid-not-supported` (приложение не прислало HWID) и `x-hwid-max-devices-reached`. По ним некоторые приложения сами включают отправку HWID.

Ограничение HWID работает только на выдачу подписки. Скопированную `vless://` ссылку оно не остановит — для этого есть лимит IP (§6.1) и `vynel admin user reissue vasya --uuid`.

### 6.1 Лимит IP одновременно

Со скольких адресов пользователь может быть подключён сразу — ко всем серверам вместе. По умолчанию **3**; свой лимит — в карточке пользователя («Изменить» → «Лимит IP одновременно», 0 — без лимита), общий — в «Настройки» → «Устройства» или `vynel admin setting ip.default_limit 3`.

Как работает:
1. Каждая нода раз в 5 секунд сообщает панели, кто подключён и с каких адресов. Xray знает это точно: адрес есть в списке, пока у него открыто соединение.
2. Панель складывает адреса со всех нод. Первые N адресов занимают места; место держится ещё 30 секунд после того, как адрес пропал, — короткий обрыв на телефоне его не отнимет.
3. Лишний адрес блокируется на всех нодах: его новые соединения уходят в blackhole, открытые закрываются. Остальные адреса пользователя работают как работали. Когда место освобождается, адрес пускается сам.
4. Подписка с заблокированного адреса (первый раз она выдаётся как обычно) вместо серверов показывает «⛔ Превышен лимит подключений: 4/3 — отключите лишние устройства» и отдаёт заголовок `x-hwid-max-devices-reached: true` — тот же, что при лимите устройств, так что приложению не нужен новый заголовок.
5. Админам в Telegram приходит сообщение (не чаще раза в несколько часов на пользователя). В карточке пользователя в строке «Адреса сразу» видно, какие адреса заняли место (⛔ — заблокированы, … — ещё проверяются).

Чтобы не мешать честным пользователям:
- **Пинг серверов** (KeqDroid и другие приложения проверяют все серверы сразу, часть может быть недоступна) — это один адрес, сколько бы серверов он ни трогал. Короткие подключения, которые живут меньше пары замеров (около 8 секунд), места не занимают и не блокируются.
- **IPv4 и IPv6** считаются отдельно, а IPv6 — сетью /64: телефон с двумя адресами не считается двумя устройствами.
- **Адреса своих нод** не считаются: приложение может проверять серверы через уже включённый туннель.

Заблокированный адрес — это адрес плюс пользователь: другой пользователь с того же адреса (общий NAT у мобильного оператора) не затрагивается.

## 7. Дашборд и статистика

Раздел **«Дашборд»**, три вкладки: «Сводка» (открывается сразу), «Подключения» и «Серверы».

**Подключения.** Сверху выбирается период: 24 часа, 7, 30 или 90 дней. Выбор запоминается.

- **Плитки:** трафик и активные пользователи за период со сравнением с прошлым периодом, онлайн сейчас и пик, средний трафик на активного.
- **Трафик:** по часам (сутки, неделя) или по дням, скачано и отдано. Наведите курсор, чтобы увидеть точные значения.
- **Онлайн:** хранится 7 дней, поэтому для 30 и 90 дней показывается последняя неделя по часам. У каждой ноды свой цвет, одинаковый на всех графиках.
- **Трафик по нодам, топ пользователей:** клик ведёт в раздел нод или в карточку пользователя.
- **«Когда пользуются»:** тепловая карта трафика за неделю, по дням недели и часам, в часовом поясе из настроек Telegram.
- **Пользователи по состоянию, приложения** (по последнему обновлению подписки), **платформы устройств** (по HWID).

Трафик пользователей хранится 90 дней по дням и 7 дней по часам, трафик нод — 90 дней.

**Серверы.** Нагрузка каждой ноды за 24 часа, 7, 30 или 90 дней: процессор (среднее и пики), steal, оперативная память в гигабайтах из общего объёма, входящий и исходящий канал в Мбит/с. Steal — время процессора, которое хостер отдал другим виртуальным машинам на том же железе: если он постоянно выше нескольких процентов, сервер «тормозит» не из-за вас, это повод сменить тариф или хостера. Нода присылает замеры каждые 10 секунд; панель раз в минуту сворачивает их в средние за 5 минут и хранит их 90 дней. Вкладка обновляется раз в 5 минут: она для общей картины во времени, текущее состояние — в разделе «Ноды».

```bash
vynel admin stats            # пользователи по статусам, онлайн, трафик за день и 30 дней, топ-10
vynel admin node list        # по нодам: состояние, CPU, RAM, онлайн, трафик за сегодня, проблемы
vynel admin user show vasya  # трафик пользователя по нодам за 30 дней
vynel admin audit            # кто и что менял
```

Нода собирает счётчики каждые 10 секунд. Пока панель недоступна, данные копятся на ноде и потом доходят без потерь.

### 7.1 Аналитика

Раздел **«Аналитика»** — подробности, которых нет на дашборде. Три вкладки:

- **По профилям.** Сколько трафика ушло через каждый профиль (все его ноды вместе) и каждый каскад: график по дням за 7, 30 или 90 дней, итоги и таблица пользователей с долями по профилям. Колонки таблицы сортируют; клик по строке показывает графики одного пользователя (из карточки пользователя сюда ведёт ссылка «Трафик по профилям»). Трафик, записанный до обновления, в котором появилась разбивка, показан строкой «До разбивки по профилям»; трафик удалённых профилей и каскадов — «Удалённые профили».
- **Устройства.** Все устройства всех пользователей по HWID: модель, платформа, приложение, последний IP, когда появилось и когда было в последний раз. Поиск по имени, HWID, модели, приложению и IP. Сверху — сколько новых устройств и адресов появлялось по дням за 30 дней и платформы.
- **IP-адреса.** С каких адресов подключались пользователи за 90 дней: пара «пользователь — адрес» одной строкой, на какой ноде видели последний раз, когда впервые и когда последний раз. Адреса наших нод не записываются.

Как это считается: у каждого пользователя на каждом инбаунде своё имя клиента в Xray (`<id>.i<номер инбаунда>`, через каскад — `<id>.c<номер каскада>`), поэтому нода присылает трафик отдельно по инбаундам. Адреса берутся из того же списка онлайна, что и лимит IP (§6.1); адрес, который остаётся онлайн, записывается раз в минуту. Трафик по профилям и адреса хранятся 90 дней.

## 8. Профили и инбаунды

Обычно хватает того, что создала установка: профиль «Reality» и инбаунд `VLESS_<КОД>`. Три уровня настройки, от общего к частному:

| Уровень | Что это | Где править |
|---------|---------|-------------|
| **Шаблон профиля** | Заготовка: JSON инбаунда Xray с `${ПЕРЕМЕННЫМИ}`, точка подключения для подписки, раздел nginx, проверки | «Профили» → «Шаблоны профилей» |
| **Профиль** | Шаблон + значения уровня профиля + свой JSON сервера и подписки. Общий для всех нод, где стоит | «Профили» → «Изменить» |
| **Инбаунд ноды** | Профиль на конкретной ноде: свои ключи Reality, домен, порт, IP входа и выхода, своя правка JSON | «Ноды» → у инбаунда «Настроить» |

### Редактор профиля

- **Поля:** название, тег (`VLESS_${NODE_CODE}`), название сервера в приложениях (`${NODE_FLAG} ${NODE_NAME}`), параметры профиля, перегенерация значений.
- **TLS-отпечаток (`FINGERPRINT`)** есть во всех VLESS-шаблонах: chrome, firefox, safari, ios, android, edge, 360, qq, random, randomized. Он уходит в подписку; для одной ноды его можно переопределить в точке подключения.
- **Вкладка «Клиент»** — кастомный профиль клиента: свои маршруты или свой конфиг Xray для серверов профиля (§5.1).
- **Вкладки «Сервер · JSON» и «Подписка · JSON»** — полный исходный JSON инбаунда Xray и точки подключения (что уходит в подписку), с подсветкой, подсказками переменных и кнопкой «Как в шаблоне». Правится как обычный конфиг, а не патчем; точка у вкладки — профиль отличается от шаблона. Подробнее — [PROFILES.md §1.4](PROFILES.md#14-свой-json-профиля).
- **Справа «Что получат ноды».** Итоговый инбаунд каждой ноды с несохранёнными правками. Если правка ломает хоть одну ноду, там видна ошибка, и сохранить нельзя.

### Редактор инбаунда ноды

- **Поля:** тег, порт, IP входа и выхода (для серверов с несколькими IP), параметры ноды (домен, CDN…), новые ключи Reality.
- **Правка JSON только для этой ноды.**
- **Справа** — итоговый инбаунд. Приватный ключ скрыт.

### Шаблоны профилей

- **Встроенные** (Reality self-steal, XHTTP + REALITY, Hysteria2) не меняются, их можно посмотреть.
- **Свой шаблон:** кнопка «Новый шаблон» открывает рабочую заготовку (VLESS + XHTTP за nginx) с пояснениями к каждому разделу. Второй путь — «Скопировать и изменить» у встроенного. Формат — как у встроенных. На вкладке «Справка» — пошаговая инструкция и описание всех полей, переменных, генераторов и проверок; подробнее — [PROFILES.md](PROFILES.md).
- **Проверка на лету.** Каждая правка проверяется пробной сборкой на тестовой ноде NL. Ключи генерируются, вводимые переменные получают примерные значения. Ошибка в YAML, неизвестная `${ПЕРЕМЕННАЯ}` (в том числе в `host` и `nginx`), ошибка в директивах nginx (если nginx стоит на панели, конфиг проверяется настоящим `nginx -t`) или нарушенная проверка lint видны сразу. Раздел `nginx:` описан в [PROFILES.md §1.3](PROFILES.md#13-формат-файла-шаблона); старое имя `caddy:` тоже работает.
- **Правка используемого шаблона.** Перед сохранением заново собираются все инбаунды, которые на нём работают. Если хоть один ломается, шаблон не сохранится.
- **Ограничения.** Используемый шаблон нельзя удалить или переименовать. Новый профиль на своём шаблоне создаётся как обычно: «Профили» → «+ Профиль» → выбрать шаблон.

```bash
vynel admin profile templates             # шаблоны (встроенные и свои) и их переменные
vynel admin profile list
vynel admin inbound list                  # инбаунды нод: адрес, ключи pbk/sid
vynel admin inbound show VLESS_NL         # итоговый JSON инбаунда для Xray
vynel admin inbound set VLESS_NL --regenerate-keys   # новые ключи Reality (клиентам — обновить подписку)
vynel admin inbound host VLESS_NL         # как сервер выглядит в приложении
vynel admin inbound host VLESS_NL --set remark="🇳🇱 Амстердам"   # своё название
vynel admin inbound host VLESS_NL --set hidden=true             # скрыть из подписки
```

**Наследование.** Изменение профиля применяется ко всем нодам. Отличия конкретной ноды хранятся отдельно и при этом не теряются:

```bash
vynel admin profile set Reality --override '{"streamSettings":{"sockopt":{"tcpKeepAliveIdle":60}}}'
```

## 9. Ещё один сервер (нода)

1. **В панели:** «Ноды» → «Добавить сервер» → домен ноды (A-запись на IP нового сервера), профили. Название и код страны необязательны: при подключении нода сообщит страну своего IP, и панель сама подставит флаг, название и код. Что вписано руками, не меняется. На втором шаге мастер покажет команду установки с одноразовым токеном и **чеклист**.
2. **На новом сервере** (Ubuntu/Debian, root, свободные 80/443) выполните эту команду:

   ```bash
   bash <(curl -fsSL https://github.com/vyto4ka/vynel/releases/latest/download/install.sh) --mode node --token vyn1.…
   ```

   Она поставит vynel, Xray и nginx (пакеты `nginx` и `libnginx-mod-stream`), подключит ноду и запустит службу `vynel-node`. Можно и через меню установщика: пункт 3, затем вставить токен.
3. **Чеклист отмечается сам**, окно можно не закрывать. Шаги:
   - команда выполнена;
   - нода на связи;
   - конфигурация применена;
   - Xray и nginx запущены;
   - домен указывает на сервер;
   - сайт ноды открывается снаружи с настоящим сертификатом;
   - есть профиль.

   Если шаг не прошёл, рядом написано почему и что делать. Например: «токен истёк», «домен указывает на другой IP (нужно серое облако)», «порт 443 закрыт». Тот же чеклист для любой ноды открывает кнопка 🔍 у неё.
4. Пользователи групп с доступом к профилю получат новый сервер в подписке сами.

**Действия с нодой** — меню «⋮» на её карточке. Работают, пока нода на связи:
- перезапустить Xray или веб-сервер (nginx; с тем же конфигом, пользователи не теряются);
- отправить конфиг заново;
- перезапустить службу vynel. На сервере панели это перезапуск и панели: страница переподключится сама;
- перезагрузить сервер;
- выпустить новый токен подключения, удалить ноду.

Каждое действие записывается в журнал.

Из терминала панели то же самое:

```bash
vynel admin node add --name Германия --country de --domain de.example.com   # печатает токен и команду установки
vynel admin inbound attach --node DE --profile Reality                      # VLESS_DE со своими ключами
```

- **Порт 9443.** Ноды сами подключаются к нему на панели (у нод своего порта управления нет). Файрвол панели открывает его только адресам, с которых подключаются ноды, и всем — пока ждёт неиспользованный токен установки или нода ещё не подключалась после обновления. Сменился IP ноды — `vynel firewall gateway open`, после переподключения — `vynel firewall gateway nodes`.
- **Токен.** Одноразовый и действует 24 часа. Новый — кнопка с ключом у ноды или `vynel admin node token DE`; старый сертификат ноды при этом отзывается.
- **Обновление ноды.** Тот же установщик на сервере ноды, пункт 4 (`--mode update`).

Подробно: [INSTALL_GUIDE.md §5](INSTALL_GUIDE.md#5-отдельная-панель-и-ноды).

### 9.1 Биллинг: провайдеры, оплата, лимит трафика

Раздел **«Биллинг»** (в меню «Серверы») — где арендованы серверы и сколько они стоят.

- **Провайдеры.** «+ Провайдер» → ссылка на сайт и, по желанию, на вход в личный кабинет. Название и иконку панель берёт с сайта сама (заголовок страницы, `og:site_name`, иконка сайта); название можно вписать своё. У ноды провайдер выбирается в «Биллинге» или в «Ноды» → ✎; его иконка и название видны у ноды, клик ведёт в личный кабинет.
- **Стоимость и оплата.** У ноды — цена в месяц или в год (сверху страницы — сумма в месяц по всем нодам) и дата, до которой сервер оплачен. За 5 дней до неё бот присылает админам напоминание со ссылкой на вход к провайдеру; новая дата — новое напоминание. Кнопка «+1 мес» продлевает дату.
- **Лимит трафика.** Лимит в гигабайтах, число месяца, когда он сбрасывается (по умолчанию 1-е; 31 в коротком месяце — его последний день, время — из часового пояса бота), и что считать: вход + выход, только исходящий или только входящий — как считает провайдер. Трафик берётся с сетевого интерфейса сервера (весь, не только пользователей). За 2 ГБ до лимита (у лимита меньше 20 ГБ — за десятую часть) нода выключается, бот об этом пишет; в день сброса она включается сама. Включить раньше — переключатель ноды: до конца периода лимит её больше не тронет. Если поднять лимит выше израсходованного, нода включится сразу.

## 10. VLESS через CDN

Встроенного шаблона для CDN больше нет: настройки CDN часто меняются, поэтому такой шаблон добавляется как свой. «Профили» → «Шаблоны профилей» → «Новый шаблон» → вставить YAML шаблона → «Сохранить». Схема и параметры прежнего шаблона для VK CDN описаны в [PROFILES.md §4](PROFILES.md).

Если на панели уже были профили на прежнем встроенном шаблоне `vless-xhttp-vkcdn`, после обновления они продолжают работать: шаблон сам появляется в списке как свой, его можно править.

Пример со своим шаблоном `vless-xhttp-vkcdn`:

```bash
vynel admin profile add --name CDN --template vless-xhttp-vkcdn
vynel admin inbound attach --node NL --profile CDN \
  --set CDN_DOMAIN=cdn.example.com --set ORIGIN_DOMAIN=origin.example.com
```

Остальное делается в кабинете VK Cloud: CDN-ресурс с источником `origin.example.com`, CNAME `cdn.example.com`, кэш выключен. Пошагово — в [PROFILES.md §4.6](PROFILES.md). nginx на ноде настраивается сам: сайт `origin.example.com` с прокси на Xray; если на том же IP:443 есть Reality, nginx разводит соединения по SNI. Имя CDN добавляется в `server_names` шаблона, а сайт источника отвечает на любое имя, поэтому в VK работает «Host: Пересылать». В подписке появится второй сервер «🇳🇱 Нидерланды · CDN». Mihomo и sing-box этот вариант не поддерживают и его не получают.

### XHTTP + REALITY напрямую

Встроенный шаблон `vless-xhttp-reality`. Это XHTTP прямо на ноду, без CDN, под маской своего сайта, как Reality в шаблоне A. Трафик выглядит как обычные HTTP-запросы к сайту: кука сессии, номер пакета и набивка в query. Подробно схема описана в [PROFILES.md §8](PROFILES.md).

```bash
vynel admin profile add --name XHTTP --template vless-xhttp-reality            # stream-up
vynel admin profile add --name XHTTP-P --template vless-xhttp-reality --set XHTTP_MODE=packet-up
vynel admin inbound attach --node NL --profile XHTTP --listen 203.0.113.11
```

- Режим (`stream-up` или `packet-up`), маскировка (`XHTTP_OBFS`: `compat` для любых клиентов или `cookie` из ТЗ для свежих) и TLS-отпечаток (`FINGERPRINT`) выбираются в профиле.
- На одном IP:443 может работать только один режим, и шаблон A тоже занимает IP:443. Поэтому для C нужен второй IP ноды или другой порт.
- В подписке появится «🇳🇱 Нидерланды · XHTTP».
- KeqDroid и другие приложения со ссылками получают ссылку с `extra`.
- Приложения на ядре Mihomo 1.19+ получают `xhttp-opts`. Проверено на настоящем Mihomo.
- sing-box этот вариант не получает.

### Hysteria2 рядом с Reality

Встроенный шаблон `hysteria2` («Hysteria2 (сертификат ноды)»). Это QUIC на **UDP** 443 на том же IP, домене и сертификате, что и Reality на TCP 443. Хорошо работает на мобильных сетях и каналах с потерями. Подробно схема описана в [PROFILES.md §9](PROFILES.md).

```bash
vynel admin profile add --name Hysteria2 --template hysteria2
vynel admin inbound attach --node NL --profile Hysteria2
```

- Сертификат берётся тот, что нода уже получила для своего сайта (Let's Encrypt). Агент сам копирует его для Xray и подхватывает продления.
- Тем, кто пришёл без пароля, Hysteria показывает тот же сайт-заглушку по HTTP/3.
- Пароль Hysteria — UUID пользователя. Включение, отключение и лимиты работают так же, как у VLESS.
- В подписке появится «🇳🇱 Нидерланды · Hysteria2». Её получают все форматы: ссылки, Xray JSON, Mihomo и sing-box.
- Нужен открытый **UDP 443**. Установщик открывает его в ufw, а firewall в панели хостера проверьте сами.

## 11. Настройки

`vynel admin setting КЛЮЧ` показывает значение, `vynel admin setting КЛЮЧ ЗНАЧЕНИЕ` меняет.

| Ключ | По умолчанию | Что делает |
|------|--------------|-----------|
| `hwid.enabled` | `true` | Учёт устройств |
| `hwid.default_limit` | `0` | Лимит устройств, если у пользователя нет своего (0 = без лимита) |
| `ip.default_limit` | `3` | Лимит адресов одновременно, если у пользователя нет своего (0 = без лимита, §6.1) |
| `hwid.allow_missing` | `false` | Пускать приложения без HWID |
| `sub.domain` | домен установки | Домен в ссылках подписки |
| `sub.prefix` | `/s/` | Путь подписок, например `/api/v1/client/` |
| `sub.title`, `sub.update_hours`, `sub.support_url`, `sub.announce`, `sub.announce_url`, `sub.page_url` | | Основное подписки — удобнее менять в панели: «Подписка» → «Основное» |
| `sub.headers`, `sub.page` | по умолчанию | Заголовки и страница подписки (JSON) — меняются в панели: «Подписка». Пустое значение возвращает умолчания |
| `sub.decoy` | случайный при установке | Сайт-заглушка домена подписок: `cloud` (облачное хранилище), `studio` (дизайн-студия), `docs` (документация), `coffee` (кофейня), `journal` (блог). Многостраничные, адреса без `.html` |
| `caddy.email` | `admin@<домен>` | Email для Let's Encrypt (старое имя ключа сохранено) |
| `web.path` | случайный | Секретный путь веб-панели |
| `web.domain` | — | Отдельный домен для панели (нужна A-запись на сервер панели); пусто — на домене подписок |
| `web.port` | как `sub.port` | Свой порт панели, например высокий `47321`: сканеры 443 её не увидят. Откройте порт в фаерволе, если он есть |
| `web.address` | как `sub.address` | IP, на котором слушает панель |
| `web.decoy` | как `sub.decoy` | Сайт-заглушка панели на её домене или порту |
| `web.login_mode` | `password` | Как входить: `password`, `link`, `miniapp` (§0) |
| `web.session_paths` | `false` | `true` — случайный адрес панели на каждую сессию (режим `link`) |
| `sub.address` | все адреса | IP, на котором отвечают подписки |
| `sub.page_enabled` | `true` | `false` — браузер вместо страницы подписки видит 404 заглушки; приложения получают подписку как обычно |
| `sub.ua_rules` | по умолчанию | Правила формата по User-Agent (JSON) — меняются в панели: «Подписка» → «Клиенты» |
| `web.listen` | `127.0.0.1:2097` | Внутренний адрес панели за nginx (после смены — `systemctl restart vynel`) |
| `node.caddy_enabled` | `true` | `false` — веб-сервер vynel (nginx) на ноде не нужен, свой веб-сервер. Для одной ноды: `node.caddy_enabled.DE` (старое имя ключа сохранено) |

Изменения применяются сами, перезапуск не нужен. Исключения — `sub.listen` и `web.listen`: после них нужен `systemctl restart vynel`.

Вверху раздела «Настройки» в панели есть ещё два блока:

- **Скрытие.** Что видит посторонний: секретный путь, свой порт панели, скрыта ли страница подписки, выключен ли вход по паролю. Кнопка «Случайный порт и новый путь» переносит панель на порт 20000–60000 и новый путь. Бот сразу присылает кнопку входа по новому адресу.
- **Адреса и роли.** IP каждой ноды и что на нём работает: панель, подписки, шлюз нод, вход и выход инбаундов. Рядом — проверка DNS: указывают ли домены подписок, панели и нод на свой сервер.

## 13. Telegram-бот

Бот встроен в панель и работает только для админов: всем остальным он не отвечает вовсе, даже не показывает, что это за бот. Входящие порты ему не нужны (long polling).

### Подключить

1. В Telegram: [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username → скопировать токен `123456789:AA…`.
2. Токен — при установке (вопрос «Токен бота») или в панели: «Telegram» → вставить → «Сохранить». Из терминала: `vynel admin bot token 123456789:AA…`.
3. Привязать свой аккаунт:
   - в панели «Привязать аккаунт» → «Открыть бота» → «Start»;
   - или отправить боту `/start КОД`, где код даёт `vynel admin bot code`.

   Код одноразовый, живёт 15 минут. После 10 неверных кодов действующий код сгорает: от перебора.
4. Админов может быть несколько, у всех полные права. Отвязать — в панели или `vynel admin bot unbind ID`.

> Если `api.telegram.org` с сервера недоступен, задайте свой Bot API-сервер или прокси: переменная `VYNEL_TELEGRAM_API=https://…` в `/etc/systemd/system/vynel.service` (`Environment=…`).

### Что умеет

| Команда / кнопка | Что делает |
|------------------|------------|
| Кнопки «🔑 Вход» и «☰ Меню» внизу | Закреплены под полем ввода, доступны откуда угодно: ссылка входа в веб-панель и главное меню. Нажатие не оставляет сообщений — бот сразу удаляет его и делает дело. Бот присылает эти кнопки сам один раз; вернуть, если пропали, — `/start` |
| `/menu` | Сводка: пользователи, онлайн, трафик, сколько нод работает; кнопки разделов |
| `/users`, «👥 Пользователи» | Список по 8 с цветом статуса и днями до конца. **Любой текст боту — поиск**: одно совпадение сразу открывает карточку |
| Карточка пользователя | Срок, трафик, устройства, группы, онлайн, ссылка подписки. Кнопки: +1/3/6/12 мес, отключить/включить, сбросить трафик, лимит трафика, устройства (отвязать), QR-код картинкой, новая ссылка (с подтверждением), удалить (с подтверждением) |
| `/new vasya`, «➕ Новый» | Новый пользователь. Если шаблонов несколько — выбор кнопками. Карточка со ссылкой приходит новым сообщением под введённым именем, а вопрос бота убирается |
| `/nodes` | Ноды: работает / нет связи, онлайн, CPU, RAM, трафик за сегодня, предупреждения |

| `/firewall`, «🧱 Файрвол» | Файрвол сервера панели: сколько сканеров заблокировано, «Разблокировать всех», выключить или включить. Выручит, если заблокировало вас самих |

Все действия бота пишутся в «Журнал» как `bot:<id>`.

### Вход в панель без пароля

Кнопка «🔑 Вход» внизу (или `/login`) присылает кнопку-ссылку на панель. Предыдущая ссылка при этом удаляется.

**Совсем без сообщений.** Кнопка «Панель» слева от поля ввода открывает панель в Telegram; в её шапке есть «В браузере» — одноразовая ссылка сразу открывается во внешнем браузере. В бот при этом ничего не пишется. (Сделать вход постоянной кнопкой внизу без сообщения Telegram не даёт: Mini App, открытая оттуда, не получает данных о том, кто её открыл.)

- **Срок и одноразовость.** Ссылка работает **60 секунд и один раз**. Через минуту бот сам меняет сообщение на «ссылка истекла».
- **Где токен.** Он стоит в части адреса после `#`. Браузер не отправляет её на сервер вместе со страницей, поэтому ссылку не «израсходует» предпросмотр Telegram, и токен не попадёт в логи. Страница сама обменивает его на сессию и тут же стирает из адресной строки.
- **Хранение.** На сервере хранится только хэш токена. Повторное открытие той же ссылки — «ссылка недействительна».
- **Без Telegram.** Если Telegram недоступен: на сервере `vynel admin login-link` выдаёт такую же ссылку.

**Панель внутри Telegram.** У поля ввода в чате с ботом есть кнопка «Панель», такая же есть под ссылкой входа. Она открывает панель как Mini App. Telegram подписывает данные о том, кто её открыл, токеном бота, и панель пускает только привязанных админов. Работает в приложениях Telegram для телефона и компьютера; в браузерной версии Telegram — нет.

### Сводка и сообщения

- **Сводка за сутки** каждый день в 10:00, время меняется в «Telegram» → «Сводка и вход». В ней трафик и сравнение с прошлыми сутками, активные пользователи, пик онлайна, кто больше всех качал, у кого подписка закончится за 3 дня, сколько нод в порядке.
- **Вход в панель:** сразу, с браузером, IP и кнопкой «Завершить эту сессию».
- **Нода не применила конфигурацию:** один раз на новую ошибку, с текстом ошибки. Когда нода её применит — «✅ применила».
- **Панель переехала** (новый путь, порт или домен): новый адрес и кнопка входа.

### Уведомления о нодах

Если нода не на связи дольше заданного времени (по умолчанию 60 секунд, «Telegram» → «Через сколько секунд»), каждый админ получает **одно** сообщение:

```
🔴 Нода 🇩🇪 Германия (DE) недоступна
с 07.10 12:03 (уже 15 мин)
последняя связь: 07.10 12:02:51
последняя проверка: 12:18:20
```

- **Пока нода недоступна.** Новых сообщений нет: это же сообщение обновляется раз в минуту.
- **Когда нода вернулась.** Сообщение превращается в «🟢 снова в строю, была недоступна 12:03 – 12:20 (17 мин)», и приходит короткий ответ на него, чтобы телефон дал знать.
- **Перезапуск панели.** Состояние переживает перезапуск: бот продолжит редактировать то же сообщение.
- **Какие ноды проверяются.** Выключенные и ещё не подключённые ноды не проверяются.

## 14. Бэкапы и восстановление

**Что в бэкапе.** Бэкап — архив `.tar.gz`:
- согласованный снимок базы панели: пользователи, группы, шаблоны, ноды, профили, ключи Reality, настройки, логин панели, статистика;
- внутренний CA, которому доверяют ноды.

С ним новая панель поднимается со всеми пользователями, и ноды подключаются к ней без новых токенов.

> В бэкапе приватные ключи. Храните его как пароль.

**Шифрование (необязательно).** Telegram считается доверенным местом, поэтому по умолчанию бэкап — обычный `.tar.gz`. Чтобы шифровать: «Telegram» → «Бэкапы» → «Шифровать бэкапы паролем» (не короче 8 символов). Тогда все бэкапы — ночные, «Бэкап сейчас», скачанные и копии на сервере — файлы `….tar.gz.age` ([age](https://age-encryption.org), шифрование паролем). Восстановление спросит пароль: `vynel restore файл.age` (или `--password`, или переменная `VYNEL_BACKUP_PASSWORD`), установщик — `--restore файл.age --backup-password …` или вопрос в терминале. Открыть вручную: `age -d файл.age > backup.tar.gz`. **Без пароля зашифрованный бэкап не восстановить** — сохраните его отдельно. «Выключить» возвращает обычные бэкапы.

| Как получить | |
|--------------|---|
| Каждый вечер в Telegram | По умолчанию в 23:00 по Москве, всем админам. Время и часовой пояс — «Telegram» → «Бэкапы»; пусто — выключено |
| Сейчас в Telegram | `/backup` или «💾 Бэкап сейчас» в боте, «Отправить бэкап сейчас» в панели |
| Файлом из панели | «Telegram» → «Скачать бэкап» |
| В терминале | `vynel admin backup` (или `-o файл`) |
| На сервере | последние 7 ночных — в `/var/lib/vynel/backups/` |

**Восстановление** на новом сервере (старый умер, переезд):

1. Направьте домены на новый IP (A-записи).
2. Скопируйте файл бэкапа на сервер и запустите установщик с ним:

   ```bash
   bash <(curl -fsSL …/install.sh) --mode aio --domain nl.example.com --restore /root/vynel-backup-….tar.gz
   ```

   В меню установщика: пункт 1 или 2, на вопрос «Восстановить из бэкапа?» → путь к файлу. Установщик поставит программы, восстановит данные и подстроит их под новый сервер (домены, IP). Логин и пароль панели будут прежними.
3. Если у панели сменился IP, на каждой ноде выполните `vynel node set-panel НОВЫЙ_IP:9443`. Ключи и сертификаты нод остаются прежними.

На уже установленной панели: `systemctl stop vynel && vynel restore файл.tar.gz --yes && systemctl start vynel`. Прежние данные не удаляются, а откладываются в `/var/lib/vynel/.before-restore-<время>/`.

## 15. Если не подключается: логи и диагностика

**1. Панель: применился ли конфиг на ноде.**

```bash
vynel admin node list   # STATE должен быть in sync, PROBLEMS пусто, XRAY — версия
```

В веб-панели то же видно на странице «Ноды»: статус и ошибка в карточке ноды. Если в карточке ошибка, Xray на ноде продолжает работать со старым конфигом. Тогда новых инбаундов там нет, а клиент получает ошибку рукопожатия.

**2. Версии панели и ноды должны совпадать.** Сравните `vynel version` на панели и на ноде. Новые шаблоны (Hysteria2, XHTTP + REALITY) требуют свежего агента на ноде. Обновить ноду: установщик → «Обновить».

**3. Отчёт с ноды.**

```bash
vynel node diag > diag.txt
```

В отчёте нет ключей и UUID пользователей, им можно делиться. Что в нём есть:
- версии, время сервера и какие инбаунды реально запущены;
- результат `xray -test`;
- проверку `nginx -t`;
- сертификаты: какие получены, и не стоит ли у Hysteria2 временный самоподписанный;
- ответ локального сайта nginx, на который REALITY пересылает чужие подключения;
- DNS домена, открытые порты, ufw и последние 300 строк журнала агента.

**4. Подробный лог Xray.**

```bash
vynel admin setting node.xray_log debug   # на панели; только одна нода: node.xray_log.NL
journalctl -u vynel-node -f               # на ноде; подключитесь клиентом и смотрите
vynel admin setting node.xray_log warning # потом верните обратно
```

Вывод Xray и nginx идёт в журнал агента (`src=xray`, `src=nginx`). Уровень `debug` пишет каждое подключение, поэтому включайте его только на время поиска проблемы. Что означают типичные строки:

| Что в логе | Причина |
|------------|---------|
| `REALITY: processed invalid connection` | Ключ, shortId или SNI клиента не совпадают с сервером: подписка устарела, обновите её. Ещё бывает при расхождении часов больше чем на минуту |
| `failed to dial to target` / в отчёте `Reality targets: FAILED` | Сайт nginx на 127.0.0.1:8443 не отвечает: nginx не запущен или конфиг не прошёл `nginx -t` (см. `src=nginx` и ошибку в карточке ноды) |
| `failed to validate path` | Путь XHTTP у клиента не тот (старая подписка) |
| XHTTP подключается и пингуется, сервер пишет `accepted … DIRECT`, но трафика ноль | Клиент со старым ядром не понимает разметку `cookie`. В профиле XHTTP выберите `XHTTP_OBFS = compat` (он по умолчанию) и обновите подписку |
| Hysteria: клиент пишет об ошибке сертификата | У ноды временный сертификат: настоящий ещё не получен (обычно не открыт порт 80 или нет A-записи; см. `component=nginx` в журнале) |
| Hysteria: таймаут | Закрыт UDP 443 (ufw или firewall хостера) |
