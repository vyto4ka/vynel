# Переход с Caddy на nginx

С этой версии веб-сервер vynel — nginx. Он отдаёт сайты-заглушки, служит целью Reality,
разводит соединения по SNI, если на одном порту несколько протоколов, и проксирует XHTTP
за CDN. Caddy больше не ставится. Обновление идёт из командной строки, база панели,
пользователи, ключи и сертификаты сохраняются.

## Что изменится

| Было (Caddy) | Стало (nginx) |
|---|---|
| Caddy сам получал сертификаты | Сертификаты получает vynel (Let's Encrypt, HTTP-01), выданные Caddy переносятся без перевыпуска |
| Сайты за Reality на `127.0.0.1:8443` | Так же. Если на одном IP:443 Reality и другие сайты (CDN-источник, панель), порт 443 занимает nginx и разводит по SNI: имена Reality → Xray, остальное → сайты |
| CDN-источник отвечал только на своё имя | CDN-источник отвечает и на домен CDN (`server_names`), и на любое имя, и без SNI — как nginx из гайда. Поэтому VK CDN с «Заголовок Host: Пересылать» работает. Остальные сайты по-прежнему со строгим SNI: чужое имя или его отсутствие — обрыв рукопожатия |
| Раздел шаблона `caddy:` | `nginx:` (старое имя читается). В шаблон можно вписать директивы nginx из инструкции как есть: `location: \|`, `server: \|`, `server_names` |
| Заглушки — по одной странице | Пять многостраничных сайтов, адреса без `.html` |
| Порт 9443 открыт всем | Порт 9443 открыт только адресам нод |

## Порядок обновления

Порядок не важен: панель отправляет nginx тем нодам, где он уже стоит, а остальным — прежний
конфиг Caddy. Нода без веб-сервера не остаётся: если nginx не запустился, возвращается
Caddy. Без цели Reality не работает.

Удобнее так:

1. **Панель.** На сервере панели:
   ```bash
   vynel update
   ```
   Перед обновлением установщик сохраняет бэкап базы и CA в
   `/var/lib/vynel/backups/pre-update-<дата>.tar.gz`. Затем ставит `nginx` и
   `libnginx-mod-stream` и выключает системный `nginx.service`: порты 80 и 443 нужны vynel.
   На all-in-one сервере встроенная нода переходит на nginx сразу.
2. **Ноды.** На каждой ноде `vynel update`, или в панели «Ноды» → «Обновить все». Нода с
   nginx сообщает об этом панели, и через несколько секунд получает конфиг nginx.

Проверка после обновления:

```bash
vynel node diag | sed -n '/===== nginx/,/===== Reality/p'   # nginx -t и сертификаты
ss -ltnp | grep nginx                                      # nginx слушает 80 и 443 (или 127.0.0.1:8443)
```

В панели на карточке ноды вместо версии Caddy видна версия nginx.

## Сертификаты

- Сертификаты, которые Caddy уже получил, копируются в `<данные>/web/tls/<домен>/`.
  Перевыпуска не будет, лимиты Let's Encrypt не тратятся.
- Новые домены: сначала временный самоподписанный сертификат, через минуту-две настоящий
  от Let's Encrypt. Нужны A-запись на сервер и открытый порт 80.
- Продление — за 30 дней до конца срока.
- Почта для Let's Encrypt: «Настройки» → «Сертификаты» (по умолчанию `admin@<домен>`
  при новой установке).

## Свои шаблоны профилей

Шаблоны с разделом `caddy:` продолжают работать: это старое имя раздела `nginx:`.
Переименовывать не обязательно. Новые возможности раздела:

```yaml
nginx:
  role: reverse_proxy_xhttp
  domain: ${ORIGIN_DOMAIN}            # на него получается сертификат
  server_names: [ "${CDN_DOMAIN}" ]   # имена без своего сертификата: Host, который пересылает CDN
  path: ${UPLINK_PATH}
  upstream: 127.0.0.1:${XRAY_PORT}
  location: |                         # свои директивы внутри location пути — как в инструкции
    proxy_pass http://127.0.0.1:${XRAY_PORT};
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_buffering off;
    proxy_request_buffering off;
    client_max_body_size 0;
  server: |                           # директивы уровня server
    large_client_header_buffers 8 64k;
```

Шаблон проверяется настоящим `nginx -t` в редакторе панели, если nginx стоит на панели, и
ещё раз на ноде перед применением.

## Если что-то пошло не так

- **nginx не стартует на ноде.** В карточке ноды будет ошибка. Нода при этом продолжает
  работать на Caddy, если он был. Подробности: `vynel node diag` и
  `journalctl -u vynel-node -n 100`. Частая причина — порт 80 или 443 занят чужим
  веб-сервером: `ss -ltnp '( sport = :80 or sport = :443 )'`.
- **Откат vynel.** Установщик сам возвращает прежнюю версию, если новая не запустилась.
  Бинарь Caddy и его сертификаты не удаляются в этой версии, так что прежний vynel работает
  как раньше. Бэкап базы лежит в `/var/lib/vynel/backups/`.
- **Нода не подключается после смены её IP** (порт 9443 открыт только адресам нод):
  `vynel firewall gateway open` на панели, после подключения ноды —
  `vynel firewall gateway nodes`. Можно и так: создать для ноды токен установки, он
  открывает порт на сутки.
