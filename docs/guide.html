00 Шаг ноль: что нужно заранее

Сервер (VPS)

Ubuntu 22.04+ или Debian 11+, от 1 ГБ RAM, доступ root по SSH. Лучше чистый: без другого веб-сервера, 3x-ui, Remnawave. У хостера должны быть открыты TCP 80, 443 и UDP 443.

Домен

Любой, можно поддомен вроде nl.example.com. Без домена не будет сертификата, а без него — ни маскировки, ни HTTPS для подписок.

Получится так: на одном сервере с одним доменом работают веб-панель, подписки, сайт-заглушка и вход для клиентов (VLESS Reality, по желанию Hysteria2). Снаружи сервер выглядит как обычный сайт.

01 Проверьте, что IP сервера не заблокирован

Подключитесь к серверу по SSH с выключенным VPN, из той сети, где будут пользоваться (домашний интернет, мобильный):

свой компьютер
ssh root@203.0.113.10
  • Пустил или спросил пароль — IP доступен, можно ставить.
  • Долго висит и падает по таймауту (а через VPN подключается) — IP заблокирован у провайдера. Попросите у хостера другой IP или возьмите другой сервер: настройки тут не помогут.

02 Направьте домен на сервер

Там, где у домена DNS (регистратор или Cloudflare), добавьте одну запись: тип A, имя — поддомен (например nl), значение — IP сервера.

Cloudflare: облако у записи — серое (DNS only). С оранжевым Reality не работает и сертификат не выпускается.

Запись расходится от минуты до часа. Ждать с проверками не нужно: установщик сам покажет под полем домена, куда он сейчас указывает.

03 Запустите установщик

На сервере под root:

на сервере
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/main/scripts/install.sh)

Откроется форма в терминале. Первым пунктом выберите «Всё на этом сервере». Дальше в большинстве полей уже стоит подходящее значение (серым) — его оставляет Enter.

Установка без вопросов (для скриптов)
на сервере
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/main/scripts/install.sh) \

05 После установки

В конце установщик печатает адрес панели, логин и пароль. Сохраните их: пароль показывается один раз.

итог установки
  Веб-панель
    адрес    https://nl.example.com/k9Qm2xT7aB3c/
    логин    admin
    пароль   dzU3LxPNfCNR3F9s

Откройте адрес в браузере и войдите. В разделе «Ноды» сервер должен быть зелёным, без проблем. Если хочется проверить из терминала — одной командой:

на сервере
vynel admin node list   # STATE: in sync, PROBLEMS пусто

Забыли адрес — vynel admin web, пароль — vynel admin web password выдаст новый. Дальше — вкладка «Первое подключение».

06 Если что-то не так

СимптомЧто делать
ports 80/443 are in useНа сервере уже есть веб-сервер. Остановите его (systemctl disable --now nginx или apache2) и запустите установщик снова
Домен → ничего / чужой IPA-запись ещё не разошлась или с опечаткой — шаг 02
Сертификат не выпускаетсяПорт 80 закрыт у хостера или оранжевое облако Cloudflare. После исправления нода повторит сама за пару минут
Нода с ошибкойТекст ошибки — в карточке ноды. Журнал: journalctl -u vynel -e
Закрыл себе SSH файрволомКонсоль хостера: vynel firewall off. Или бот: «🧱 Файрвол» → «Разблокировать всех»
Начать зановоУстановщик → «Удалить», затем установить снова

Отдельная панель и ноды на других серверах, несколько IP, обновление — INSTALL_GUIDE.md.

Минимум, чтобы подключиться: всё со стандартными значениями. Подробнее о каждом разделе — во вкладке «Администрирование».

01 Инбаунд из шаблона

Установщик уже создал профиль «Reality» (VLESS Reality) и поставил его на сервер — можно сразу переходить к шагу 02. Инбаунд — это вход для клиентов на конкретной ноде; профиль — его общие настройки, которые берутся из шаблона.

Добавить второй протокол, например Hysteria2 (быстрее на плохих каналах):

1

«Профили» → «+ Профиль» → название (например Hysteria2) → шаблон «Hysteria2 (сертификат ноды)» → «Создать». Поля с параметрами не трогайте: всё заполнится само.

2

«Ноды» → у своего сервера «+ Профиль» → выберите новый профиль → «Добавить». Порт, ключи и тег создадутся автоматически.

Кто его получит: группа «Основная» (в неё попадают все новые пользователи) видит все профили, поэтому новый сервер появится у пользователей сам, с ближайшим обновлением подписки.

02 Пользователь

«Пользователи» → «+ Пользователь» → имя (например vasya) → «Создать». Достаточно имени: срок (3 месяца), группа и лимиты берутся из шаблона пользователя по умолчанию — они показаны серым.

Откроется карточка пользователя со ссылкой подписки, QR-кодом и кнопкой «Копировать». Продлить потом — кнопки «+1 / 3 / 6 / 12 мес» в той же карточке.

03 Подписка

Отправьте ссылку пользователю. На телефоне она открывает страницу с QR-кодом и кнопками приложений; рекомендуемое — KeqDroid (Android, Windows, Linux): кнопка «Добавить в KeqDroid» стоит первой. В любом другом приложении — «Добавить подписку» и вставить ссылку.

Что стоит поправить один раз — «Подписка» → «Основное»:

  • Название подписки — так она называется в приложениях.
  • Поддержка — ссылка на ваш Telegram: кнопка в приложениях и на странице.

Остальное (маршруты, форматы для разных приложений, вид страницы) уже настроено: российские сайты идут напрямую, остальное — через сервер.

Не подключается? В карточке пользователя видны его устройства и адреса. По умолчанию одновременно можно подключаться с 3 IP-адресов. Остальное — «Если не подключается».

00 Как устроено

Шаблон профиляГотовая схема: VLESS + Reality или Hysteria2
ПрофильВаши общие настройки на основе шаблона. Изменение применяется на всех нодах

Всё, что есть в панели, есть и в терминале: vynel admin … на сервере панели. Справка у любой команды: vynel admin user --help.

01 Веб-панель

Дашборд и статистика

Онлайн, трафик, графики за 24 ч – 90 дней, нагрузка нод, топ пользователей, баннер новой версии.

Пользователи

Поиск и фильтры, карточка: подписка с QR, продление +1/3/6/12 мес, устройства, лимиты.

Группы и шаблоны

Кто какие серверы видит и что получает новый пользователь.

Подписка

Название, объявление, страница, кнопки приложений, заголовки, правила форматов, проверка ответа.

Ноды и профили

Серверы, их инбаунды и ключи; профили и шаблоны профилей с проверкой на лету.

Настройки и Telegram

Домены и IP, путь и домен панели, заглушка, сертификаты, бот, сводки, бэкапы.

на сервере
vynel admin web                       # адрес панели и логин
vynel admin web password              # новый пароль (сессии разлогинятся)
vynel admin setting web.path /новый-путь/   # сменить секретный путь

Безопасность входа: сессия закрывается после 5 минут бездействия и привязана к IP; о каждом входе бот присылает сообщение с кнопкой «Завершить эту сессию». Открытые сессии — «Аккаунт» или /sessions в боте.

02 Пользователи

В панели — «Пользователи». Статусы: active работает, expired истёк срок, limited кончился трафик, disabled отключён. Неактивный пропадает со всех нод за секунды, а в приложении вместо серверов видит причину «⛔ …».

на сервере
vynel admin user add vasya                    # срок и группы — из шаблона по умолчанию
vynel admin user add vasya --template Пробный
vynel admin user list --status active
vynel admin user show vasya                   # статус, трафик, ссылка подписки
vynel admin user extend vasya --months 1      # или --days 7
vynel admin user disable vasya                # enable — включить обратно
vynel admin user reset vasya                  # обнулить трафик
vynel admin user reissue vasya                # новая ссылка, старая перестанет работать
vynel admin user devices vasya                # устройства; --rm ID — отвязать
vynel admin user rm vasya

Своя ссылка подписки вместо случайной: поле «Ссылка подписки» при создании или vynel admin user link vasya vasya-phone-01 (8–64 символа: латиница, цифры, _, -).

03 Группы и шаблоны пользователей

Группа решает, какие серверы видит пользователь. Установка создала «Основную» с доступом ко всему профилю «Reality»: новая нода с этим профилем сразу появится у всех в группе. Групп у пользователя может быть несколько — доступы складываются.

на сервере
vynel admin group add Тест
vynel admin group grant Тест profile Reality          # весь профиль, включая будущие ноды
vynel admin group grant Тест node NL                # все инбаунды ноды
vynel admin group grant Тест inbound VLESS_NL       # один инбаунд
vynel admin user groups vasya --group Основная --group Тест

Шаблон пользователя — что получает новый пользователь, если указать только имя. Изменение шаблона не трогает уже созданных.

на сервере
vynel admin template add Пробный --days 3 --limit-gb 5 --reset no --group Основная
vynel admin template add Год --months 12 --group Основная --default

04 Подписка и приложения

Ссылка вида https://nl.example.com/s/<токен>. Формат ответа выбирается по приложению:

Кто запрашиваетЧто получает
KeqDroid, Happ, v2RayTunXray JSON: у каждого сервера свой конфиг с маршрутами
Остальные приложения на XrayСписок ссылок vless://, hysteria2://
Mihomo (Clash Meta)Профиль YAML
sing-boxПрофиль JSON
БраузерСтраница: срок, трафик, QR-код, кнопки «Добавить в …»

Явно: …/s/<токен>/clash, /singbox, /json, /base64. Неверный токен открывает 404 сайта-заглушки, а IP, который перебирает токены, банится на час.

Раздел «Подписка» в панели: название и объявление в приложениях, страница (тема, цвет, тексты с переменными {username}, {days_left}…), кнопки приложений (первая — KeqDroid), HTTP-заголовки, вкладка «Клиенты» — какой формат какому приложению (у каждого можно вставить свой конфиг, например шаблон из Remnawave), «Маршруты» — что идёт напрямую, что через сервер, что блокируется (домены, IP, geosite:, процессы process:), и «Проверка» — что получит конкретное приложение. Всё видно в предпросмотре до сохранения.

Устройства и адреса. По умолчанию число устройств (HWID) не ограничено, а подключаться одновременно можно с 3 IP-адресов: vynel admin setting ip.default_limit 5. Лимит устройств — vynel admin setting hwid.default_limit 3; клиенты без HWID — выключить проверку пользователю в карточке или vynel admin setting hwid.allow_missing true.

05 Каскады и внешние подписки

Каскад («Профили» → «Каскады»): приложение подключается к одной ноде, а в интернет выходит через другую. Для пользователя это отдельный сервер в подписке, например «🇳🇱 Нидерланды → 🇩🇪 Германия». Новых портов не нужно. Группа «Основная» получает каждый каскад сразу; другим — в «Группах» или в карточке пользователя со своим сроком.

Внешняя подписка — чужие серверы в вашей подписке: ссылка на подписку друга или другой панели, или сами ссылки vless://, hysteria2://. Выдаётся группе, шаблону пользователя или одному пользователю; обновляется, когда приложение обновляет подписку.

06 Аналитика

Раздел «Аналитика» — то, чего нет на дашборде:

  • По профилям — сколько трафика ушло через каждый профиль и каскад, всего и у каждого пользователя, графиком по дням.
  • Устройства — все HWID всех пользователей: модель, приложение, последний IP, поиск.
  • IP-адреса — с каких адресов подключались за 90 дней и на какой ноде.

Нагрузка серверов (процессор, steal, память, канал) — на дашборде, вкладка «Серверы».

Биллинг

Раздел «Биллинг»: провайдеры (ссылка на сайт и на вход в кабинет — название и иконка подтянутся сами), у каждой ноды — провайдер, цена и дата оплаты. За 5 дней до оплаты бот напомнит. Лимит трафика провайдера в гигабайтах и число месяца сброса (по умолчанию 1-е): за пару гигабайт до лимита нода выключится и включится сама в новый период.

07 Профили и инбаунды

Установка создала профиль «Reality» и инбаунд VLESS_NL — этого достаточно для начала. Настройка идёт на трёх уровнях:

УровеньЧто этоГде
Шаблон профиляJSON инбаунда Xray с ${ПЕРЕМЕННЫМИ}, точка подключения, раздел nginx, проверкиПрофили → Шаблоны
ПрофильШаблон + ваши значения. Общий для всех нодПрофили → Изменить
Инбаунд нодыПрофиль на ноде: ключи, домен, порт, IP входа и выходаНоды → «Настроить»

Справа в редакторе — «Что получат ноды»: итоговый конфиг каждой ноды с несохранёнными правками. Если правка ломает хоть одну ноду, сохранить нельзя.

Два протокола

VLESS + Reality

TCP 443, маскировка под свой сайт-заглушку. Профиль «Reality» есть сразу после установки.

Hysteria2

UDP 443 рядом с Reality, на сертификате ноды. Хорош на мобильных сетях. Нужен открытый UDP 443.

на сервере
vynel admin profile templates                         # шаблоны и их переменные
vynel admin profile add --name Hysteria2 --template hysteria2
vynel admin inbound attach --node NL --profile Hysteria2
vynel admin inbound list                              # инбаунды: адрес, ключи pbk/sid
vynel admin inbound set VLESS_NL --regenerate-keys  # новые ключи Reality
vynel admin inbound host VLESS_NL --set remark="🇳🇱 Амстердам"

08 Свои шаблоны профилей

Обычно не нужны: VLESS + Reality и Hysteria2 уже встроены. Если захочется своё — «Профили» → «Шаблоны профилей» → «Новый шаблон» (заготовка с пояснениями к каждому разделу) или «Скопировать и изменить» у встроенного. На вкладке «Справка» — все поля, переменные и проверки.

Каждая правка проверяется пробной сборкой на тестовой ноде: ошибка YAML, неизвестная ${ПЕРЕМЕННАЯ} или ошибка nginx видны сразу. Используемый шаблон нельзя удалить, а правка, которая ломает хоть одну ноду, не сохранится. Формат — PROFILES.md.

09 Ещё один сервер

1

A-запись домена новой ноды → IP нового сервера (в Cloudflare — серое облако).

2

В панели: «Ноды» → «Добавить сервер» → домен, профили. Страну и название можно не заполнять — их определит установщик ноды по IP.

3

Панель покажет команду с токеном (одноразовый, 24 часа). Выполните её на новом сервере:

на новом сервере
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/…/scripts/install.sh) --mode node --token vyn1.…

Через минуту нода станет «работает», и пользователи групп с доступом к её профилям получат новый сервер в подписке сами.

Порт 9443 на панели открыт только адресам нод. Нода сменила IP и не подключается — на панели vynel firewall gateway open, после подключения vynel firewall gateway nodes.

10 Обновление

Из панели. Раз в полчаса панель сверяет версии. Если есть новая — баннер на дашборде и значок у «Нод». «Обновить всё» обновляет все ноды разом, панель — последней; около минуты подключения не работают. Ход обновления и лог видны прямо на карточке ноды. Одна нода — меню «⋮» → «Обновить».

На сервере:

на сервере
vynel update --check          # только сравнить версии
vynel update                  # в фоне; следить: journalctl -u vynel-update -f
vynel update --foreground     # здесь и сейчас
  • Обновляются vynel, Xray и nginx; пользователи, ключи, настройки, логин и пароль сохраняются.
  • Перед обновлением панели — бэкап базы в /var/lib/vynel/backups/pre-update-<дата>.tar.gz.
  • Новая версия не запустилась — возвращается прежняя сама. Лог: /var/log/vynel-update.log.
  • GitHub с сервера тормозит — зеркало: bash <(curl …/install.sh) --mode update --gh-proxy https://ghfast.top/.
Переход с Caddy на nginx идёт при обычном обновлении, база не теряется — MIGRATION_NGINX.md.

12 Бэкапы и переезд

Бэкап — .tar.gz со снимком базы (пользователи, ноды, профили, ключи, настройки, логин) и внутренним CA. С ним новая панель поднимается со всеми пользователями, а ноды подключаются без новых токенов. В нём приватные ключи — храните как пароль.

на сервере
vynel admin backup -o /root/vynel-backup.tar.gz      # сейчас
ls /var/lib/vynel/backups/                           # последние 7 ночных и перед обновлениями

Переезд на новый сервер: направьте домен на новый IP, скопируйте бэкап и запустите установщик с ним — логин и пароль останутся прежними:

на новом сервере
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/main/scripts/install.sh) \
  --mode aio --domain nl.example.com --restore /root/vynel-backup.tar.gz

Если сменился IP панели, на каждой отдельной ноде: vynel node set-panel НОВЫЙ_IP:9443.

13 Файрвол и защита

Открыто только то, что сервер реально обслуживает: SSH, 80/443, порты инбаундов (vynel берёт их из конфига сам), 9443 — только адресам нод. Остальное молчит. Адрес, который за минуту стучится в 20+ закрытых портов, блокируется на сутки. Свои (вход по SSH, сессия панели, подключение своим ключом) не блокируются никогда.

на сервере
vynel firewall status                # что открыто, сколько заблокировано
vynel firewall allow 8080 5000/udp   # свои порты; deny — закрыть
vynel firewall unblock all           # снять блокировки
vynel firewall off                   # выключить и снять правила

SSH по ключу и другой порт включаются потом через установщик: пункт «Защитить сервер» (--mode harden).

15 Если не подключается

1

vynel admin node list — нода in sync, проблем нет. Ошибка применения видна и в карточке ноды; пока она есть, нода работает на прежнем конфиге.

2

Версии панели и ноды совпадают: vynel version на обеих.

3

Подробный лог Xray на время проверки:

на сервере
vynel admin setting node.xray_log debug
journalctl -u vynel -f            # подключитесь клиентом и смотрите (отдельная нода: -u vynel-node)
vynel admin setting node.xray_log warning
В логеПричина
