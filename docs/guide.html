00 Что получится

Один сервер, один домен. На нём сразу всё: веб-панель, подписки, сайт-заглушка и сам вход для клиентов (VLESS + Reality). Снаружи сервер выглядит как обычный сайт с HTTPS.

:443 → Xray (Reality, имя ) ├─ свой клиент (ключ Reality) → выход в интернет └─ всё остальное → nginx 127.0.0.1:8443 ├─ /секретный-путь/ → веб-панель ├─ /s/токен → подписка └─ остальное → сайт-заглушка :80 → nginx: сертификат Let's Encrypt, редирект на https :9443 → подключение других серверов (нод), только с их адресов

Маскировка

Браузер и сканер видят сайт: один из пяти многостраничных сайтов-заглушек, настоящий сертификат, HSTS, TLS 1.2/1.3.

Свой nginx

vynel держит собственный nginx и сам получает и продлевает сертификаты. Системный nginx выключается.

Защита

Файрвол vynel: открыто только нужное, сканеры портов блокируются, SSH — по ключу и на другом порту по желанию.

02 Подготовка домена

Нужна одна A-запись: {{DOMAIN}} → {{SERVER_IP}}. Её создают там, где у домена DNS: у регистратора или в Cloudflare.

2

Откройте раздел DNS и добавьте запись:

ПолеЗначение
ТипA
Имяподдомен (например, nl) или полное {{DOMAIN}} — как принято у регистратора
Значение{{SERVER_IP}}
TTLавто или 300
Cloudflare: облако у записи должно быть серым (DNS only), не оранжевым. Через прокси Cloudflare Reality работать не будет, а сертификат не выпустится.
Второй домен не обязателен. По желанию подпискам и панели можно дать свой домен на том же сервере (sub.example.com): тогда ссылка подписки не совпадает с адресом сервера. nginx сам разведёт имена на одном 443.

03 Проверка, что домен применился

Записи расходятся от минуты до часа. Не запускайте установку, пока публичный DNS не отдаёт ваш IP: иначе сертификат не выпустится с первой попытки (установщик и нода повторят сами, но быстрее дождаться).

3

Публичные DNS Cloudflare и Google — у себя на компьютере (Windows, macOS, Linux):

свой компьютер
nslookup {{DOMAIN}} 1.1.1.1
nslookup {{DOMAIN}} 8.8.8.8
ожидание
Name:    {{DOMAIN}}
Address: {{SERVER_IP}}
4

То же с сервера, плюс проверка, что это именно этот сервер:

на сервере
curl -s "https://dns.google/resolve?name={{DOMAIN}}&type=A" | grep -o '"data":"[^"]*"'
curl -4s https://ifconfig.me; echo
ожидание
"data":"{{SERVER_IP}}"
{{SERVER_IP}}

Оба IP должны совпасть. Пусто в первой строке — запись ещё не разошлась или опечатка в имени. Другой IP — запись указывает не туда (или старая запись ещё в кэше: подождите TTL).

Установщик проверяет DNS и сам: прямо под полем домена он показывает ✓ {{DOMAIN}} → {{SERVER_IP}} или что не так, в том числе оранжевое облако Cloudflare.

Порт меняется безопасно: новый открывается рядом со старым, установщик просит проверить вход по нему из другого окна, и только потом закрывает 22.

00 Как устроено

Шаблон профиля ──► Профиль (общие настройки) ──► Инбаунд ноды (VLESS_…) ▲ Пользователь ──► Группы ──── правила доступа ────────────────────┘ │ └─► Подписка: одна ссылка → все серверы, доступные через группы
ПонятиеЧто это
НодаСервер, к которому подключаются клиенты (Xray + nginx). В all-in-one живёт на сервере панели, код — {{NODE_CODE}}
Шаблон профиляГотовая схема: VLESS + Reality или Hysteria2
ПрофильВаши общие настройки на основе шаблона. Изменение применяется на всех нодах
Инбаунд нодыПрофиль на конкретной ноде со своими ключами: VLESS_{{NODE_CODE}}
ГруппаК чему есть доступ: профиль целиком, нода или один инбаунд
Шаблон пользователяЧто получает новый пользователь: срок, лимиты, группы
Точка подключенияКак сервер выглядит в приложении: «🇳🇱 Нидерланды»
Если вы с Remnawave: профиль + инбаунд ≈ Config Profile, группа ≈ Internal Squad, точка подключения ≈ Host.

Всё, что есть в панели, есть и в терминале: vynel admin … на сервере панели. Справка у любой команды: vynel admin user --help.

01 Веб-панель

Дашборд и статистика

Онлайн, трафик, графики за 24 ч – 90 дней, нагрузка нод, топ пользователей, баннер новой версии.

Пользователи

Поиск и фильтры, карточка: подписка с QR, продление +1/3/6/12 мес, устройства, лимиты.

Группы и шаблоны

Кто какие серверы видит и что получает новый пользователь.

Подписка

Название, объявление, страница, кнопки приложений, заголовки, правила форматов, проверка ответа.

Ноды и профили

Серверы, их инбаунды и ключи; профили и шаблоны профилей с проверкой на лету.

Настройки и Telegram

Домены и IP, путь и домен панели, заглушка, сертификаты, бот, сводки, бэкапы.

на сервере
vynel admin web                       # адрес панели и логин
vynel admin web password              # новый пароль (сессии разлогинятся)
vynel admin setting web.path /новый-путь/   # сменить секретный путь

Безопасность входа: сессия закрывается после 5 минут бездействия и привязана к IP; о каждом входе бот присылает сообщение с кнопкой «Завершить эту сессию». Открытые сессии — «Аккаунт» или /sessions в боте.

02 Пользователи

В панели — «Пользователи». Статусы: active работает, expired истёк срок, limited кончился трафик, disabled отключён. Неактивный пропадает со всех нод за секунды, а в приложении вместо серверов видит причину «⛔ …».

на сервере
vynel admin user add {{USERNAME}}                    # срок и группы — из шаблона по умолчанию
vynel admin user add {{USERNAME}} --template Пробный
vynel admin user list --status active
vynel admin user show {{USERNAME}}                   # статус, трафик, ссылка подписки
vynel admin user extend {{USERNAME}} --months 1      # или --days 7
vynel admin user disable {{USERNAME}}                # enable — включить обратно
vynel admin user reset {{USERNAME}}                  # обнулить трафик
vynel admin user reissue {{USERNAME}}                # новая ссылка, старая перестанет работать
vynel admin user devices {{USERNAME}}                # устройства; --rm ID — отвязать
vynel admin user rm {{USERNAME}}

Своя ссылка подписки вместо случайной: поле «Ссылка подписки» при создании или vynel admin user link {{USERNAME}} {{USERNAME}}-phone-01 (8–64 символа: латиница, цифры, _, -).

03 Группы и шаблоны пользователей

Группа решает, какие серверы видит пользователь. Установка создала «Основную» с доступом ко всему профилю «Reality»: новая нода с этим профилем сразу появится у всех в группе. Групп у пользователя может быть несколько — доступы складываются.

на сервере
vynel admin group add Тест
vynel admin group grant Тест profile Reality          # весь профиль, включая будущие ноды
vynel admin group grant Тест node {{NODE_CODE}}                # все инбаунды ноды
vynel admin group grant Тест inbound VLESS_{{NODE_CODE}}       # один инбаунд
vynel admin user groups {{USERNAME}} --group Основная --group Тест

Шаблон пользователя — что получает новый пользователь, если указать только имя. Изменение шаблона не трогает уже созданных.

на сервере
vynel admin template add Пробный --days 3 --limit-gb 5 --reset no --group Основная
vynel admin template add Год --months 12 --group Основная --default

04 Подписка и приложения

Ссылка вида https://{{DOMAIN}}/s/<токен>. Формат ответа выбирается по приложению:

Кто запрашиваетЧто получает
KeqDroid и приложения на XrayСписок ссылок vless://, hysteria2://
Mihomo (Clash Meta)Профиль YAML
sing-boxПрофиль JSON
БраузерСтраница: срок, трафик, QR-код, кнопки «Добавить в …»

Явно: …/s/<токен>/clash, /singbox, /json, /base64. Неверный токен открывает 404 сайта-заглушки, а IP, который перебирает токены, банится на час.

Раздел «Подписка» в панели: название и объявление в приложениях, страница (тема, цвет, тексты с переменными {username}, {days_left}…), кнопки приложений (первая — KeqDroid), HTTP-заголовки, правила «какой формат какому приложению» и вкладка «Проверка» — что получит конкретное приложение. Всё видно в предпросмотре до сохранения.

Устройства (HWID). По умолчанию до 3 на пользователя. Лимит — vynel admin setting hwid.default_limit 5; клиенты без HWID — выключить проверку пользователю в карточке или vynel admin setting hwid.allow_missing true.

05 Профили и инбаунды

Установка создала профиль «Reality» и инбаунд VLESS_{{NODE_CODE}} — этого достаточно для начала. Настройка идёт на трёх уровнях:

УровеньЧто этоГде
Шаблон профиляJSON инбаунда Xray с ${ПЕРЕМЕННЫМИ}, точка подключения, раздел nginx, проверкиПрофили → Шаблоны
ПрофильШаблон + ваши значения. Общий для всех нодПрофили → Изменить
Инбаунд нодыПрофиль на ноде: ключи, домен, порт, IP входа и выходаНоды → «Настроить»

Справа в редакторе — «Что получат ноды»: итоговый конфиг каждой ноды с несохранёнными правками. Если правка ломает хоть одну ноду, сохранить нельзя.

Два протокола

VLESS + Reality

TCP 443, маскировка под свой сайт-заглушку. Профиль «Reality» есть сразу после установки.

Hysteria2

UDP 443 рядом с Reality, на сертификате ноды. Хорош на мобильных сетях. Нужен открытый UDP 443.

на сервере
vynel admin profile templates                         # шаблоны и их переменные
vynel admin profile add --name Hysteria2 --template hysteria2
vynel admin inbound attach --node {{NODE_CODE}} --profile Hysteria2
vynel admin inbound list                              # инбаунды: адрес, ключи pbk/sid
vynel admin inbound set VLESS_{{NODE_CODE}} --regenerate-keys  # новые ключи Reality
vynel admin inbound host VLESS_{{NODE_CODE}} --set remark="🇳🇱 Амстердам"

06 Свои шаблоны профилей

Обычно не нужны: VLESS + Reality и Hysteria2 уже встроены. Если захочется своё — «Профили» → «Шаблоны профилей» → «Новый шаблон» (заготовка с пояснениями к каждому разделу) или «Скопировать и изменить» у встроенного. На вкладке «Справка» — все поля, переменные и проверки.

Каждая правка проверяется пробной сборкой на тестовой ноде: ошибка YAML, неизвестная ${ПЕРЕМЕННАЯ} или ошибка nginx видны сразу. Используемый шаблон нельзя удалить, а правка, которая ломает хоть одну ноду, не сохранится. Формат — PROFILES.md.

07 Ещё один сервер

1

A-запись домена новой ноды → IP нового сервера (в Cloudflare — серое облако).

2

В панели: «Ноды» → «Добавить сервер» → домен, профили. Страну и название можно не заполнять — их определит установщик ноды по IP.

3

Панель покажет команду с токеном (одноразовый, 24 часа). Выполните её на новом сервере:

на новом сервере
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/…/scripts/install.sh) --mode node --token vyn1.…

Через минуту нода станет «работает», и пользователи групп с доступом к её профилям получат новый сервер в подписке сами.

Порт 9443 на панели открыт только адресам нод. Нода сменила IP и не подключается — на панели vynel firewall gateway open, после подключения vynel firewall gateway nodes.

08 Обновление

Из панели. Раз в полчаса панель сверяет версии. Если есть новая — баннер на дашборде и значок у «Нод». «Обновить всё» обновляет все ноды разом, панель — последней; около минуты подключения не работают. Ход обновления и лог видны прямо на карточке ноды. Одна нода — меню «⋮» → «Обновить».

На сервере:

на сервере
vynel update --check          # только сравнить версии
vynel update                  # в фоне; следить: journalctl -u vynel-update -f
vynel update --foreground     # здесь и сейчас
  • Обновляются vynel, Xray и nginx; пользователи, ключи, настройки, логин и пароль сохраняются.
  • Перед обновлением панели — бэкап базы в /var/lib/vynel/backups/pre-update-<дата>.tar.gz.
  • Новая версия не запустилась — возвращается прежняя сама. Лог: /var/log/vynel-update.log.
  • GitHub с сервера тормозит — зеркало: bash <(curl …/install.sh) --mode update --gh-proxy https://ghfast.top/.
Переход с Caddy на nginx идёт при обычном обновлении, база не теряется — MIGRATION_NGINX.md.

10 Бэкапы и переезд

Бэкап — .tar.gz со снимком базы (пользователи, ноды, профили, ключи, настройки, логин) и внутренним CA. С ним новая панель поднимается со всеми пользователями, а ноды подключаются без новых токенов. В нём приватные ключи — храните как пароль.

на сервере
vynel admin backup -o /root/vynel-backup.tar.gz      # сейчас
ls /var/lib/vynel/backups/                           # последние 7 ночных и перед обновлениями

Переезд на новый сервер: направьте домен на новый IP, скопируйте бэкап и запустите установщик с ним — логин и пароль останутся прежними:

на новом сервере
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/main/scripts/install.sh) \
  --mode aio --domain {{DOMAIN}} --restore /root/vynel-backup.tar.gz

Если сменился IP панели, на каждой отдельной ноде: vynel node set-panel НОВЫЙ_IP:9443.

11 Файрвол и защита

Открыто только то, что сервер реально обслуживает: SSH, 80/443, порты инбаундов (vynel берёт их из конфига сам), 9443 — только адресам нод. Остальное молчит. Адрес, который за минуту стучится в 20+ закрытых портов, блокируется на сутки. Свои (вход по SSH, сессия панели, подключение своим ключом) не блокируются никогда.

на сервере
vynel firewall status                # что открыто, сколько заблокировано
vynel firewall allow 8080 5000/udp   # свои порты; deny — закрыть
vynel firewall unblock all           # снять блокировки
vynel firewall off                   # выключить и снять правила

SSH по ключу и другой порт включаются потом через установщик: пункт «Защитить сервер» (--mode harden).

13 Если не подключается

1

vynel admin node list — нода in sync, проблем нет. Ошибка применения видна и в карточке ноды; пока она есть, нода работает на прежнем конфиге.

2

Версии панели и ноды совпадают: vynel version на обеих.

3

Подробный лог Xray на время проверки:

на сервере
vynel admin setting node.xray_log debug
journalctl -u vynel -f            # подключитесь клиентом и смотрите (отдельная нода: -u vynel-node)
vynel admin setting node.xray_log warning
В логеПричина
REALITY: processed invalid connectionПодписка устарела (ключ, shortId, SNI) — обновить; или часы расходятся больше чем на минуту
failed to dial to targetСайт nginx на 127.0.0.1:8443 не отвечает: см. ошибку в карточке ноды
Hysteria: ошибка сертификатаНастоящий сертификат ещё не получен (порт 80, A-запись)
Hysteria: таймаутЗакрыт UDP 443 у хостера
