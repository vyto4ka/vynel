# Публичное API

API нужно, чтобы подключить к панели то, что должно управлять подписками само: биллинг, Telegram-бота, другую панель, личный кабинет, скрипт. Через него создают пользователей, продлевают и отключают их, читают трафик, состояние нод и следят за событиями.

Это не тот API, которым пользуется сама панель в браузере. У него свои токены, свои права, стабильные имена полей и описание в формате OpenAPI.

## Быстрый старт

1. В панели откройте **«API» → «Токены» → «Создать токен»**. Назовите его по программе, которая будет им пользоваться, отметьте нужные права. Токен показывается **один раз**: скопируйте его.
2. Адрес API показан на вкладке «Начало». Он состоит из адреса панели, её секретного пути и `/api/v1`:

   ```
   https://panel.example.com/<секретный путь>/api/v1
   ```

3. Проверьте:

   ```bash
   export VYNEL_API=https://panel.example.com/<секретный путь>/api/v1
   export VYNEL_TOKEN=vyn_...

   curl -H "Authorization: Bearer $VYNEL_TOKEN" $VYNEL_API/me
   ```

   В ответе — имя токена, его права и время сервера.

4. Создайте пользователя и продлите ему подписку:

   ```bash
   curl -X POST $VYNEL_API/users \
     -H "Authorization: Bearer $VYNEL_TOKEN" -H "Content-Type: application/json" \
     -H "Idempotency-Key: order-1042-create" \
     -d '{"username": "alice", "external_id": "order-1042", "telegram_id": 123456789}'

   curl -X POST $VYNEL_API/users/1/extend \
     -H "Authorization: Bearer $VYNEL_TOKEN" -H "Content-Type: application/json" \
     -H "Idempotency-Key: order-1042-paid" \
     -d '{"months": 1}'
   ```

   В ответе — пользователь с полем `subscription_url`: эту ссылку выдают клиенту.

Попробовать запросы можно прямо в панели: вкладка **«Проверка»** знает все методы, подставляет примеры и показывает тот же запрос на curl, Python, Node.js, PHP и Go.

## Токены

Токен — ключ, по которому программа входит в API. Он выглядит как `vyn_` и 43 символа: 256 случайных бит. Приставка `vyn_` нужна, чтобы утёкший токен находили сканеры секретов.

**Как токен хранится.** Панель хранит только хэш (SHA-256). Показать токен второй раз она не может: потеряли — создайте новый и отзовите старый. Утечка базы панели не раскрывает токены.

**Как токен передаётся.** Заголовком `Authorization: Bearer vyn_…`. Ни в адресе, ни в теле: адреса попадают в журналы.

### Права

У токена есть только те права, которые вы отметили. Запрос за пределами прав получает `403 insufficient_scope`.

| Право | Что разрешает |
|-------|---------------|
| `users:read` | Список и поиск пользователей, один пользователь, ссылки подписки, устройства, трафик |
| `users:write` | Создание, изменение, продление, включение и выключение, сброс трафика, перевыпуск ссылки, удаление устройства |
| `users:delete` | Удаление пользователей. Отдельное право: удаление необратимо, а токен, который только продлевает подписки, не должен его уметь |
| `groups:read` | Список групп |
| `templates:read` | Шаблоны пользователей (тарифы) |
| `nodes:read` | Состояние и нагрузка нод |
| `stats:read` | Сводка: пользователи, трафик, онлайн |
| `events:read` | Лента событий |

Готовые наборы при создании токена: **«Биллинг»** (пользователи, группы, шаблоны, события), **«Telegram-бот»** (то же без событий, плюс ноды и статистика), **«Только чтение»**, **«Всё, кроме удаления»**. Набор лишь отмечает права, их можно поправить.

Вебхуками и токенами управляют из панели (или командой `vynel admin api-token create|list|revoke` в терминале), а не по API: токен, которым можно выписывать токены, был бы лишним риском.

### Разрешённые адреса

Токен можно привязать к адресам или сетям: `203.0.113.5`, `10.0.0.0/24`, по одному в строке. Запрос с другого адреса получит `403 ip_not_allowed`. Если токен утечёт, им не воспользуются с чужого сервера. Укажите адрес машины, на которой работает ваша программа.

Панель берёт адрес клиента из соединения; заголовку `X-Forwarded-For` она верит только от своего обратного прокси на этой же машине.

### Срок и лимит запросов

- **Срок действия.** Временным интеграциям ставьте срок (7, 30, 90 дней, год); по истечении токен отвечает `401 token_expired`. Менять срок можно без смены токена.
- **Запросов в минуту.** По умолчанию 600. Нужен, чтобы зациклившаяся программа не положила панель. Ответ при превышении — `429 rate_limited` с `Retry-After`.

### Отзыв и журнал

«Отозвать» выключает токен сразу (`401 token_revoked`), запись остаётся в списке. В списке видны: когда токен использовали в последний раз, с какого адреса и сколько было запросов.

Всё, что программа делает через API, попадает в журнал действий под её именем (актор `api`, имя токена). Те же имена видны в событиях.

### Правила хранения

- Токен — пароль. Держите его в переменной окружения или в секретах сервера, не в коде, не в репозитории, не в чате.
- Один токен на одну программу. Тогда в журнале видно, кто что сделал, а отзыв одного не ломает остальные.
- Давайте минимум прав и адреса, с которых токен работает.
- Меняйте токены время от времени: создайте новый, переключите программу, отзовите старый.
- Подозреваете утечку — отзовите сразу, потом разбирайтесь по журналу.

## Запросы и ответы

- Тела запросов и ответов — JSON в UTF-8, `Content-Type: application/json`.
- Названия полей — `snake_case`. Времена — RFC 3339 в UTC: `2026-12-31T23:59:59Z`. Размеры — в байтах.
- `null` в ответе значит «нет»: у `expire_at` — «без срока», у `traffic_limit_bytes` — «без лимита».
- Неизвестные поля в **запросе** — ошибка (`bad_json`): опечатка не должна молча терять данные. Неизвестные поля в **ответе** игнорируйте: со временем их станет больше.
- Каждый ответ несёт `X-Request-Id`. Назовите его, когда будете спрашивать, что пошло не так.
- Тексты ошибок английские; сообщения о неподходящих значениях (`validation_failed`) приходят по-русски, если запрос с заголовком `Accept-Language: ru` (или `X-Lang: ru`). Программе нужен `code`: он не зависит от языка.

### Списки

Списки отдаются страницами:

```json
{"items": [ … ], "total": 1280, "limit": 50, "offset": 0}
```

`limit` — до 500 (по умолчанию 50), `offset` — смещение. `total` — всего подходящих под фильтр. Чтобы обойти всех, листайте `offset`, пока он меньше `total`. Лента событий листается курсором (см. ниже).

### Ошибки

```json
{"error": {"code": "user_not_found", "message": "user not found", "field": "id", "request_id": "req_0a1b2c3d4e5f6071"}}
```

`code` — то, по чему программа принимает решения; `message` — для человека; `field` — какое поле виновато (когда это применимо).

| Статус | `code` | Когда |
|--------|--------|-------|
| 400 | `bad_json`, `unknown_field`, `bad_parameter`, `bad_id`, `bad_idempotency_key` | Запрос не разобрать |
| 401 | `unauthenticated` | Нет заголовка `Authorization` |
| 401 | `invalid_token`, `token_expired`, `token_revoked` | Токен не подходит |
| 403 | `insufficient_scope` | У токена нет нужного права |
| 403 | `ip_not_allowed` | Токен не разрешён с этого адреса |
| 404 | `user_not_found`, `group_not_found`, `node_not_found`, `device_not_found`, `no_such_endpoint` | Нет такого |
| 405 | `method_not_allowed` | Метод не подходит к пути (заголовок `Allow` говорит, какой подходит) |
| 409 | `username_taken`, `telegram_id_taken`, `external_id_taken`, `subscription_token_taken`, `conflict` | Значение занято другим |
| 413 | `body_too_large` | Тело больше 1 МиБ |
| 422 | `validation_failed` | Значения не годятся; `message` объясняет, `field` указывает поле |
| 422 | `idempotency_key_reused` | Ключ идемпотентности уже был у другого запроса |
| 429 | `rate_limited`, `too_many_failures` | Слишком много запросов или неверных токенов; ждите `Retry-After` секунд |
| 500 | `internal` | Ошибка панели. Повторите с тем же ключом идемпотентности; если не проходит — сообщите `request_id` |

## Повторы и идемпотентность

Сеть теряет ответы. Если запрос «продлить на месяц» ушёл, а ответ не дошёл, программа не знает, продлено или нет. Повторить без защиты значит рискнуть продлить дважды.

Поэтому каждый запрос, который что-то меняет (`POST`, `PATCH`, `DELETE`), надо отправлять с заголовком `Idempotency-Key`: уникальным значением до 128 символов. Правила:

- Повтор с тем же ключом и тем же запросом возвращает **первый ответ** (с заголовком `Idempotent-Replayed: true`) и ничего не делает второй раз.
- Тот же ключ с другим запросом — `422 idempotency_key_reused`.
- Ключи принадлежат токену: у другого токена те же ключи не пересекаются.
- Ответ хранится 24 часа. Ответы `5xx` и `429` не запоминаются: их можно и нужно повторять.
- Параллельные запросы с одним ключом выполняются по очереди, действие произойдёт один раз.

Как выбирать ключ: он должен однозначно называть **действие**. Для оплаты — номер платежа или заказа (`order-1042-paid`): уведомление платёжной системы, пришедшее дважды, не продлит подписку дважды. Для действий без естественного номера — случайный UUID, но тогда программа должна сохранить его до первой попытки и использовать тот же при повторе.

Клиенты из [api-examples](api-examples/README.md) делают это сами: повторяют при сетевых ошибках, `5xx` и `429` (ждут `Retry-After`), всегда с одним и тем же ключом.

## Лимиты и защита от перебора

- **Лимит токена.** По умолчанию 600 запросов в минуту (меняется у токена). Остаток видно в заголовках: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (unix-время сброса).
- **Неверные токены.** 10 несуществующих токенов с одного адреса за 5 минут блокируют адрес на 15 минут: `429 too_many_failures`, в `Retry-After` — сколько ждать. Блок действует на адрес, поэтому ждут и верные токены с него. Отозванный или просроченный токен не считается: это не подбор, а программа, которой не сказали. Счётчик сбрасывается первым верным запросом.
- Попытки с неверным токеном видны в журнале панели (`journalctl -u vynel | grep "api:"`).

## Методы

Права — в скобках. Полное описание с полями и примерами — в OpenAPI (`/openapi.json`, `/openapi.yaml`) и на вкладке «Проверка».

### Аккаунт

| Метод | Описание |
|-------|----------|
| `GET /me` | Токен, которым вызвали (имя, права, адреса, срок), и время сервера. Подходит любой токен |
| `GET /openapi.json`, `GET /openapi.yaml` | Описание API. Токен не нужен |

### Пользователи

| Метод | Право | Описание |
|-------|-------|----------|
| `GET /users` | `users:read` | Список. Фильтры: `status`, `search`, `username`, `telegram_id`, `external_id`; `sort`, `order`; `limit`, `offset`; `include=subscription` добавляет ссылку подписки каждому |
| `POST /users` | `users:write` | Создать |
| `GET /users/{id}` | `users:read` | Один пользователь со ссылкой подписки |
| `PATCH /users/{id}` | `users:write` | Изменить: присылайте только то, что меняется |
| `DELETE /users/{id}` | `users:delete` | Удалить (`204`) |
| `POST /users/{id}/extend` | `users:write` | Продлить: `{"months": 1, "days": 0}` |
| `POST /users/{id}/reset-traffic` | `users:write` | Сбросить счётчик трафика периода |
| `POST /users/{id}/enable`, `/disable` | `users:write` | Включить, выключить |
| `POST /users/{id}/reissue` | `users:write` | Новая ссылка подписки и/или UUID: `{"subscription_token": true, "uuid": false}`. Без тела — новая ссылка |
| `GET /users/{id}/subscription` | `users:read` | Ссылка подписки и ссылки на отдельные серверы |
| `GET /users/{id}/traffic?days=30` | `users:read` | Трафик по нодам и по дням |
| `GET /users/{id}/devices` | `users:read` | Устройства, которые брали подписку |
| `DELETE /users/{id}/devices/{device_id}` | `users:write` | Освободить место под устройство |

#### Пользователь

```json
{
  "id": 17,
  "username": "alice",
  "status": "active",
  "enabled": true,
  "expire_at": "2026-12-31T23:59:59Z",
  "traffic_limit_bytes": 107374182400,
  "traffic_used_bytes": 5368709120,
  "lifetime_traffic_bytes": 21474836480,
  "reset_strategy": "month",
  "hwid_limit": null,
  "hwid_off": false,
  "ip_limit": null,
  "client_type": "auto",
  "note": "",
  "telegram_id": 123456789,
  "external_id": "order-1042",
  "group_ids": [1],
  "template_id": 1,
  "uuid": "eb86d8dd-d34a-4588-aa2c-0768634a0c66",
  "online_at": "2026-10-28T11:20:00Z",
  "created_at": "2026-10-01T09:00:00Z",
  "subscription_url": "https://sub.example.com/s/…"
}
```

- `status`: `active`, `disabled` (выключен вручную), `limited` (кончился трафик), `expired` (кончился срок). Меняется сам, в том числе без вашего участия: об этом событие `user.status_changed`.
- `external_id` — идентификатор этого человека в вашей системе, `telegram_id` — его аккаунт в Telegram. Оба уникальны среди пользователей и по ним ищут: `GET /users?external_id=…`. Хранятся для связи, на работу подписки не влияют.
- `subscription_url` — ссылка, которую выдают клиенту. В списках её нет, пока не попросить `include=subscription`. Равна `null`, пока в панели не настроен домен подписок.
- `hwid_limit`, `ip_limit`: `null` — действует общая настройка панели; `ip_limit: 0` — без ограничения.

#### Создание

Обязателен только `username` (1–64 символа: буквы, цифры, `_ . - @`). Остальное берётся из шаблона (`template_id`, по умолчанию — шаблон «по умолчанию»), если не указано:

```json
{
  "username": "alice",
  "template_id": 2,
  "group_ids": [1, 3],
  "note": "заказ 1042",
  "expire_at": "2026-12-31T23:59:59Z",
  "never_expires": false,
  "traffic_limit_bytes": 107374182400,
  "reset_strategy": "month",
  "hwid_limit": 3,
  "ip_limit": 5,
  "client_type": "auto",
  "telegram_id": 123456789,
  "external_id": "order-1042",
  "subscription_token": "own-link-end-123"
}
```

Ответ — `201` и созданный пользователь. Занятое имя — `409 username_taken`, занятые `telegram_id` или `external_id` — `409 telegram_id_taken` / `external_id_taken`.

#### Изменение

`PATCH` меняет только присланные поля; `null` означает «нет» (или «по умолчанию»):

```json
{"enabled": true, "expire_at": null, "traffic_limit_bytes": null, "note": "оплачен", "external_id": null}
```

Можно менять: `note`, `enabled`, `expire_at`, `traffic_limit_bytes`, `reset_strategy`, `hwid_limit`, `hwid_off`, `ip_limit`, `client_type`, `group_ids`, `telegram_id`, `external_id`, `subscription_token`. Поле вне списка — `400 unknown_field`. Значения проверяются все до первого изменения, но сами изменения применяются по очереди; нужна жёсткая атомарность — отправляйте поля отдельными запросами с ключами идемпотентности.

#### Продление

`extend` прибавляет срок к **большему из «сейчас» и текущего срока окончания**: оплаченные дни не теряются, а просроченная подписка отсчитывается от сегодняшнего дня. У пользователя без срока он появится.

### Группы и шаблоны

| Метод | Право | Описание |
|-------|-------|----------|
| `GET /groups`, `GET /groups/{id}` | `groups:read` | Группы и сколько людей в каждой |
| `GET /user-templates` | `templates:read` | Шаблоны пользователей (тарифы): срок, трафик, группы |

Группа говорит, к каким серверам есть доступ; её `id` кладут в `group_ids` пользователя. Тариф в вашей системе обычно соответствует шаблону: `template_id` при создании.

### Ноды и статистика

| Метод | Право | Описание |
|-------|-------|----------|
| `GET /nodes`, `GET /nodes/{id}` | `nodes:read` | Ноды: состояние, версия, нагрузка (`metrics`), трафик за сегодня, проблемы |
| `GET /stats/overview` | `stats:read` | Пользователи по статусам, онлайн, трафик за сутки и 30 дней, число нод на связи, самые активные |

`state` ноды: `disabled`, `pending` (не подключалась), `offline`, `in sync`, `syncing`. `online` — есть живое соединение с панелью.

### Лента событий

`GET /events` (`events:read`) отдаёт события в порядке появления, старые первыми:

```bash
curl -H "Authorization: Bearer $VYNEL_TOKEN" "$VYNEL_API/events?after=now"
# {"items": [], "next_cursor": "evt_1042", "has_more": false}

curl -H "Authorization: Bearer $VYNEL_TOKEN" "$VYNEL_API/events?after=evt_1042&types=user.*,node.offline"
```

- `after` — курсор из предыдущего ответа (`next_cursor`); `after=now` — начать с нынешнего момента, ничего старого. Без `after` — с самого начала доступного.
- `types` — типы или приставки через запятую: `user.*`, `node.offline`.
- Храните `next_cursor` и передавайте в следующий раз. Если `has_more` — `true`, запросите следующую страницу сразу.
- События хранятся 30 дней.

Это то же, что приходит на вебхуки. Лента нужна программам, которые не могут принимать входящие вызовы, и для догоняния после простоя.

## События и вебхуки

Вебхук — адрес вашей программы, на который панель сама присылает события, как только они случились. Не нужно опрашивать API каждую минуту.

Создаётся на вкладке **«API» → «Вебхуки»**: адрес, какие события присылать, секрет подписи (показывается один раз; потом виден только его конец, а «Новый секрет» выдаёт другой). Кнопка «Проверить» шлёт тестовое событие `ping` и показывает ответ.

### Что приходит

`POST` с телом:

```json
{
  "id": "evt_1042",
  "type": "user.extended",
  "created": 1790000000,
  "actor": {"kind": "api", "id": "billing"},
  "entity": {"type": "user", "id": 17, "username": "alice"},
  "data": {"months": 1, "days": 0}
}
```

- `id` — уникальный номер события. Он же курсор в `GET /events`.
- `actor` — кто это сделал: `admin` (человек в панели), `api` (программа по токену, `id` — имя токена), `bot` (Telegram-бот), `cli`, `system` (сама панель: срок кончился, нода пропала). Свои же изменения можно отсеивать по актору.
- `entity` — над кем: тип, номер и имя (`username` у пользователя, `code` и `name` у ноды, `name` у группы). У удалённого объекта имя тоже есть.
- `data` — подробности; зависят от типа.

Заголовки: `X-Vynel-Event` (тип), `X-Vynel-Delivery` (номер доставки), `X-Vynel-Timestamp`, `X-Vynel-Signature`, `Content-Type: application/json`, `User-Agent: Vynel-Webhook/1`.

### Типы событий

| Тип | Когда | `data` |
|-----|-------|--------|
| `user.created` | Пользователь создан | — |
| `user.deleted` | Удалён | — |
| `user.extended` | Подписка продлена | `months`, `days` |
| `user.expiry_changed` | Срок задан напрямую | `expire_at` (время или `null`) |
| `user.limit_changed` | Изменён лимит трафика | `limit` (байты или `null`) |
| `user.traffic_reset` | Счётчик трафика сброшен (вручную или автоматически по периоду) | при автоматическом — `strategy` |
| `user.groups_changed` | Изменены группы | `groups` (список id) |
| `user.updated` | Изменены заметка, лимиты устройств и адресов, тип клиента, `telegram_id`, `external_id` | только изменённые поля: `note`, `hwid_limit`, `ip_limit`, `telegram_id`… |
| `user.credentials_changed` | Перевыпущена или задана вручную ссылка подписки, перевыпущен UUID | `sub_token`, `uuid` (что именно; самих значений нет) |
| `user.status_changed` | Статус сменился сам: кончился срок или трафик | `from`, `to` |
| `user.enabled`, `user.disabled` | Включён, выключен вручную | `enabled` |
| `node.created`, `node.updated`, `node.deleted` | Нода добавлена, изменена, удалена | — (`entity`: `code`, `name`) |
| `node.online`, `node.offline` | Нода подключилась, пропала со связи | — |
| `group.created`, `group.updated`, `group.deleted` | Группы | — (`entity`: `name`) |
| `ping` | Проверка вебхука кнопкой | `note` |

`node.online` и `node.offline` приходят, когда состояние держится минимум два опроса подряд (около 20 секунд): короткая перезагрузка соединения событием не становится. При запуске панели первое состояние нод событием не считается.

Список типов растёт: приёмник должен игнорировать то, чего не знает.

### Как проверять подпись

Любой, кто знает адрес приёмника, может послать на него что угодно. Подпись доказывает, что запрос прислала панель.

В `X-Vynel-Signature` лежит `sha256=` и HMAC-SHA256 от строки `<X-Vynel-Timestamp>.<сырое тело запроса>` с секретом вебхука, в шестнадцатеричном виде. Приёмник должен:

1. Взять **сырое** тело запроса (до разбора JSON: пробелы и порядок полей влияют на подпись).
2. Пересчитать подпись и сравнить **за постоянное время** (`hmac.compare_digest`, `timingSafeEqual`, `hash_equals`).
3. Отвергнуть запрос (`401`), если подпись не совпала **или** `X-Vynel-Timestamp` старше пяти минут: так перехваченный запрос нельзя прислать повторно.

Python:

```python
import hmac, hashlib, time

def verify(secret: str, headers, raw_body: bytes) -> bool:
    ts = headers["X-Vynel-Timestamp"]
    if abs(time.time() - int(ts)) > 300:
        return False
    mac = hmac.new(secret.encode(), ts.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest("sha256=" + mac, headers["X-Vynel-Signature"])
```

Готовые приёмники на Python, Node.js, PHP и Go — в [api-examples](api-examples/README.md); на вкладке «Вебхуки» тот же код показан на четырёх языках.

### Доставка, повторы, порядок

- Ответьте `2xx` быстро, в пределах 10 секунд, а тяжёлую работу сделайте потом. Редиректы не выполняются: `3xx` считается неудачей.
- Не `2xx` или нет ответа — панель повторяет: через 10 секунд, 1, 5, 30 минут, 2, 6 и 12 часов; всего 8 попыток. Потом доставка помечается как не доставленная; её можно отправить заново кнопкой в журнале доставок.
- Если 10 событий подряд не удалось доставить даже после всех повторов, панель **выключает вебхук**, чтобы не стучаться впустую (в списке написано «выключен: не отвечает»). Исправьте приёмник и включите вебхук.
- **Порядок не гарантируется**: событие, которое повторяется, может прийти позже следующего. Смотрите на `id` и `created`.
- **Одно событие может прийти дважды** (повтор после потерянного ответа). Запоминайте обработанные `id` и пропускайте повторы, либо делайте обработку безвредной при повторе.
- Событие записывается в ту же транзакцию, что и изменение, и не теряется, даже если панель перезапустят до отправки.
- В событии нет полного состояния объекта: если нужно «каков пользователь сейчас», запросите `GET /users/{id}`.

### Локальные адреса

По умолчанию вебхук уходит только на **публичные** адреса. Так панель нельзя использовать, чтобы стучаться в внутреннюю сеть сервера (метаданные облака, `127.0.0.1`, соседние машины). Если ваш приёмник работает на этом же сервере или в вашей локальной сети, включите у вебхука «Разрешить локальные адреса».

## Рецепты

### Биллинг: оплата → подписка

Платёжная система сообщила, что заказ оплачен. Что делает биллинг:

1. Находит пользователя по своему идентификатору клиента: `GET /users?external_id=customer-77`. Нет — создаёт: `POST /users` с `external_id` и `template_id` тарифа.
2. Продлевает: `POST /users/{id}/extend` с `Idempotency-Key: order-<номер заказа>`. Если уведомление об оплате придёт дважды, подписка продлится один раз.
3. Если пользователь был выключен (`enabled: false`), включает: `POST /users/{id}/enable`.
4. Показывает клиенту `subscription_url`.

Рабочий код: [python/billing_flow.py](api-examples/python/billing_flow.py).

Обратная связь, чтобы биллинг знал о том, что происходит в панели: подпишитесь на `user.status_changed` (подписка кончилась: можно напомнить об оплате) и `user.deleted`.

### Telegram-бот

Бот не должен хранить пользователей у себя: `telegram_id` лежит в панели, по нему бот находит человека (`GET /users?telegram_id=…`). `/start` создаёт пользователя с `telegram_id` (ключ идемпотентности — `start-<telegram_id>`: повторное нажатие не создаст второго), `/status` показывает срок и трафик из `GET /users/{id}`, `/newlink` перевыпускает ссылку. Бот на aiogram 3: [python/aiogram_bot.py](api-examples/python/aiogram_bot.py).

Токену бота достаточно `users:read` и `users:write`.

### Мониторинг и личный кабинет

- Статус нод для своей страницы статуса: `GET /nodes` (`nodes:read`) или события `node.online` / `node.offline` на вебхук.
- Кабинет клиента: по `external_id` найти пользователя, показать `status`, `expire_at`, трафик (`GET /users/{id}/traffic`), ссылку подписки, устройства (`GET /users/{id}/devices`).

### Другая панель

Панель-партнёр может зеркалить пользователей: раз в минуту `GET /events?after=<курсор>&types=user.*` и повторяет изменения у себя, либо принимает те же события вебхуком. Свои собственные изменения отсеивайте по `actor`.

### Миграция с другой панели

Пользователей переносят скриптом: для каждого `POST /users` с `username`, `expire_at`, `traffic_limit_bytes`, `external_id` (идентификатор в старой панели) и `subscription_token` (чтобы старые ссылки подписок продолжили работать). Ключ идемпотентности — идентификатор в старой панели: скрипт можно запускать повторно.

## OpenAPI, Postman и генерация клиентов

Описание API в формате OpenAPI 3 отдаётся без токена:

```
GET <адрес API>/openapi.json
GET <адрес API>/openapi.yaml
```

Оно вшито в панель и сверяется с кодом тестом, поэтому совпадает с тем, что API делает на самом деле. Файл подходит для:

- **Swagger UI, Redoc** — вставьте адрес описания;
- **Postman, Insomnia, Bruno** — «Import» → адрес описания; токен задайте в авторизации «Bearer Token»;
- **генераторов клиентов** — `openapi-generator`, `oapi-codegen` (Go), `openapi-python-client`, `openapi-typescript` и другие дадут типизированный клиент на нужном языке.

```bash
npx @openapitools/openapi-generator-cli generate -i "$VYNEL_API/openapi.yaml" -g python -o ./vynel-client
```

## Совместимость и версии

Версия API — в адресе: `/api/v1`. Внутри `v1` панель обещает не ломать то, что уже работает:

- имена методов, полей и кодов ошибок не меняются и не исчезают;
- новые поля, методы, типы событий и коды ошибок **добавляются**. Поэтому программа должна игнорировать неизвестные поля ответа и неизвестные типы событий и не ветвиться по тексту `message`;
- несовместимое изменение выйдет как `/api/v2`, `v1` останется работать рядом.

## Безопасность

- API живёт под тем же **секретным путём**, что и панель, и доступен там же, где панель. Если панель закрыта файрволом или VPN-доступом, API закрыт так же. Настоящую защиту дают токены; секретный путь только прячет вход.
- Используйте HTTPS: токены идут в заголовках. Панель за обратным прокси (nginx, Caddy) его уже даёт.
- Привязывайте токены к адресам ваших серверов.
- Приёмник вебхуков всегда проверяет подпись и свежесть метки времени.
- Права минимальные, срок — у временных интеграций, один токен на программу.
- Попытки входа с неверным токеном ограничены (см. «Лимиты»), каждый отказ записан в журнале панели с адресом и причиной.
- Тела запросов ограничены 1 МиБ. CORS-заголовков API не отдаёт (токены предназначены для серверных программ, не для страниц в браузере); исключение — описание OpenAPI, которое доступно любому, кто знает адрес, и не содержит ничего секретного.

## Если что-то не работает

| Что видите | Что делать |
|------------|-----------|
| `404 no_such_endpoint` | Неверный адрес. Он должен заканчиваться на `/api/v1`, и в начале — секретный путь панели (его видно на вкладке «Начало») |
| `401 unauthenticated` | Нет заголовка `Authorization: Bearer …` (прокси иногда его вырезает: проверьте) |
| `401 invalid_token` | Токен скопирован не целиком или принадлежит другой панели |
| `401 token_revoked` / `token_expired` | Отозван или истёк: создайте новый |
| `403 ip_not_allowed` | Запрос идёт не с разрешённого адреса. Какой адрес видит панель — в списке токенов, колонка «Использован» |
| `403 insufficient_scope` | В `message` написано, какое право нужно: добавьте его токену (✎ в списке) |
| `429 too_many_failures` | С этого адреса слишком много неверных токенов; подождите `Retry-After` секунд |
| `422 validation_failed` | Читайте `message` и `field` |
| Вебхук «выключен: не отвечает» | Откройте «Доставки»: там код ответа и ошибка каждой попытки. Исправьте приёмник и включите вебхук |
| Вебхук не доходит, в доставках «address … is not public» | Приёмник на локальном адресе: включите у вебхука «Разрешить локальные адреса» |
| Подпись не совпадает | Считайте по **сырому** телу, а не по разобранному и заново сериализованному JSON; проверьте секрет (после «Нового секрета» старый не работает) и точность строки `<метка>.<тело>` |

Журнал панели: `journalctl -u vynel -f`; строки про API начинаются с `api:`.
