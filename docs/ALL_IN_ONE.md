# All-in-one: всё на одном сервере и одном IP

Панель, нода, Caddy и подписки работают на одном сервере. Отдельные серверы под панель и ноды не нужны. Позже к такому серверу можно подключить дополнительные ноды.

## Сколько нужно доменов

| Вариант | Домены | Что где |
|---------|--------|---------|
| **Минимум** | **1** — `nl.example.com` | Reality SNI + сайт-заглушка + подписки по пути `/s/…` |
| Рекомендуется | 2 — `nl.example.com`, `sub.example.com` | Ссылки подписки не совпадают с адресом VPN-сервера |
| Позже (этап 7, веб-панель) | +1 — `app.example.com` | Интерфейс панели (секретный путь, нестандартный порт) |

**Почему без домена никак.** Reality self-steal показывает чужим посетителям настоящий сайт с настоящим сертификатом, а Let's Encrypt выдаёт сертификат только на домен. Подпискам тоже нужен HTTPS с валидным сертификатом. Можно обойтись без домена, если Reality маскируется под чужой сайт (`www.microsoft.com`), но тогда подписки не будут работать по HTTPS. Поэтому минимум — один домен.

**Почему одного домена хватает.** На один IP и один порт 443 работает всё сразу:

```
:443 → Xray (Reality, SNI nl.example.com)
        ├─ VPN-клиент                  → VPN
        └─ всё остальное (браузер,     → Caddy 127.0.0.1:8443, домен nl.example.com
           приложение за подпиской)        ├─ /s/<токен>  → подписка
                                           └─ всё прочее  → сайт-заглушка (и её 404)
:80  → Caddy: выпуск сертификата (HTTP-01) и редирект на https
:9443 → только для подключения дополнительных нод (mTLS)
```

Отдельный домен подписок ничего не добавляет в плане устойчивости: IP всё равно один. Он нужен только затем, чтобы ссылки подписки не совпадали с адресом VPN-сервера.

## Что нужно

- VPS с Debian 11+ или Ubuntu 22.04+ (amd64 или arm64), root.
- Свободные порты 80 и 443: на сервере не должно быть nginx, Remnawave и т.п.
- A-запись домена (доменов) на IP сервера. Проверка: `getent hosts nl.example.com`.
- IP сервера доступен из РФ: подключение по SSH без VPN проходит.

## Установка

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vpn/claude/magical-hamilton-9vnx7n/scripts/install-aio.sh) \
  --domain nl.example.com \
  --email you@example.com          # необязательно
  # --sub-domain sub.example.com   # если хочешь отдельный домен для подписок
  # --name "Нидерланды" --country NL   # иначе страна определяется по IP
```

Если репозиторий приватный, склонируй его сам и запусти `scripts/install-aio.sh` из клона. Скрипт склонирует себя в `/opt/vpn-src` (`VPN_REPO` указывает, откуда клонировать).

Что делает скрипт:

1. **Проверки:** ОС, архитектура, DNS доменов, свободные порты 80 и 443.
2. **Сборка.** Ставит Go и собирает `vpn` из исходников (пока нет релизов, этап 9), скачивает Xray и Caddy. Первый запуск занимает несколько минут.
3. **Настройка:** `vpn admin setup` создаёт локальную ноду, профиль «Reality» (self-steal) с доступом для группы «Основная», инбаунд `VLESS_<КОД>` со своими ключами и домен подписок.
4. **Сервис.** Создаёт systemd-юнит `vpn-panel`. Ядро настраивается само: BBR, fq, TCP Fast Open.
5. **Ожидание.** Ждёт, пока нода синхронизируется и выпустится сертификат.

Повторный запуск = обновление: код пересобирается, данные сохраняются. Удаление — `--uninstall`, вместе с данными — `--uninstall --purge`.

## Работа

```bash
vpn admin user add vasya              # +3 месяца, группа «Основная», лимит устройств 3
vpn admin user show vasya             # ссылка подписки → открыть на телефоне или импортировать в Happ / v2RayTun
vpn admin user extend vasya --months 1
vpn admin user devices vasya          # устройства HWID; --rm ID освобождает место
vpn admin user disable vasya
vpn admin stats                       # пользователи, онлайн, трафик, топ
vpn admin node list                   # состояние ноды, CPU/RAM, онлайн, предупреждения
journalctl -u vpn-panel -f            # логи
```

Полезные настройки (`vpn admin setting КЛЮЧ ЗНАЧЕНИЕ`):

| Ключ | По умолчанию | Что делает |
|------|--------------|-----------|
| `hwid.default_limit` | `3` | Лимит устройств для пользователей без своего лимита (0 = без лимита) |
| `hwid.allow_missing` | `false` | `true` пускает клиентов без `x-hwid` |
| `hwid.enabled` | `true` | Выключить HWID совсем |
| `sub.title` | `VPN` | Название профиля в клиентах |
| `sub.prefix` | `/s/` | Путь подписок (например, `/api/v1/client/`) |
| `sub.decoy` | `docs` | Сайт-заглушка домена подписок: `cloud`, `studio`, `docs` |
| `sub.support_url` | — | Ссылка поддержки в клиентах |

## Проверка снаружи

- `https://nl.example.com/` в браузере открывает обычный сайт-заглушку с настоящим сертификатом, без заголовка `Server`.
- `https://nl.example.com/s/<токен>` в браузере открывает страницу с QR-кодом и кнопками для приложений, а в приложении — подписку.
- Любой другой путь отдаёт 404 того же сайта. Подбор токенов банит IP на час.

## Добавить ещё одну ноду

На all-in-one сервере открыт порт 9443 для дополнительных нод:

```bash
vpn admin node add --name Германия --country de --domain de.example.com   # печатает токен
vpn admin inbound attach --node DE --profile Reality
# на новом сервере: Xray + Caddy + vpn, затем
vpn node run --token vpn1....
```

Скрипт для отдельной ноды и установка по SSH из панели появятся на этапах 9 и 11.
