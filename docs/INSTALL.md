# Установка

Три сценария:

1. **Первичная установка панели**: интерактивный скрипт по ссылке из GitHub (§1–§3).
2. **Нода по команде**: страница-инструкция с одной командой (ARCHITECTURE.md §6.1).
3. **Нода по SSH прямо из панели**: никуда не заходить руками (§4).

Связанные документы: [INBOUNDS.md](INBOUNDS.md) (IP и роли), [STEALTH.md](STEALTH.md) (скрытие, вход через Telegram).

---

## 1. Запуск

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vpn/main/install.sh)
```

Схема в два слоя:

| Слой | Что делает | Почему так |
|------|-----------|------------|
| `install.sh` (bash, ~100 строк) | Проверяет root, ОС (Debian 11+/Ubuntu 22.04+) и архитектуру (amd64/arm64). Скачивает бинарь `vpn` из GitHub Releases, сверяет sha256 и подпись (minisign), запускает `vpn install` | Bash держим минимальным: в нём трудно делать валидацию, проверки DNS и красивый ввод |
| `vpn install` (Go, TUI) | Все вопросы, проверки, установка | Нормальные формы, валидация на лету, проверки DNS и портов, один код с панелью |

Детали:
- Ввод читается из `/dev/tty`, поэтому `curl … | bash` тоже работает.
- Если терминала нет (cloud-init, Ansible), вопросы не задаются, ответы берутся из флагов или файла: `vpn install --config install.yaml`.
- Ответы (без секретов) сохраняются в `/etc/vpn/install.yaml`. Повторный запуск предлагает: **обновить**, **изменить настройки** (тот же мастер с текущими значениями) или **удалить**.

## 2. Мастер установки: вопросы по порядку

### Шаг 0. Что ставим

```
Что установить?
  1) Панель + нода на этом сервере   (рекомендуется для основного сервера)
  2) Только панель
  3) Только ноду                      (нужен токен из панели — проще ставить из панели, §4)
  4) Восстановить панель из бэкапа
```

### Шаг 1. Проверка системы (без вопросов, только отчёт)

```
✓ Ubuntu 24.04, x86_64, 2 ГБ RAM
✓ время синхронизировано (смещение 12 мс)
⚠ порт 80 занят: nginx (pid 812)        → предложит остановить и отключить
⚠ найден Docker с контейнером remnanode  → предупреждение о конфликте портов
✓ BBR доступен в ядре
```

### Шаг 2. Сеть: интерфейсы, IP и для чего они

Агент показывает все глобальные адреса:

```
Найдено адресов: 3
  #  интерфейс  IP               основной
  1  eth0       203.0.113.10     ✓  (маршрут по умолчанию)
  2  eth0       203.0.113.11
  3  eth1       203.0.113.12
  +  добавить IP, которого нет в списке

IP для панели      [1] 203.0.113.10
IP для подписок    [1] 203.0.113.10   ← можно тот же, что у панели
IP для VLESS       [3] 203.0.113.12
```

Правила подсказок:
- Если IP **один**, вопросы не задаются: всё ставится на него, Reality стоит перед Caddy (INBOUNDS.md §2.3).
- Если VLESS выбран на том же IP, что и панель или подписки, показывается, как будут разложены порты, и предупреждение: «при блокировке IP VLESS станет недоступна и панель».
- Если для VLESS выбран основной IP, предупреждение: «служебный трафик панели будет выходить с IP VLESS», и предложение задать исходящий IP панели (INBOUNDS.md §2.5).
- «Добавить IP» запускает `vpn net add-ip` с откатом (INBOUNDS.md §2.6).

Комбинации, которые принимает мастер (любые роли на любых IP):

| Вариант | IP1 | IP2 | IP3 |
|---------|-----|-----|-----|
| Один IP | панель, подписки, VLESS | — | — |
| **Два IP** | панель + подписки | VLESS | — |
| Два IP | панель | подписки + VLESS | — |
| Три IP | панель | подписки | VLESS |

### Шаг 3. Домены

```
Домен панели       [               ]  → должен указывать на 203.0.113.10
Домен подписок     [               ]  → должен указывать на 203.0.113.10
Домен ноды (VLESS) [               ]  → должен указывать на 203.0.113.12
```

- Каждый домен сразу проверяется (A-запись через 1.1.1.1 и 8.8.8.8, ✓/✗ с фактическим IP).
- Если запись ещё не создана, предлагается «Подождать (проверять каждые 10 с)» или «Продолжить, сертификат получу позже».
- Подсказка про имена: не `panel.` и `vpn.`, а нейтральные (`app.`, `static.`, `id.`). Подробно, почему это важно, — STEALTH.md §2.

### Шаг 4. Скрытие

```
Режим доступа к панели и подпискам
  1) Скрытый     (рекомендуется): нестандартный порт, секретный путь, сайт-заглушка на корне
  2) Стандартный: 443, без пути
  3) Настроить вручную
```

В «скрытом» режиме значения генерируются и показываются, их можно поменять:

```
Панель:    https://app.example.com:47321/k9Qm2xT7/
Подписки:  https://static.example.com/s/<token>         (порт 443, префикс /s/)
gRPC нод:  :38211, SNI gw-5c1e.internal
```

Что именно включает каждый режим — STEALTH.md §1.

### Шаг 5. Сертификаты

```
Как получать сертификаты?
  1) HTTP-01 — нужен открытый порт 80                (просто)
  2) DNS-01 через Cloudflare — нужен API-токен       (рекомендуется для скрытого режима:
                                                       wildcard-сертификат, имена поддоменов не видны в CT-логах,
                                                       порт 80 не нужен)
```

Если выбран DNS-01, токен Cloudflare сразу проверяется: есть ли права `Zone.DNS:Edit` на зону.

### Шаг 6. Telegram-бот (основной способ входа)

```
Токен бота (от @BotFather): [ 123456:ABC… ]
  ✓ бот @my_panel_bot найден

Отправьте боту команду:   /start 482913
  ожидание… ✓ привязан админ: Vitya (@vyto4ka, id 1234567)

Добавить ещё админа? [n]
```

- Привязка идёт **кодом из терминала**, поэтому числовой id знать не нужно. Код одноразовый и действует 10 минут. Привязывается тот, кто первым прислал правильный код.
- Шаг можно пропустить. Тогда включается вход по логину и паролю: пароль генерируется и печатается один раз, а бот подключается позже в настройках.

### Шаг 7. Бэкапы

```
Пароль шифрования бэкапов:  1) сгенерировать   2) ввести свой
  → сгенерирован: tundra-velvet-orbit-63-plume
    ЗАПИШИТЕ ЕГО. Без него бэкап не расшифровать.  [понял ✓]
Время ночного бэкапа: [03:00] (часовой пояс Europe/Moscow)
```

### Шаг 8. Профиль ноды (если выбран вариант «панель + нода»)

```
Профиль VLESS для этой ноды:
  1) Reality self-steal       (рекомендуется)
  2) Пропустить — настрою в панели
Код ноды: [NL]   название: [Нидерланды]   (определено по IP, можно поменять)
```

### Шаг 9. Сводка и подтверждение

```
Панель + нода · Ubuntu 24.04
  Панель     app.example.com:47321/k9Qm2xT7/   → 203.0.113.10
  Подписки   static.example.com/s/             → 203.0.113.10
  VLESS_NL   nl.example.com:443 (Reality)      → 203.0.113.12, выход через 203.0.113.12
  Сертификаты: DNS-01 Cloudflare (*.example.com)
  Вход: Telegram @my_panel_bot (1 админ), пароль выключен
  Бэкап: 03:00 → Telegram
Устанавливаем? [Y/n]
```

### Шаг 10. Установка и финал

Прогресс по шагам:
1. Бинари: `xray` и `caddy` со сверкой sha256.
2. Пользователь `vpn`, каталоги, systemd-юниты, sysctl (BBR, fq, TFO).
3. Миграции, внутренний CA, ключи.
4. Caddy и сертификаты.
5. Агент ноды и Reality.
6. Самотест.

В конце:

```
✓ Готово.
Кнопка входа отправлена в Telegram (@my_panel_bot).
Резервная ссылка входа (одноразовая, 10 минут): https://app.example.com:47321/k9Qm2xT7/auth/l/Zp3…
```

## 3. Восстановление из бэкапа (вариант 4 в шаге 0)

Порядок вопросов меняется, потому что часть данных уже есть в бэкапе:

1. **Откуда взять бэкап:**
   - путь к файлу на сервере;
   - «Пришлю файл боту». Мастер спрашивает токен бота, бот ждёт документ от админа из бэкапа. Скачивание идёт через `getFile`, лимит 20 МБ (ARCHITECTURE.md §11.2).
2. **Пароль бэкапа.** Расшифровка, показ содержимого: дата, версия, сколько нод и пользователей.
3. **Сеть.** IP из бэкапа сравниваются с IP этого сервера:
   - если совпадают, ничего не спрашивается;
   - если нет, мастер просит сопоставить старые роли с новыми адресами: «панель была 203.0.113.10 → теперь?» и показывает, какие DNS-записи нужно поменять.
4. **Домены и скрытие** берутся из бэкапа (можно поменять).
5. Сводка, установка. Внешние ноды переподключаются сами, если домен и порт gRPC-шлюза не изменились (ARCHITECTURE.md §11.3).

Неинтерактивно: `vpn install --restore backup.vpnbak --passphrase-file pass.txt`.

## 4. Установка ноды по SSH из панели

### 4.1 Сценарий

«Ноды → Добавить» → способ установки: **[Команда / инструкция]** или **[По SSH]**.

```
Хост         [ 198.51.100.7 ]   Порт [22]   Пользователь [root]
Авторизация  ( ) пароль
             ( ) приватный ключ (вставить)
             (•) ключ панели — добавьте на сервер одну строку:
                 echo 'ssh-ed25519 AAAAC3… vpn-panel' >> ~/.ssh/authorized_keys
☐ Сохранить SSH-доступ для обновлений и диагностики   (по умолчанию выкл)
```

Дальше по шагам. Весь вывод в реальном времени идёт в UI.

1. **Подключение и ключ хоста.** Показывается fingerprint: «SHA256:E6vt…, сравните с панелью хостера или подтвердите». После подтверждения ключ запоминается. Если ключ хоста потом изменится, панель откажется подключаться.
2. **Предпроверка (без изменений на сервере).**
   - ОС, архитектура, RAM, синхронизация времени;
   - **список IP и интерфейсов**;
   - заняты ли порты 80 и 443 и кем;
   - установлен ли Docker, remnanode, nginx.
3. **Форма ноды с уже найденными данными.** Название, страна (по GeoIP адреса), код и домен. IP выбираются из найденного списка: для какого профиля какой адрес (INBOUNDS.md §4). Проверка DNS.
4. **Опции:**
   - `apt upgrade` и перезагрузка (панель дождётся, пока сервер вернётся);
   - остановить мешающий nginx или Docker-контейнер;
   - отключить парольный вход по SSH. Предлагается, только если используется ключ.
5. **Установка.** Панель выпускает install-токен и выполняет на хосте тот же `node.sh`, что и при установке командой (через `sudo`, если пользователь не root). Чеклист тот же: агент → конфиг → сертификат → 443 → самотест.
6. **Финал.** Нода онлайн. Если «сохранить доступ» не отмечен, панель предлагает убрать свой ключ из `authorized_keys` и сама удаляет его.

### 4.2 Реализация

- `golang.org/x/crypto/ssh`, сессия с PTY: вывод скрипта стримится как есть.
- **Задача установки** — запись в `install_jobs`: статус, шаги, лог. Поэтому можно закрыть вкладку и вернуться, а бот пришлёт «✅ Нода NL установлена» или «❌ ошибка на шаге 4» с хвостом лога.
- **SSH-ключ панели** — ed25519, генерируется при установке и хранится зашифрованным `app.key`.
- **Пароль** живёт только в памяти на время задачи, не пишется ни в БД, ни в лог, ни в audit.
- **Сохранённый доступ** (по желанию) — запись в `node_ssh`: хост, порт, пользователь, known_host, приватный ключ зашифрован `app.key`. Даёт кнопки «Переустановить», «Обновить систему» и «Собрать диагностику». Обычное управление идёт через агента, SSH для этого не нужен.
- Исходящее SSH-соединение идёт с исходящего IP панели (INBOUNDS.md §2.5), не с IP VLESS.

### 4.3 Данные

```
install_jobs   id, node_id, method(command|ssh), status(pending|running|ok|failed),
               step, log_text, started_at, finished_at, created_by
node_ssh       node_id, host, port, username, host_key, private_key_enc, created_at   -- только если «сохранить доступ»
```
