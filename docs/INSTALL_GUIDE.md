# Установка

Одна команда под root на сервере открывает меню установщика:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/main/scripts/install.sh)
```

```
  vynel — установка
  На этом сервере сейчас: ничего

  1) Всё на этом сервере: панель + VPN-нода   (проще всего начать с этого)
  2) Только панель (VPN-ноды будут на других серверах)
  3) Только VPN-нода для существующей панели  (нужен токен из панели)
  4) Обновить установленное
  5) Удалить
```

| Что выбрать | Когда |
|-------------|-------|
| **1. Всё на одном сервере** | Один сервер и один домен. Самый простой старт; другие серверы можно подключить потом (пункт 3 на них) |
| **2. Только панель** | Панель отдельно от VPN: на этом сервере пользователи, подписки и веб-панель, VPN — на нодах |
| **3. Только нода** | Ещё один VPN-сервер для уже установленной панели. Готовую команду с токеном показывает панель |
| **4. Обновить** | Свежие vynel, Xray и Caddy. Данные, ключи, логин и пароль сохраняются |
| **5. Удалить** | Убрать службы; по желанию — вместе со всеми данными |

Порядок для первого сервера: [что нужно](#1-что-нужно) → [домен](#2-домен) → [установка](#3-установка-всё-на-одном-сервере) → [первый пользователь](#4-первый-пользователь) → [проверка](#7-проверка). Отдельная панель и ноды — [раздел 5](#5-отдельная-панель-и-ноды), обновление и удаление — [раздел 6](#6-обновление-и-удаление).

## 1. Что нужно

| Что | Зачем |
|-----|-------|
| VPS с **Ubuntu 22.04+ или Debian 11+**, amd64 или arm64, от 1 ГБ RAM | Сервер |
| Доступ **root** по SSH | Установка |
| **Свободные порты 80 и 443** | 443 — VPN и сайт, 80 — выпуск сертификата. На сервере не должно быть nginx, Apache, Remnawave и т.п. Для Hysteria2 нужен ещё UDP 443: установщик открывает его в ufw, firewall хостера проверьте сами. |
| **Домен** (любой, можно поддомен) | Маскировка под сайт и HTTPS для подписок |
| IP сервера доступен из РФ | Если по SSH без VPN подключается — всё хорошо |

Проверить порты: `ss -ltnp '( sport = :80 or sport = :443 )'`. Пустой вывод означает, что порты свободны.

## 2. Домен

Нужна **одна A-запись**: домен (например, `nl.example.com`) → IP сервера. Она создаётся у регистратора домена или в Cloudflare, в разделе DNS.

- Тип: `A`
- Имя: `nl` (или полный `nl.example.com`, в зависимости от регистратора)
- Значение: IP сервера
- В Cloudflare: **серое облако** (DNS only), не оранжевое. Иначе трафик пойдёт через Cloudflare, и Reality работать не будет.

Проверка на сервере: `getent hosts nl.example.com` должна вернуть IP сервера. Иногда запись появляется через несколько минут.

### Сколько доменов нужно

| Вариант | Домены | Что где |
|---------|--------|---------|
| **Минимум** | **1** — `nl.example.com` | VPN (Reality) + сайт-заглушка + подписки по пути `/s/…` |
| По желанию | 2 — `nl.example.com` и `sub.example.com` | Ссылка подписки не совпадает с адресом VPN-сервера |

На одном IP и порту 443 работает всё сразу. Xray принимает VPN-клиентов, а всё остальное (браузеры, загрузку подписки) передаёт в Caddy:

```
:443  → Xray (Reality, SNI nl.example.com)
          ├─ VPN-клиент          → VPN
          └─ всё остальное       → Caddy 127.0.0.1:8443
                                     ├─ /s/<токен> → подписка
                                     └─ остальное  → сайт-заглушка
:80   → Caddy: выпуск сертификата Let's Encrypt, редирект на https
:9443 → подключение дополнительных нод (можно закрыть при установке)
```

Без домена не получится: Let's Encrypt выдаёт сертификаты только на домены, а без сертификата нет ни маскировки, ни HTTPS для подписок.

## 3. Установка: всё на одном сервере

Запустите установщик (команда выше) и выберите **1**. Скрипт задаст вопросы. Enter оставляет значение в скобках:

```
  Публичный IP сервера [31.59.217.217]:
  Домен сервера (A-запись на этот IP; на нём VPN, сайт-заглушка и подписки): nl.example.com
  ✓ nl.example.com → 31.59.217.217
  Отдельный домен для подписок? (не обязательно, одного домена достаточно) [y/N]:
  Email для Let's Encrypt (можно пусто):
  Код страны сервера, для флага в клиентах [NL]:
  Название сервера в клиентах [Нидерланды]:
  Подключать к этой панели другие серверы (ноды) в будущем? Откроет порт 9443 [Y/n]:
  Логин для веб-панели (пароль сгенерируется сам) [admin]:
  Токен бота от @BotFather (Enter — настроить потом):
  Восстановить пользователей и ноды из бэкапа? [y/N]:
  …сводка…
  Устанавливаем? [Y/n]:
```

Что происходит дальше (1–3 минуты):

1. Проверяются DNS и свободные порты.
2. Скачиваются `vynel` (готовая сборка из GitHub), Xray и Caddy.
3. Создаются локальная нода, профиль «Reality» со своими ключами, группа «Основная» и шаблон пользователя «Стандарт» (+3 месяца).
4. Запускается сервис `vynel` (systemd). Ядро настраивается само: BBR, fq, TCP Fast Open.
5. Создаётся админ веб-панели со случайным паролем (только при первой установке).
6. Скрипт ждёт запуска ноды и выпуска сертификата, затем показывает **итоговую таблицу**: адрес веб-панели, логин и пароль, адреса и основные команды.

```
  Веб-панель
    адрес                   https://nl.example.com/k9Qm2xT7aB3c/
    логин                   admin
    пароль                  dzU3LxPNfCNR3F9s
  Сохраните пароль: он показывается один раз. Адрес секретный — без него панель не найти.
```

Установка без вопросов (для автоматизации):

```bash
bash <(curl -fsSL …/install.sh) --mode aio --domain nl.example.com --email you@example.com --yes
# ещё: --sub-domain sub.example.com --name "Нидерланды" --country NL --gateway-listen 127.0.0.1:9443 --admin-login boss
```

> Старая команда `…/install-aio.sh` тоже работает: теперь она запускает этот же установщик.

## 4. Первый пользователь

**В веб-панели:** откройте адрес из таблицы, войдите, затем «Пользователи» → «+ Пользователь» → имя (например `vasya`) → «Создать». Откроется карточка пользователя со ссылкой подписки и кнопкой «Копировать».

**Или в терминале:**

```bash
vynel admin user add vasya
vynel admin user show vasya     # печатает sub url https://nl.example.com/s/…
```

Ссылку подписки:

- **открываешь на телефоне в браузере** — там QR-код и кнопки приложений, первая — KeqDroid (для системы телефона — первыми);
- или **вставляешь в приложение**: «Добавить подписку» / «Импорт из буфера».

Приложение получит сервер «🇳🇱 Нидерланды» и само будет обновлять подписку. Как выглядит страница, какие кнопки на ней и какие заголовки получают приложения — настраивается в панели: «Подписка» ([USER_GUIDE §5](USER_GUIDE.md#5-подписки-и-приложения)).

> По умолчанию у пользователя **до 3 устройств**, и приложение должно передавать HWID. KeqDroid это делает. Если используешь клиент без HWID, включи `vynel admin setting hwid.allow_missing true`.

Продлить, отключить, лимит трафика, устройства — в карточке пользователя в панели или командами из [USER_GUIDE.md](USER_GUIDE.md).

## 5. Отдельная панель и ноды

### Панель

На сервере панели запустите установщик и выберите **2**. Нужны: домен с A-записью на этот сервер (на нём панель, подписки и сайт-заглушка), свободные 80/443 и открытый порт 9443 — к нему подключаются ноды.

```
  Публичный IP сервера [203.0.113.10]:
  Домен панели и подписок (A-запись на этот IP): panel.example.com
  Email для Let's Encrypt (можно пусто):
  Логин для веб-панели (пароль сгенерируется сам) [admin]:
```

В конце — таблица с адресом панели, логином и паролем. Установщик сразу создаёт профиль «Reality», его получат новые ноды.

Без вопросов: `install.sh --mode panel --domain panel.example.com --yes`.

### Нода

1. **В панели:** «Ноды» → «+ Нода» → название (как в приложениях), код страны, домен ноды (A-запись на IP **нового** сервера, в Cloudflare — серое облако), профили (Reality отмечен).
2. Панель покажет команду:

   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/…/scripts/install.sh) --mode node --token vyn1.…
   ```

3. **На новом сервере** (Ubuntu/Debian, root, свободные 80 и 443) выполните её. Установщик поставит vynel, Xray и Caddy, подключит ноду к панели и запустит службу `vynel-node`.
4. Через минуту в панели нода станет «работает». Пользователи групп с доступом к профилю получат новый сервер в подписке сами.

Токен одноразовый и действует 24 часа. Новый — кнопка с ключом у ноды (старый сертификат ноды при этом отзывается). Можно и через меню установщика: пункт **3**, затем вставить токен.

То же самое, когда панель стоит в режиме «всё на одном сервере» и вы хотите добавить второй сервер (при установке на вопрос про другие ноды нужно было ответить «да», чтобы открылся порт 9443).

## 6. Обновление и удаление

- **Telegram-бот** настраивается при установке (токен) или позже в панели «Telegram». После установки в таблице будет ссылка `t.me/бот?start=КОД`: откройте её, чтобы привязать себя ([USER_GUIDE §13](USER_GUIDE.md#13-telegram-бот)).
- **Перенос или восстановление панели** из бэкапа: `--restore файл.tar.gz` (или вопрос в мастере), подробно — [USER_GUIDE §14](USER_GUIDE.md#14-бэкапы-и-восстановление).

- **Обновление:** запустите установщик и выберите **4** (он предложит его сам, если на сервере уже что-то стоит). Или `install.sh --mode update`. Обновляются vynel, Xray и Caddy; пользователи, ключи, настройки, логин и пароль сохраняются. Обновлять нужно каждый сервер: панель и каждую ноду.

  Как устроено обновление:
  - **Ничего лишнего не качается.** Если vynel, Xray или Caddy уже последней версии, установщик пишет «already the latest». Повторное обновление занимает секунды.
  - **Загрузки видны и не зависают.** Каждый файл качается с полосой прогресса. Соединение должно открыться за 20 с. Если данные не идут 30 с, попытка прерывается и повторяется. Медленная, но идущая загрузка докачивается до конца.
  - **Сразу после пуша CI пересобирает релиз** (2–3 минуты). Установщик ждёт его и повторяет попытку раз в 20 с. Сам релиз при пересборке больше не удаляется, поэтому окна «релиза нет» не бывает.
  - **Тихой сборки из исходников при обновлении больше нет.** Если релиз скачать не удалось, установленная версия остаётся и продолжает работать. Установщик подскажет, что делать. Собрать из исходников можно явно: `--build-from-source`.
  - **Если GitHub тормозит или недоступен с сервера,** добавьте зеркало: `install.sh --mode update --gh-proxy https://ghfast.top/`. Переменная `VYNEL_GH_PROXY` работает так же.
  - **Откат.** После перезапуска установщик проверяет, что служба поднялась и не падает. Если новая версия не стартует, возвращается предыдущая (`/usr/local/bin/vynel.prev`), а установщик показывает лог.
  - **apt** при обновлении не запускается, если всё нужное уже стоит. Если apt занят автообновлениями, установщик ждёт до 5 минут, а не висит молча.
- **Удаление:** пункт **5** или `install.sh --mode uninstall`. Скрипт спросит, удалять ли данные; без вопросов: `--mode uninstall --purge --yes` (удаляет и данные, и программы).

## 7. Проверка

| Проверка | Ожидание |
|----------|----------|
| Адрес веб-панели в браузере | Форма входа; после входа — дашборд |
| `https://nl.example.com/` без секретного пути | Сайт-заглушка (панели там не видно) |
| `vynel admin node list` или «Ноды» в панели | Нода в состоянии `in sync` («работает»), проблем нет |
| `https://nl.example.com/` в браузере | Обычный сайт (заглушка) с замком в адресной строке |
| `https://nl.example.com/s/<токен>` в браузере | Страница подписки с QR-кодом |
| Приложение после импорта подписки | Подключается, сайты открываются |
| `vynel admin stats` после пары минут работы | Трафик и онлайн больше нуля |

## 8. Если что-то не так

Сначала посмотри логи: `journalctl -u vynel -e` (последние строки) или `journalctl -u vynel -f` (в реальном времени).

| Симптом | Причина и что делать |
|---------|---------------------|
| Скрипт пишет `ports 80/443 are in use` | Порты занимает другой веб-сервер или VPN. Посмотреть, кто именно: `ss -ltnp '( sport = :80 or sport = :443 )'`. Остановить: `systemctl disable --now nginx` (или что там), затем запустить скрипт заново. |
| `✗ домен → ничего` | Нет A-записи или она ещё не разошлась. Проверь в панели регистратора и подожди несколько минут. |
| Сертификат не выпускается (`does not answer yet`) | DNS указывает не туда; порт 80 закрыт файрволом хостера; в Cloudflare включено оранжевое облако. Caddy повторяет попытки сам: после исправления подожди пару минут. |
| `node list`: `offline` / `syncing` | `journalctl -u vynel -e`. Перезапуск: `systemctl restart vynel`. |
| PROBLEMS: `net.core.default_qdisc=…` | Ядро не дало включить fq/BBR (бывает на OpenVZ/LXC). VPN работает и без этого. |
| В приложении сервер «⛔ Лимит устройств 3/3» | Освободить место: `vynel admin user devices vasya`, затем `… --rm ID`. Или поднять лимит: `vynel admin setting hwid.default_limit 5`. |
| «⛔ Приложение не передаёт HWID» | Клиент без HWID. Используй KeqDroid, выключи HWID пользователю в его карточке или `vynel admin setting hwid.allow_missing true`. |
| «⛔ Подписка истекла» / «Трафик исчерпан» | `vynel admin user extend vasya --months 1` / `vynel admin user reset vasya`. |
| Подписка открывается, VPN не подключается | Проверь, что IP сервера не заблокирован (SSH без VPN), что часы сервера синхронизированы (`timedatectl`) и что в Cloudflare серое облако. |
| Забыли адрес или пароль панели | `vynel admin web` — адрес и логин, `vynel admin web password` — новый пароль |
| Панель пишет «the web UI is not built into this binary» | vynel собран из исходников без фронтенда (готовый релиз не скачался). Запустите установщик ещё раз, когда релиз появится, или соберите с `make web build` |
| Нода не подключается к панели (`the panel did not accept the token`) | Токен уже использован или старше 24 часов — выпустите новый (кнопка с ключом у ноды). На панели должен быть открыт порт 9443: `ss -ltn | grep 9443`, файрвол хостера. |
| Нода «нет связи» в панели | На ноде: `journalctl -u vynel-node -e`, перезапуск `systemctl restart vynel-node`. Если панель переехала на другой IP: `vynel node set-panel НОВЫЙ_IP:9443`. |
| `this server runs the panel…` при установке ноды | На сервере уже стоит панель (80/443 заняты). Нода ставится на другой сервер; чтобы VPN был и на сервере панели — режим «всё на одном сервере». |
| Нужно начать с нуля | `install.sh --mode uninstall --purge --yes`, затем установить заново. |

## 9. Где что лежит

| Путь | Что |
|------|-----|
| `/var/lib/vynel/panel.db` | База: пользователи, ноды, статистика |
| `/var/lib/vynel/ca/` | Внутренние сертификаты для связи с нодами |
| `/var/lib/vynel/backups/` | Последние 7 ночных бэкапов |
| `/var/lib/vynel/node/` | Локальная нода: конфиг Xray, сертификаты Caddy, сайты-заглушки |
| `/etc/systemd/system/vynel.service` | Служба панели (`journalctl -u vynel`) |
| `/var/lib/vynel-node/` | Отдельная нода: сертификат для связи с панелью, состояние |
| `/etc/systemd/system/vynel-node.service` | Служба отдельной ноды (`journalctl -u vynel-node`) |
| `/usr/local/bin/{vynel,xray,caddy}` | Программы |

**Бэкап**: каждый вечер в Telegram, кнопкой в панели или `vynel admin backup`; восстановление — `--restore` у установщика или `vynel restore` ([USER_GUIDE §14](USER_GUIDE.md#14-бэкапы-и-восстановление)).
