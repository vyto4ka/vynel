# Установка

То же в виде страницы с вкладками: [руководство](https://raw.githack.com/vyto4ka/vynel/main/docs/guide.html).

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/main/scripts/install.sh)
```

Команда под root на сервере открывает меню установщика:

| Пункт | Когда |
|-------|-------|
| **Всё на этом сервере** | Один сервер и один домен. Самый простой старт; другие серверы можно подключить потом |
| **Только панель** | Пользователи, подписки и веб-панель здесь, а серверы для клиентов — на других машинах (нодах) |
| **Только нода** | Ещё один сервер для уже установленной панели. Готовую команду с токеном выдаёт панель: «Ноды» → «+ Нода» |
| **Обновить** | Свежие vynel, Xray и nginx. Данные, ключи, логин и пароль сохраняются |
| **Защитить сервер** | Файрвол, SSH только по ключу, SSH на другой порт — без переустановки |
| **Удалить** | Убрать службы; по желанию — вместе со всеми данными |

---

## 0. Шаг ноль: что нужно заранее

| Что | Какое |
|-----|-------|
| **Сервер (VPS)** | Ubuntu 22.04+ или Debian 11+, amd64 или arm64, от 1 ГБ RAM, доступ root по SSH. Лучше чистый: без другого веб-сервера, 3x-ui, Remnawave. У хостера должны быть открыты TCP 80, 443 и UDP 443 |
| **Домен** | Любой, можно поддомен (`nl.example.com`). Без домена нет сертификата, а без него — ни маскировки, ни HTTPS для подписок |

**Проверьте, что IP сервера не заблокирован.** Подключитесь по SSH с выключенным VPN, из той сети, где будут пользоваться:

```bash
ssh root@203.0.113.10
```

Пустил или спросил пароль — всё хорошо. Висит и падает по таймауту, хотя через VPN подключается, — IP заблокирован у провайдера: попросите у хостера другой IP или возьмите другой сервер.

## 1. Домен

Нужна **одна A-запись**: домен (например, `nl.example.com`) → IP сервера. Её создают там, где у домена DNS: у регистратора или в Cloudflare.

- Тип `A`, имя `nl` (или полное `nl.example.com` — как принято у регистратора), значение — IP сервера.
- В Cloudflare облако **серое** (DNS only). С оранжевым Reality не работает и сертификат не выпускается.

Ждать с проверками не нужно: установщик сам показывает под полем домена, куда тот сейчас указывает.

Второй домен не обязателен. По желанию подпискам и панели можно дать свой (`sub.example.com`) на том же сервере: тогда ссылка подписки не совпадает с адресом, к которому подключаются клиенты. Как всё делит один порт 443 — [INBOUNDS.md §2.3](INBOUNDS.md).

## 2. Установка: всё на одном сервере

Запустите команду выше и выберите **«Всё на этом сервере»**. В большинстве полей уже стоит подходящее значение (серым) — его оставляет **Enter**. **Tab** / **Shift+Tab** — по полям, **Пробел** — галочка, **Esc** — выйти, ничего не установив (ответы запомнятся до следующего запуска).

### Сервер и домены

| Поле | Что это |
|------|---------|
| Публичный IP | Определяется сам. Если адресов несколько, форма спросит, какой отдать клиентам, а какой — панели и подпискам: блокировка одного не заденет другой |
| Домен сервера | Домен из шага 1. Под полем видно, куда он указывает: `✓ nl.example.com → 203.0.113.10` или что не так |
| Отдельный домен подписок и панели | Обычно пусто. Второй домен на этот же сервер для ссылок подписок и панели |
| Email для Let's Encrypt | На него придёт письмо, если продление сертификата сломается. Можно оставить предложенный `admin@<домен>` |

### Панель

| Поле | Что это |
|------|---------|
| Код страны, название | Флаг и имя сервера в приложениях. Определяются по IP — можно не трогать |
| Подключать другие серверы? | «Да» откроет порт 9443 для будущих нод (только их адресам). Если сервер будет один — «Нет» |
| Путь ссылок подписки | Начало ссылки: `https://домен/s/…`. Оставьте `/s/` |
| Секретный путь панели | Адрес панели, по умолчанию случайный. На любом другом пути — сайт-заглушка, так что путь — такой же секрет, как пароль |
| Вход в панель | **Логин и пароль**; **только по одноразовой ссылке** (`/login` в боте или `vynel admin login-link`, по желанию — со случайным адресом на каждую сессию); **только через Telegram** (кнопка «Панель» в боте). Меняется потом в «Аккаунте» |
| Логин | По умолчанию `admin`. Пароль генерируется и показывается в конце |
| Токен Telegram-бота | По желанию, от [@BotFather](https://t.me/BotFather): бэкапы, уведомления, вход без пароля. Можно добавить позже |
| Восстановить из бэкапа | Обычно пусто. Путь к файлу бэкапа при переезде |

### Безопасность

| Галочка | Что делает |
|---------|------------|
| Файрвол | Открыты только SSH и порты vynel, сканеры портов блокируются (§10). Рекомендуется |
| SSH только по ключу | Выключает вход по паролю. Предлагается, только если ключи на сервере уже есть |
| SSH на случайный порт | Старый порт закроется только после того, как вы проверите вход по новому из другого окна |

Последний экран показывает, что будет сделано. «Установить» — 1–3 минуты: пакеты, vynel, Xray, nginx, сертификат, запуск. Создаются нода, профиль «Reality», группа «Основная» и шаблон пользователя «Стандарт» (+3 месяца). Полный лог — `/var/log/vynel-install.log`.

В конце — адрес панели, логин и пароль. **Сохраните их**: пароль показывается один раз.

```
  Веб-панель
    адрес                   https://nl.example.com/k9Qm2xT7aB3c/
    логин                   admin
    пароль                  dzU3LxPNfCNR3F9s
```

Забыли адрес — `vynel admin web`, пароль — `vynel admin web password` выдаст новый.

## 3. После установки

Откройте адрес панели и войдите. В разделе «Ноды» сервер должен быть зелёным, без проблем; то же в терминале — `vynel admin node list` (`in sync`, проблем нет). Если что-то не так — [§8](#8-если-что-то-не-так).

## 4. Первый пользователь

«Пользователи» → «+ Пользователь» → имя (например `vasya`) → «Создать». Срок, группа и лимиты берутся из шаблона по умолчанию. Откроется карточка со ссылкой подписки, QR-кодом и кнопкой «Копировать».

Ссылку открывают на телефоне — там QR-код и кнопки приложений, первая — [KeqDroid](https://github.com/Lemonochka/keqdroid/releases/latest), — или вставляют в приложение: «Добавить подписку». Название подписки и ссылку на поддержку стоит один раз поправить в «Подписка» → «Основное».

> По умолчанию пользователь может быть подключён с 3 адресов одновременно, число устройств не ограничено — поэтому приложения без HWID тоже пускаются и получают подписку ссылками. Если задать лимит устройств, клиенту без HWID: выключите «Проверять HWID» в карточке пользователя или `vynel admin setting hwid.allow_missing true`.

Продлить, отключить, лимиты, устройства — в карточке пользователя или командами из [USER_GUIDE.md](USER_GUIDE.md).

## 5. Отдельная панель и ноды

### Панель

На сервере панели запустите установщик и выберите **2**. Нужны: домен с A-записью на этот сервер (на нём панель, подписки и сайт-заглушка), свободные 80/443 и открытый порт 9443 — к нему подключаются ноды.

```
  Публичный IP сервера [203.0.113.10]:
  Домен панели и подписок (A-запись на этот IP): panel.example.com
  Email для Let's Encrypt (можно пусто):
  Логин для веб-панели (пароль сгенерируется сам) [admin]:
```

В конце — таблица с адресом панели, логином и паролем. Установщик сразу создаёт профиль «Reality», его получат новые ноды.

Без вопросов: `install.sh --mode panel --domain panel.example.com --yes`.

### Нода

1. **В панели:** «Ноды» → «Добавить сервер» → домен ноды (A-запись на IP **нового** сервера, в Cloudflare — серое облако), профили (Reality отмечен). Название и код страны можно не заполнять: установщик ноды определит страну по IP сервера, и панель подставит флаг, название («Германия») и код ноды (`DE`, теги `VLESS_DE`).
2. Панель покажет команду:

   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/vyto4ka/vynel/…/scripts/install.sh) --mode node --token vyn1.…
   ```

3. **На новом сервере** (Ubuntu/Debian, root, свободные 80 и 443) выполните её. Установщик поставит vynel, Xray и nginx, подключит ноду к панели и запустит службу `vynel-node`. Порт 9443 панели откроется для этой ноды сам: пока токен не использован, он открыт всем, потом — только адресам нод.
4. Через минуту в панели нода станет «работает». Пользователи групп с доступом к профилю получат новый сервер в подписке сами.

Токен одноразовый и действует 24 часа. Новый — кнопка с ключом у ноды (старый сертификат ноды при этом отзывается). Можно и через меню установщика: пункт **3**, затем вставить токен.

То же самое, когда панель стоит в режиме «всё на одном сервере» и вы хотите добавить второй сервер (при установке на вопрос про другие ноды нужно было ответить «да», чтобы открылся порт 9443).

## 6. Обновление и удаление

- **Telegram-бот** настраивается при установке (токен) или позже в панели «Telegram». После установки в таблице будет ссылка `t.me/бот?start=КОД`: откройте её, чтобы привязать себя ([USER_GUIDE §13](USER_GUIDE.md#13-telegram-бот)).
- **Перенос или восстановление панели** из бэкапа: `--restore файл.tar.gz` (или вопрос в мастере), подробно — [USER_GUIDE §14](USER_GUIDE.md#14-бэкапы-и-восстановление).

- **Обновление из панели.** Панель раз в полчаса сверяет свою версию и версии нод с релизом, из которого их ставили. Если есть новая, на дашборде появляется баннер, а у «Нод» значок с числом устаревших серверов.
  - **«Обновить всё»** (на дашборде или «Обновить все» в «Нодах») запускает обновление на всех устаревших нодах **одновременно**, панель — последней. Около минуты подключения не работают, потом всё поднимается само. Страница панели переподключится сама.
  - **Одну ноду** обновляет меню «⋮» → «Обновить».
  - **Ход обновления виден сразу.** На карточке ноды и в баннере дашборда: «команда отправлена» → «обновляется · 0:42» → «перезапускается» → «обновлено» или «обновление не удалось». Нода присылает его сама каждые 2 секунды вместе с последними строками лога. Клик по плашке (или «⋮» → «Лог обновления») открывает лог, он обновляется на глазах. Если нода за 2 минуты так и не сообщила, что начала, панель покажет ошибку: значит, версия на ноде слишком старая для обновления из панели.
  - Если обновление не удалось, плашка у ноды (или в баннере дашборда) станет красной «обновление не удалось»; по клику — лог. Если новая версия не запустилась, работает прежняя. Лог на сервере: `/var/log/vynel-update.log`.
  - Ноды, поставленные до этой версии, команду из панели не понимают: их нужно один раз обновить установщиком.
- **Обновление на сервере:** `vynel update` (идёт в фоне, следить: `journalctl -u vynel-update -f`), `vynel update --foreground` (здесь и сейчас), `vynel update --check` (только сравнить версии). Или запустите установщик и выберите **4** (он предложит его сам, если на сервере уже что-то стоит), или `install.sh --mode update`. Обновляются vynel, Xray и nginx; пользователи, ключи, настройки, логин и пароль сохраняются. Перед обновлением панели делается бэкап базы в `/var/lib/vynel/backups/pre-update-<дата>.tar.gz`. С Caddy на nginx сервер переходит при обычном обновлении — [MIGRATION_NGINX.md](MIGRATION_NGINX.md). Откуда брать обновления (ветка, релиз, зеркало GitHub), установщик записывает в `/etc/vynel/install.env`.

  Как устроено обновление:
  - **Ничего лишнего не качается.** Если vynel или Xray уже последней версии, установщик пишет «already the latest». Повторное обновление занимает секунды.
  - **Загрузки видны и не зависают.** Каждый файл качается с полосой прогресса. Соединение должно открыться за 20 с. Если данные не идут 30 с, попытка прерывается и повторяется. Медленная, но идущая загрузка докачивается до конца.
  - **Сразу после пуша CI пересобирает релиз** (2–3 минуты). Установщик ждёт его и повторяет попытку раз в 20 с. Сам релиз при пересборке больше не удаляется, поэтому окна «релиза нет» не бывает.
  - **Тихой сборки из исходников при обновлении больше нет.** Если релиз скачать не удалось, установленная версия остаётся и продолжает работать. Установщик подскажет, что делать. Собрать из исходников можно явно: `--build-from-source`.
  - **Если GitHub тормозит или недоступен с сервера,** добавьте зеркало: `install.sh --mode update --gh-proxy https://ghfast.top/`. Переменная `VYNEL_GH_PROXY` работает так же.
  - **Откат.** После перезапуска установщик проверяет, что служба поднялась и не падает. Если новая версия не стартует, возвращается предыдущая (`/usr/local/bin/vynel.prev`), а установщик показывает лог.
  - **apt** при обновлении не запускается, если всё нужное уже стоит. Если apt занят автообновлениями, установщик ждёт до 5 минут, а не висит молча.
- **Удаление:** пункт «Удалить» или `install.sh --mode uninstall`. Файрвол vynel при этом снимается. Скрипт спросит, удалять ли данные; без вопросов: `--mode uninstall --purge --yes` (удаляет и данные, и программы).

- **Проверка релиза.** Установщик сверяет SHA-256 каждого скачанного бинаря. Если в установщике задан ключ подписи релизов (`scripts/release-key.sh`), он проверяет ещё и подпись Ed25519 файла с контрольными суммами. Бинарь с неподходящей подписью не ставится, даже если он пришёл через `--gh-proxy`. С ключом `vynel update` и обновление из панели запускают установщик только из подписанного релиза: подпись не сошлась — обновление останавливается. Xray сверяется с его `.dgst` с GitHub.

## 7. Проверка

| Что открыть | Что увидеть |
|-------------|-------------|
| Адрес веб-панели | Форма входа; после входа — дашборд, нода зелёная |
| `https://nl.example.com/` | Обычный сайт (заглушка) с замком; панели там не видно |
| Ссылка подписки в браузере | Страница с QR-кодом и кнопками приложений |
| Приложение после импорта подписки | Подключается, сайты открываются |

## 8. Если что-то не так

Сначала посмотри логи: `journalctl -u vynel -e` (последние строки) или `journalctl -u vynel -f` (в реальном времени).

| Симптом | Причина и что делать |
|---------|---------------------|
| Скрипт пишет `ports 80/443 are in use` | Порты занимает другой веб-сервер или VPN. Посмотреть, кто именно: `ss -ltnp '( sport = :80 or sport = :443 )'`. Остановить: `systemctl disable --now nginx` (или что там), затем запустить скрипт заново. |
| `✗ домен → ничего` | Нет A-записи или она ещё не разошлась. Проверь в панели регистратора и подожди несколько минут. |
| Сертификат не выпускается (`does not answer yet`) | DNS указывает не туда; порт 80 закрыт файрволом хостера; в Cloudflare включено оранжевое облако. Нода повторяет попытки сама (сначала через минуту, потом реже): после исправления подожди пару минут или перезапусти службу. Ход выпуска и причина ошибки: `journalctl -u vynel \| grep certificate` (на отдельной ноде — `-u vynel-node`). |
| `node list`: `offline` / `syncing` | `journalctl -u vynel -e`. Перезапуск: `systemctl restart vynel`. |
| PROBLEMS: `net.core.default_qdisc=…` | Ядро не дало включить fq/BBR (бывает на OpenVZ/LXC). VPN работает и без этого. |
| В приложении сервер «⛔ Превышен лимит подключений: 4/3» | Слишком много адресов сразу. Лишние отпустятся сами, когда отключатся другие устройства; поднять лимит: в карточке пользователя или `vynel admin setting ip.default_limit 5`. |
| В приложении сервер «⛔ Лимит устройств 3/3» | Освободить место: `vynel admin user devices vasya`, затем `… --rm ID`. Или поднять лимит: `vynel admin setting hwid.default_limit 5`. |
| «⛔ Приложение не передаёт HWID» | Клиент без HWID при заданном лимите устройств (без лимита его пускают ссылками). Используй KeqDroid, поставь лимит устройств 0, выключи HWID пользователю в его карточке или `vynel admin setting hwid.allow_missing true`. |
| «⛔ Подписка истекла» / «Трафик исчерпан» | `vynel admin user extend vasya --months 1` / `vynel admin user reset vasya`. |
| Подписка открывается, VPN не подключается | Проверь, что IP сервера не заблокирован (SSH без VPN), что часы сервера синхронизированы (`timedatectl`) и что в Cloudflare серое облако. |
| Забыли адрес или пароль панели | `vynel admin web` — адрес и логин, `vynel admin web password` — новый пароль |
| Панель пишет «the web UI is not built into this binary» | vynel собран из исходников без фронтенда (готовый релиз не скачался). Запустите установщик ещё раз, когда релиз появится, или соберите с `make web build` |
| Нода не подключается к панели (`the panel did not accept the token`) | Токен уже использован или старше 24 часов — выпустите новый (кнопка с ключом у ноды). На панели должен быть открыт порт 9443: `ss -ltn | grep 9443`, файрвол хостера. |
| Нода «нет связи» в панели | На ноде: `journalctl -u vynel-node -e`, перезапуск `systemctl restart vynel-node`. Если панель переехала на другой IP: `vynel node set-panel НОВЫЙ_IP:9443`. |
| `this server runs the panel…` при установке ноды | На сервере уже стоит панель (80/443 заняты). Нода ставится на другой сервер; чтобы VPN был и на сервере панели — режим «всё на одном сервере». |
| Нужно начать с нуля | `install.sh --mode uninstall --purge --yes`, затем установить заново. |

## 10. Защита сервера

Цель — чтобы снаружи сервер выглядел как обычный веб-сервер: SSH, сайт на 80/443 и больше ничего. Установщик включает защиту при установке, а для уже работающего сервера есть пункт меню **5 «Защитить сервер»** (`install.sh --mode harden`).

### Файрвол

`vynel firewall on` — свой набор правил nftables (таблица `inet vynel`; правила ufw и Docker не трогаются).

- **Открыто только нужное.** SSH на всех портах, где он слушает. Инбаунды Xray: TCP, а Hysteria2 — UDP. Сайты nginx: 80 и 443, свой порт панели, если задан. На панели — ещё порт для нод (9443), но **только для адресов нод**: панель запоминает, откуда подключается каждая нода. Открыт всем, пока ждёт неиспользованный токен установки или нода ещё ни разу не подключилась после обновления. Нода сменила IP и не может подключиться: `vynel firewall gateway open`, после подключения — `vynel firewall gateway nodes`.
- **Порты vynel знает сам.** Он берёт их из конфигурации, которую нода выполняет. Добавили инбаунд на другом порту или перенесли панель — порт откроется сам, закрытый — закроется. Ручной список не нужен.
- **Остальное молчит.** Пакеты на закрытые порты отбрасываются без ответа: сканер не отличит такой порт от отсутствующего хоста. Даже сервис, случайно слушающий наружу (база данных, почта), снаружи не виден.
- **Сканеры портов.** Адрес, который за минуту стучится больше чем в 20 закрытых портов, блокируется на сутки целиком, вместе с 443. Сканер видит «мёртвый» сервер.
- **Свои не блокируются никогда.** «Свои» — это адреса, которые доказали, что они ваши:
  - успешный вход по SSH за последние сутки (по журналу sshd);
  - открытая сессия веб-панели;
  - подключение к VPN своим ключом.

  Для них закрытые порты просто молчат, без бана, и лимит SSH на них не действует. Иначе браузер, который ломится на только что сменённый порт панели, или клиент, проверяющий «пинг» всех серверов подписки, забанил бы самого админа.
- **SSH.** Новые подключения ограничены 10 в минуту с одного адреса (кроме своих): перебор паролей захлёбывается. Уже открытые сессии файрвол не трогает никогда, правила меняются одной транзакцией.
- **Ping.** Отвечает, с ограничением 5 в секунду, как обычный сервер. Остальное ICMP, что выдаёт систему (timestamp и т.п.), не отвечается.
- **Ядро.** SYN cookies, без ICMP-редиректов и source routing, без ответа на broadcast ping (вместе с BBR в `/etc/sysctl.d/90-vynel.conf`).

```bash
vynel firewall status            # что открыто, сколько сканеров заблокировано
vynel firewall allow 8080 5000/udp   # открыть свои порты (для своих сервисов)
vynel firewall deny 8080
vynel firewall unblock 198.51.100.7  # снять блокировку (или all)
vynel firewall on --no-trap --no-ping   # без блокировки сканеров / без ответа на ping
vynel firewall off               # выключить и сразу снять правила
```

Если что-то перестало открываться — сначала `vynel firewall status`, на крайний случай `vynel firewall off`. В `vynel node diag` есть раздел «firewall».

**Если заблокировало вас самих** (сервер перестал отвечать на всё сразу), есть три способа:
- **Telegram-бот:** «🧱 Файрвол» → «Разблокировать всех» или «Выключить файрвол». Бот работает с сервера, ему блокировка не мешает.
- **С другого адреса:** блокировка по IP, поэтому подойдёт мобильный интернет или другой VPN. Дальше `vynel firewall unblock all`.
- **Консоль хостера (VNC):** `vynel firewall off`.

Блокировка снимается сама через сутки.

> Внешний файрвол хостера (security groups) — отдельная вещь: в нём тоже должны быть открыты 80, 443 (TCP и UDP для Hysteria2), SSH и на панели 9443.

### SSH

- **Только по ключу.** Установщик предлагает выключить вход по паролю, только если на сервере уже есть ключи (`~/.ssh/authorized_keys`). Без ключа вы бы себя заперли, поэтому вопрос тогда не задаётся. Заодно: `MaxAuthTries 3`, `LoginGraceTime 30`, root — только по ключу.
- **Другой порт.** Боты перебирают пароли на 22; на случайном высоком порту их почти нет. Порт меняется безопасно:
  - новый открывается **рядом** со старым;
  - установщик просит проверить вход по новому порту из другого окна;
  - только после «да» 22 закрывается;
  - «нет» или потеря связи — порт остаётся прежним.

  Без терминала (`--yes`) открыты оба порта; закрыть старый: `install.sh --mode harden --ssh-port НОВЫЙ`.
- Настройки лежат в `/etc/ssh/sshd_config.d/90-vynel.conf`. Перед применением конфиг проверяется (`sshd -t`), с ошибкой он не применяется.

### Несколько IP

- **При установке.** На сервере с несколькими IP установщик спрашивает, какой отдать VPN, а какой — панели и подпискам. Доменам нужны A-записи на соответствующие адреса. Заблокируют IP VPN — панель на другом IP продолжит работать, и наоборот.
- **Добавить IP позже:**

  ```bash
  vynel net list                      # адреса на интерфейсах
  vynel net add-ip 203.0.113.12       # добавить; откатится, если не подтвердить за 60 с
  vynel net rm-ip 203.0.113.12
  ```

  `add-ip` работает как `netplan try`:
  - адрес добавляется сразу, и проверяется, что трафик с него выходит в интернет;
  - нужно ответить `yes`; потеряли связь или не ответили за 60 секунд — адрес убирается;
  - подтверждённый адрес переживает перезагрузку (служба `vynel-ips`), и панель видит его через минуту.

  Дальше в панели: «Ноды» → инбаунд → «Настроить» → IP входа.
