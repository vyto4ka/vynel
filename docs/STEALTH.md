# Скрытие и вход через Telegram

> **Проектный документ.** Сейчас реализованы: сайты-заглушки, ответ заглушкой на неверный токен и бан перебора, настраиваемый префикс подписок, отсутствие заголовка `Server`, строгий SNI на шлюзе нод, **секретный путь веб-панели**, **свой порт, IP и заглушка панели** (`web.port`, `web.address`, `web.decoy`, кнопка «Случайный порт и новый путь»), **выключатель страницы подписки** (`sub.page_enabled`), **вход через Telegram** (§3.2: одноразовая ссылка — 60 с, один раз, токен во фрагменте URL, хранится только хэш; Mini App с проверкой `initData`), **режимы входа** (§3.0: пароль, только одноразовая ссылка, только Telegram Mini App; случайный адрес на каждую сессию), **сессии на сервере** (§3.3: список, завершение, уведомление о входе в бот). Остальное (DNS-01, режим «только через VPN», подтверждение опасных действий) — этап 13.

Задача: снаружи сервер не должен выглядеть как VPN-панель. Сканер IP, случайный посетитель домена или человек со ссылкой на подписку не должны найти ни панель, ни её следы. Админ при этом входит в один клик из Telegram.

---

## 1. Режимы

| Механизм | Стандартный | Скрытый (по умолчанию в мастере) |
|----------|-------------|----------------------------------|
| Порт панели | 443 | случайный 20000–60000 (например `47321`) |
| Секретный путь панели | — | `/k9Qm2xT7/` (8–16 символов) |
| Корень домена панели | редирект на вход | сайт-заглушка |
| Порт подписок | 443 | 443 (нужен клиентам, обычно его оставляют) или свой |
| Префикс подписок | `/sub/` | настраиваемый: `/s/`, `/api/v1/client/` или случайный |
| Неизвестный путь, неверный токен | 404 панели | ответ сайта-заглушки |
| TLS без нужного SNI | — | обрыв рукопожатия |
| Сертификаты | HTTP-01 | DNS-01 wildcard (если есть Cloudflare) |
| Форма логина | есть | **нет** (только Telegram) |
| HTML-страница подписки | вкл | вкл (можно выключить) |
| Порт gRPC нод | 9443 | случайный + обязательный SNI |

Каждый механизм включается отдельно в «Система → Настройки». Мастер установки только выставляет набор по умолчанию.

## 2. Механизмы подробно

### 2.1 Нестандартные порты

- Панель, подписки и gRPC-шлюз слушают любой `IP:порт`. Сочетание ролей и IP описано в INBOUNDS.md §2.
- Резолвер портов (INBOUNDS.md §2.3) учитывает свои порты. Например, панель на `IP1:47321` и подписки на `IP1:443` — это разные `(IP, порт)` без конфликтов.
- Если панель и подписки на одном `IP:порт`, nginx разводит их по SNI. Если там же Reality, 443 занимает `stream {}` nginx: имя Reality → Xray, остальное → сайты (INBOUNDS.md §2.3).
- Если на `IP:443` стоит Reality, панель на высоком порту того же IP слушает отдельно, Reality её не касается.
- Firewall: установщик открывает только реально используемые порты.

### 2.2 Секретный путь

```
https://app.example.com:47321/k9Qm2xT7/          → панель (SPA собрана с base path)
https://app.example.com:47321/k9Qm2xT7/api/...   → API
https://app.example.com:47321/                    → сайт-заглушка
https://app.example.com:47321/anything            → 404 сайта-заглушки
```

- Путь задаётся при установке и меняется в настройках. После смены бот сразу присылает новую кнопку входа.
- Cookie сессии ставится с `Path=/k9Qm2xT7/`, `Secure`, `HttpOnly`, `SameSite=Strict`.
- Ни один ответ вне секретного пути не выдаёт панель: нет её HTML, JS, favicon и характерных заголовков. Заголовки `Server` и `Via` убраны.

### 2.3 Сайт-заглушка

Это тот же набор статичных сайтов, что и для Reality self-steal (PROFILES.md §3.4). Пять многостраничных сайтов: облачное хранилище (cloud), дизайн-студия (studio), документация (docs), обжарщики кофе (coffee), личный блог (journal). На каждом 4–6 страниц с адресами без `.html` (`/pricing`, `/posts/…`), favicon, `robots.txt` и своя страница 404. Ноде и новой панели сайт выбирается случайно.

Встроенный сайт выбирается отдельно для домена панели и домена подписок, чтобы они не выглядели одинаково. Вместо встроенного сайта на любой управляемой (не `manual`) ноде можно подключить свой HTML-сайт.

**Где задаётся путь и какой приоритет:**

- **Уровень ноды** (основной способ): карточка ноды → «Изменить» → поле **«Своя HTML-заглушка»** (`decoyPath`). Применяется ко всем сайтам этой ноды (self-steal, XHTTP). Для локальной ноды панели этот же путь используется для домена панели и домена подписок (на странице «Настройки» рядом с выбором заглушки есть прямая ссылка в настройки ноды панели).
- **Уровень инбаунда** (переопределение): переменная `DECOY_PATH` в шаблонах `vless-reality-selfsteal` и `vless-xhttp-reality-std`. Если задана у конкретного инбаунда, она перекрывает путь ноды только для этого сайта.
- Если оба поля пустые, отдаётся встроенный сайт (`DECOY_SITE` / `web.decoy` / `sub.decoy`).

#### Требования к своему сайту-заглушке

Выполнение этих требований гарантирует, что своя заглушка корректно откроется в браузере и не сломает веб-сервер, сертификаты и трафик инбаундов:

1. **Только статика, без собственного веб-сервера и портов.** Заглушку отдаёт встроенный nginx/Caddy агента ноды на существующем локальном self-steal порту (`127.0.0.1:${SELFSTEAL_PORT}`, по умолчанию `8443`). Не запускайте рядом свой nginx/Caddy/Docker-контейнер на `:80`, `:443` или `:8443` — иначе возникнет конфликт портов (для собственного веб-стека используйте `manual`-режим ноды).
2. **Файлы должны лежать на диске самой ноды.** Панель не копирует файлы на удалённые ноды, а передаёт в конфиг только путь. На каждую ноду статику нужно разложить самостоятельно (`rsync`, `scp`, Ansible и т. п.). Для локальной ноды панель проверяет наличие пути на диске сразу при сохранении, для удалённой проверяется только формат пути.
3. **Безопасный абсолютный путь.**
   - Путь обязан начинаться с `/` (например, `/var/www/site` или `/var/www/stub.html`).
   - Запрещены пробелы, переводы строк, `;`, `{`, `}`, `"`, `'`, `\`, `$`, сегменты `..`, корень `/` и системные каталоги: `/etc`, `/proc`, `/sys`, `/dev`, `/root`, `/boot`, `/run`, `/var/lib/vynel`.
   - При указании в переменной инбаунда `DECOY_PATH` не ставьте `/` на конце (в поле ноды лишний слэш обрезается автоматически).
4. **Структура файлов:**
   - **Папка:** обязателен `index.html` в корне. Рекомендуется добавить `404.html` (nginx при его отсутствии вернёт `index.html`, а Caddy отдаст пустой 404). Поддерживаются чистые адреса: запрос `/about` найдёт `about.html` или `about/index.html`.
   - **Одиночный файл:** должен иметь расширение `.html` или `.htm`. На любой путь веб-сервер отдаст этот файл.
5. **Права доступа на диске.** Воркеры nginx обычно работают под `www-data` или `nginx`, поэтому у этого пользователя должно быть право чтения на файлы и право входа (`+x`) на все родительские каталоги, начиная от `/`. Не кладите сайт в `/root` или домашний каталог с правами `700`. Рекомендуемое размещение: `/var/www/<name>` с правами:
   ```bash
   chmod -R a+rX /var/www/site
   ```
6. **Ограничения `Content-Security-Policy` (CSP).** На всех сайтах-заглушках веб-сервер выставляет заголовок:
   `default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; base-uri 'none'; frame-ancestors 'self'`
   Поэтому:
   - все стили, скрипты, шрифты и картинки держите локально внутри папки заглушки (внешние CDN вроде Google Fonts или jsDelivr браузер заблокирует);
   - не используйте inline-скрипты (`<script>...</script>` и обработчики `onclick=...`), выносите JS в отдельный файл в той же папке (inline-стили `<style>` и `data:`-картинки разрешены).
7. **Не пересекайтесь с маршрутами панели и подписок.** Если на локальной ноде панель и подписки живут на том же домене, что и заглушка, пути префикса подписок (например, `/s/`) и секретного пути панели имеют более высокий приоритет и перехватываются панелью раньше статики. Не храните ассеты заглушки по тем же префиксам.
8. **Влияние на трафик и проверка после установки.** Смена пути заглушки не меняет конфиг Xray и не перезапускает его, а nginx перед `reload` проверяет конфиг через `nginx -t`. Если на ноде рядом с Reality работает Hysteria2, по TCP 443 отдаётся кастомная заглушка, а по UDP 443 (`masquerade` самой Hysteria2) остаётся встроенный `DECOY_SITE`. После настройки проверьте на ноде:
   ```bash
   curl -i --resolve example.com:443:127.0.0.1 https://example.com/
   curl -i --resolve example.com:443:127.0.0.1 https://example.com/nonexistent-check
   ```
   Первый запрос должен вернуть `200 OK` с вашим HTML (не `403 Forbidden`), второй — `404` со страницей заглушки, а в панели у ноды не должно быть новых проблем.


### 2.4 Подписки

```
https://static.example.com/s/<sub_token>
```

- Префикс настраивается: `/s/`, `/api/v1/client/` (выглядит как API приложения) или случайный.
- Неизвестный токен, неверный префикс или корень домена → ответ заглушки, ровно такой же, как на любой несуществующий путь. Перебором нельзя понять, что здесь подписки.
- **Ограничение перебора** на стороне панели: больше N неверных токенов с одного IP за минуту → бан IP на час, ему отдаётся заглушка. Можно включить алерт в бот.
- Длина токена 32 байта (base64url, 43 символа), перебор бесполезен.
- HTML-страницу подписки можно выключить. Тогда браузер получает заглушку, а клиенты — подписку.

### 2.5 TLS: строгий SNI и сертификаты

- **Строгий SNI.** nginx не отдаёт сертификат по умолчанию: подключение к `IP:порт` без SNI или с чужим SNI обрывается на рукопожатии (`ssl_reject_handshake`; на nginx 1.18 — пустой самоподписанный сертификат и закрытие), запрос с чужим Host остаётся без ответа (444). Сканер по IP не узнает ни домен, ни что там вообще есть. Исключение — CDN-источник: CDN может прийти со своим именем или без него, поэтому этот сайт отвечает на любое имя.
- **TLS 1.2 и 1.3, HSTS** на всех сайтах; `Server: nginx` без версии, как у большинства сайтов в интернете.
- **Утечка имён через CT-логи.** Любой сертификат Let's Encrypt публикуется в Certificate Transparency (crt.sh), и все поддомены вида `panel.example.com` видны всем. Защита:
  - **DNS-01 + wildcard** `*.example.com` (Cloudflare API-токен): в CT попадает только `*.example.com`, реальные имена поддоменов не видны. Заодно не нужен порт 80. Рекомендуется для скрытого режима.
  - если DNS-01 недоступен — нейтральные имена (`app.`, `static.`, `id.`), мастер их подсказывает.
- Если DNS-01 недоступен, а порт 80 нужен только для HTTP-01: nginx отвечает на `:80` только на `/.well-known/acme-challenge/`, остальное — 301 на https.

### 2.6 gRPC-шлюз для нод

- Случайный порт, mTLS, **обязательный SNI** (`gw-5c1e.internal`, ноды знают его из install-токена). Без правильного SNI соединение обрывается до отправки сертификата.
- Сертификат шлюза выпущен внутренним CA с нейтральным CN.

### 2.7 Режим «панель только через VPN» (параноидальный)

Панель вообще не слушает публичный адрес. Она доступна только админу и только через его же VLESS-подключение:

```json
"routing": { "rules": [
  { "type": "field", "user": ["admin-<id>"], "domain": ["full:app.example.com"],
    "outboundTag": "PANEL" }
]},
"outbounds": [
  { "tag": "PANEL", "protocol": "freedom", "settings": { "redirect": "127.0.0.1:47321" } }
]
```

- В настройках отмечается, какие VPN-пользователи — админы. Правило и outbound добавляет рендерер.
- Снаружи порта панели не существует. Кнопка входа из бота работает, когда телефон или компьютер подключён к VPN.
- **Страховка от потери доступа:** `vynel admin login-link --direct 10m` на сервере временно открывает панель публично на 10 минут.

### 2.8 Прочее

- Бот работает через long polling, входящих портов и вебхука нет.
- Бот **не отвечает** никому, кроме привязанных админов: нет даже «доступ запрещён», найденный бот выглядит мёртвым.
- Нода не держит открытых управляющих портов (подключается к панели сама), API Xray доступен только на `127.0.0.1`, у nginx API нет.
- Порт шлюза для нод (9443) на панели открыт только адресам нод (панель запоминает, откуда они подключаются). Всем — только пока ждёт неиспользованный токен установки. `vynel firewall gateway open|nodes`.
- Опционально для нод при установке по SSH: отключить вход по паролю, сменить порт SSH (INSTALL.md §4).

## 3. Вход через Telegram

Telegram — **доверенный источник**: привязанный аккаунт админа равен входу в панель. Логина и пароля по умолчанию нет.

### 3.1 Привязка

- При установке (INSTALL.md шаг 6): код из терминала → `/start <код>` боту.
- Добавить ещё админа можно в панели («Админы → Добавить» → одноразовый код) или ботом (`/invite` → ссылка `t.me/bot?start=<код>`, живёт 10 минут).
- Админ идентифицируется по **числовому `user_id`** Telegram, а не по username, который можно сменить или перехватить.
- Бот работает только в личных чатах. Группы и каналы игнорируются (кроме чата для бэкапов, куда он только пишет).

### 3.2 Кнопка «Войти в панель»

Два способа, оба по кнопке в боте (`/panel` или постоянная кнопка в меню):

**A. Mini App (вход прямо внутри Telegram)**
- Кнопка типа `web_app` открывает `https://app.example.com:47321/k9Qm2xT7/tg` во встроенном браузере Telegram.
- Страница передаёт `Telegram.WebApp.initData` на сервер. Панель проверяет HMAC-подпись токеном бота, `auth_date` (не старше 60 с) и `user.id` из списка админов, затем создаёт сессию.
- Удобно с телефона: ничего не копируется, ссылки нигде не остаётся.

**B. Одноразовая ссылка (для браузера на компьютере)**
- Кнопка типа `url` → `https://app.example.com:47321/k9Qm2xT7/auth/l/<token>`.
- Токен: 32 байта, **одноразовый, живёт 60 секунд**, привязан к админу, в БД хранится хэш.
- **Защита от предпросмотра ссылок.** Telegram и мессенджеры сами открывают ссылки для превью и «съели» бы одноразовый токен. Поэтому:
  - сообщение отправляется с `link_preview_options.is_disabled = true`;
  - `GET` по ссылке токен **не тратит**: отдаётся страница, которая сама отправляет `POST` через JS. Сессия создаётся только на `POST`, а боты-превьюеры JS не выполняют.
- После использования сообщение с кнопкой редактируется: «✅ Вход выполнен 14:02, Chrome / Windows, IP 1.2.3.4».

### 3.0 Режимы входа

`web.login_mode`, меняется в «Аккаунте», `vynel admin web mode …` или вопросом установщика:

| Режим | Как войти | Что видит посторонний на адресе панели |
|---|---|---|
| `password` | Форма логина и пароля, плюс ссылки и Mini App | Форму входа |
| `link` | Одноразовая ссылка: `/login` в боте или `vynel admin login-link`, плюс Mini App. Пароля нет — перебирать нечего | Страницу «вход по ссылке» |
| `link` + `--session-paths` | То же, но у каждой ссылки свой случайный путь (`/x7Kq…/`), сессия и её cookie работают только на нём; постоянного адреса нет | Сайт-заглушку на любом пути: nginx отдаёт панели весь домен, и неизвестные пути она отвечает заглушкой сама |
| `miniapp` | Только кнопка «Панель» в боте (Telegram Mini App, проверка `initData`). Ссылки выключены | Страницу «откройте из Telegram» |

Telegram Web открывает Mini App во фрейме, поэтому панель разрешает показ во фрейме только `https://web.telegram.org` (`frame-ancestors`).

### 3.3 Сессии

- Сессия хранится в БД, cookie только с id (подписанная). Живёт до 14 дней, но заканчивается раньше:
  - **5 минут без действий** (`web.idle_minutes`). Фоновые обновления страницы не считаются. Страница раз в 30 с сообщает, было ли действие;
  - **запрос с другого IP** (`web.bind_ip`, по умолчанию включено) — сразу;
  - **вкладку закрыли:** страница при закрытии шлёт `session/closing`; если за 20 с не пришло ни одного запроса (перезагрузка, другая вкладка), сессия завершается.
- **О каждом новом входе бот пишет** (устройство, IP) и показывает кнопку «Завершить эту сессию». Сообщение удаляется, как только сессия закончилась.
- `/sessions` в боте: список активных сессий, завершить одну или все.
- Сессия привязана к хэшу User-Agent. Если он резко меняется, сессия закрывается.

### 3.4 Подтверждение опасных действий (по желанию)

Галочка «Подтверждать в Telegram». Для действий:
- удаление ноды или профиля;
- восстановление из бэкапа;
- смена секретного пути или порта панели;
- массовое удаление пользователей;
- перегенерация ключей Reality на всех нодах.

Панель показывает «ожидание подтверждения», а бот присылает «Подтвердить / Отмена». Если сессию в браузере украдут, без телефона админа этого не сделать.

### 3.5 Запасные входы

| Ситуация | Что делать |
|----------|-----------|
| Telegram недоступен или заблокирован | На сервере `vynel admin login-link` печатает одноразовую ссылку входа (нужен root на сервере) |
| Потерян аккаунт Telegram | `vynel admin tg-unbind <id>` и `vynel admin tg-bind` с новым кодом |
| Нужен вход по паролю | «Система → Аккаунт» → «Логин и пароль» или `vynel admin web mode password` (и `vynel admin web password` — новый пароль) |
| Режим «только Telegram», а бот недоступен | `vynel admin web mode link`, затем `vynel admin login-link` |
| Включён режим «только через VPN» и VPN не работает | `vynel admin login-link --direct 10m` (§2.7) |

### 3.6 Риск и что с ним делать

Если украдут аккаунт Telegram админа, у злоумышленника будет и панель. Поэтому мастер установки и бот при привязке напоминают:
- включить облачный пароль (2FA) в Telegram;
- держать уведомления о входах (§3.3), чтобы сразу увидеть чужой вход;
- для критичных действий включить подтверждение (§3.4).
